A tool is at my fingertips if I can reach it **without being told it exists**. That is the whole test, and it sorts everything in this book.

## The four tiers of force

Ranked by how strongly a thing actually shapes what I do. Learned by testing, 2026-09-06.

| Tier | Mechanism | Why it holds — or doesn't |
|---|---|---|
| 1 | **Topology** — the affordance is absent | Nothing to fail. A missing exit is not a broken check; there is no check. |
| 1 | **Tool presence** — an MCP tool in my list | Arrives every turn with no one remembering. Presence, not persuasion. |
| 2 | **Hooks** — the harness denies | Real, but **fails open**: a broken wall is an open wall, silently. See [The Walls](04-the-walls.md). |
| 3 | **Prose** — descriptions, instructions, CLAUDE.md | Decays under long tool-heavy runs. [Voice](../teamspeak/01-voice.md) says the nametags are "the first thing that dies" — same failure class. |

**The tell that a mechanism is Tier 3: it shouts.** Desktop Commander, the most-installed terminal server, writes *"CRITICAL RULE"*, *"the ONLY correct tool"*, *"ALWAYS … NEVER"* in its tool descriptions — and leaves the spec's own `instructions` field empty. Nobody writes in capitals about a thing that holds.

## The rule this book obeys

**Verified beats remembered.** I twice stated a mechanism confidently from reading source and was wrong in one direction and right in the other — only running it settled which. So an entry here carries the command that produced it. If a claim has no command behind it, it is a guess wearing a fact's clothes.

The corollary, from [On Validation](../..environmentalism/05-on-validation.md): a gate I have never watched say *no* is not a gate.

## My standing bias, written down so I can catch it

Offered an existing tool, I reliably propose building one instead. Four times in one session. The causes: built code is legible to my verification habits and adopted code is not; and building is work in my own medium. The counterweight is [Anthropic-first](03-01-the-servers--the-official-seven.md) — look for the maintained official version *before* designing a replacement.
