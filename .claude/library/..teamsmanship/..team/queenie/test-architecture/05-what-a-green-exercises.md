# What a green exercises

- **author:** [Queenie](../queenie-and-the-specification/.cover.md)

---

[Book: [Test Architecture](.cover.md)]

A green number is read as a guarantee, but it is only ever a claim about a *specific body of code* under a *specific set of checks*. Its true scope is the intersection of two sets: the code the runner actually ran, and the code the checks actually covered. Inside that intersection the number means what it says. Outside it — code that ran but was never checked, or was checked but never ran — the number counts what it does not cover, and the green overstates. The question is never "how many green," it is "green over what, checked by what."

Two failures wear this one shape. The [suite that passed against a stale build](../../../../../../library/.public/.lib/solutions/05-the-suite-that-passed-against-a-stale-build.md) ran against a compiled artifact that was no longer the source — so the green checked *different code* than the one being read; the intersection with the current source had a hole in it. The second is quieter and is the one the [markdown sprint](../../../../../../library/.public/.lib/projection/11-markdown.md) named before it could bite: a runner that runs code no typechecker validated — so the green checks a *weaker specification* than the number implies, "runs without throwing on the tested paths" standing in for "typechecks and runs." Different clothes, one disease: the code the number counts is not the code the checks covered.

The markdown seam is worth stating exactly, because it is a live instance and not a hypothesis. In the `@dna-platform/lib` package, `npm run test` is `tsc --noEmit` then `vitest run`. The `tsc` uses the package `tsconfig.json`, whose `include` is `src` and `tests` only; the app compiles under its own `app/tsconfig.json`, which the test script never invokes. `vitest.config.ts` sets no `test.include`, so vitest's default glob discovers and runs every `.test.tsx` under the package — *including any placed under `app/`*. Put those together and the result is precise: a test living in the app **runs**, and is counted in the green, while it is **typechecked by neither project** — the package `tsc` excludes the app, and the app's own `tsc` is never run. The mini framework is ruled to live in the demo, under the app, so absent a decision its tests would ship exactly this green: their runtime paths exercised, their types unchecked. A wrong override signature, a property that isn't there, an unhandled null — none fail the gate unless they also happen to throw on a path a test drives.

Resolving it is one principle applied: make the checked set equal the run set. Co-locate the app's tests under `app/src`, where the app tsconfig's existing `src/**/*.tsx` glob already takes in a `.test.tsx` file, and add the app project to the gate — `tsc -p app/tsconfig.json --noEmit` beside the package `tsc`, before `vitest`. Then every test that contributes to the number is typechecked by exactly one project and run by the runner, and the intersection has no hole. The honest consequence must be stated in the same breath, not discovered at work: the app has never been typechecked in the gate, so turning it on will surface whatever type debt was always present and never caught. That surfacing is not a regression the change introduced — it is the truth about a rung that never ran, finally told. Measure the delta and either fix or baseline it; do not let a first red from newly-honest checking read as damage.

So the discipline generalizes past this one config: report a green with its scope attached. "N tests green" is half a sentence; the whole sentence is "N tests, over *this* code, checked by *these* gates, run by *this* runner." A number offered without its scope is the same overstatement as a green against a stale build — a claim whose subject was never pinned. A gate is only as strong as the smallest coverage anywhere in its pipeline, and the number a gate reports must never claim more than that floor. When someone asks what the green means, the answer is not the count; it is the intersection.
