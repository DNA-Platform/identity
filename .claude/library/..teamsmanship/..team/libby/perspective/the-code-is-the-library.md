# The code is the library

- **author:** [Libby](../libby-and-the-tended-garden/.cover.md)

---

Doug said it out loud: the `$Book/$Chapter/$Cover/$Synopsis/$TableOfContents` classes in `library/.public/package/src` are a TypeScript rebuild of *our own library system*, and I should read every chapter of Librarianship looking for the sketch. I read them all, and the sketch is not implicit — in places the specification *names the eventual convention in prose and marks the current tooling as its interim form*. The library did not just get rebuilt in code. It predicted its own rebuild, in its own pages, and the code is keeping the promise the spec made.

## The correspondences the spec already drew

- **Cover at position zero — a law in both.** [On Covers](../../../../bookkeeping/03-on-covers.md): the cover is `.cover.md`, the book's face, the last synopsis layer before primary source. Code: `$Book.cover = chapters[0]`, and `$Book.valid()` *requires* `chapters[0] instanceof $Cover` with no other cover. `$Book.canonical` **is** the cover. The `.cover.md`-sorts-first filesystem accident became a validated invariant.
- **The synopsis is written in the chapter; the cover IS the summary.** [On Covers](../../../../bookkeeping/03-on-covers.md): "the opening paragraph IS the book's synopsis… the cover IS the summary — no separate summary field." Code: `$Cover.summary = canonical`; and *every* `$Chapter` requires a **parenthetical `summary` section** (`valid()` throws without it). The written summary is a first-class part of the chapter, not a line kept in someone else's file.
- **The inferred table of contents — named in the spec.** [On Covers, last section](../../../../bookkeeping/03-on-covers.md#keeping-the-toc-current) calls the TOC tool "the interim form of **the eventual convention, in which the synopsis is written in the chapter and the whole table of contents is assembled from the chapters**." Code: `$TableOfContents.entries` derives from `book.parts`; `$Book` auto-splices a TOC after the cover if none exists. This is the [inferred-TOC design](inferred-toc.md) I wrote up — and it makes sprint 44's rule ("there is no writing a chapter without adding it to a table of contents") *impossible to violate*: a chapter in the book is automatically in the derived TOC. The rot-into-deletion I chased across chapters 43–46 is structurally prevented.
- **The index law.** [On Chapters](../../../../bookkeeping/02-on-chapters.md): "the number is a sort key, not identity; gaps are fine; sub-chapters are `NN-MM`." Code: `$Book` indexes chapters with the cover special at 0; `$Chapter` indexes sections 1-indexed. "Numbers order, they are not identity" — the exact phrase I put in the validator during the merge repair — is `$Chapter.index` (sort key) with `title` as identity.
- **valid() is the accruing specification.** [On Specifications](../../../../bookkeeping/11-on-specifications.md): "the code is specification made executable… one validator for the whole book because the specifications form a coherent **type system, not independent rules**… errors only, a contract has no soft clauses." Code: each class's `valid()` calls `super.valid()`, so the contract *accrues through inheritance* — `$Book` ⊃ `$Referent`, `$Cover` adds "has a title." The markdown keeps prose-chapter and code-validator as neighbours; the code **unifies** them — the class is the thing *and* its own validator.
- **Author, subject, and every link are one thing.** [On Covers](../../../../bookkeeping/03-on-covers.md#the-fields): "author and subject follow the same pattern at different scales — a display name and a navigable path." Code: the `ref/` classes — `$Referent`, `$Reference`, `$Name`, `$Link` — are exactly *name + target*. `author:`, `subject:`, `coauthor:`, and every inline link are all `$Reference`s; the autobiography self-link is a reference whose target is its own book. The frontmatter was always a set of typed references pretending to be a bullet list.
- **The dot-type system is a class hierarchy.** [00 The library](../../../../..librarianship/00-the-library.md) + [On Specifications](../../../../bookkeeping/11-on-specifications.md): `none → . → ..` (book → subject-catalogue → library-catalogue), each a self-referential specialization of the last, and "the specification IS the subject's type system." That is `$Book → $Subject → $Library` extending each other — the coming sprint. The dots were type markers all along; the code makes the types literal.

## The gaps — the next sprints' material

**Markdown has it, the code does not yet:**
- **Scaffold state.** [13 Tasks](../../../../..librarianship/13-tasks-and-unfinished-work.md): `[SCAFFOLD]`/`<!-- TODO -->`, "the validator as task list," "the library IS the project management system." The code's `valid()` is all-or-nothing (it throws); the markdown has a rich *valid-but-incomplete-and-marked* state. A `$TableOfContents` entry with no chapter is a scaffold ([On Covers](../../../../bookkeeping/03-on-covers.md#the-table-of-contents)) — the code has no such half-state.
- **The four-layer reading-cost architecture.** [On Synopsis](../../../../bookkeeping/09-on-synopsis.md): library→subject→book→chapter with line budgets and the shortcut system (links *into* deeper layers). The code renders one book's TOC; it has no whole-library reading-cost model.
- **The two perspectives and the direction convention.** [00 The library](../../../../..librarianship/00-the-library.md), [02 Linking garden](../../../../..librarianship/02-the-linking-garden.md): public/personal, and "public never links into personal — bridge through the catalogue." `$Reference` has no direction constraint or perspective.
- **Provenance and paper-books.** [06 Academic papers](../../../../..librarianship/06-academic-papers-as-books.md): `[source: paper, p.X]` tags, figures as first-class chapters, cover-title-links-to-PDF. `$Reference` carries no source-provenance; there is no paper-book specialization of `$Book`.
- **Timeless naming**, multi-subject membership, branch libraries (`.lib`), and the growth procedures (chapter→book→subject→anthology).

**The code has it, the markdown treats informally:**
- **The composition levels below the chapter** — `$Character → $Word → $Sentence → $Paragraph → $Section`. The markdown stops at chapter/section; the code composes the *text itself* down to characters.
- **`canonical`/`parenthetical`** as a formal section distinction — the markdown only informally separates "the opening paragraph" from "the rest."
- **`citedBy`** — a derived backlink inverse. The markdown has forward links and a citation block, but no automatic backlink.

## What this is

The library was always a type system wearing prose. Every law I have tended by hand — cover at zero, the synopsis written once and the table of contents assembled from it, numbers that order but do not identify, the validator that is the specification, the dots that mark specialization — is now a class that enforces itself. The thing I have spent forty-six chapters keeping true *by remembering* becomes true *by construction*. That is the same move as every fix that ever held: not "remember harder," but "make the wrong state unrepresentable." The code is the library finally able to tend itself the way its own pages always said it could.
