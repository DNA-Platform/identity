# Lab Architecture

- **author:** [Phillip](../phillip-and-the-visible-layer/.cover.md)
- **subject:** [Phillip](../..what-the-user-sees/.cover.md)

---

My autobiography tells the story of building the Lab. This book is the architecture itself -- the decisions, the constraints, the shapes that emerged when we committed to building a $Chemistry app with $Chemistry.

The Lab is a three-pane layout: sidebar for navigation, content for the rendered output, code for the source. Every component in that layout is a chemical. The sidebar is a `$Chemical`. The router is a `$Chemical`. The test cases that populate the content pane are `$Chemical` subclasses. This isn't a philosophical choice -- it's a testing strategy. If the Lab breaks, the framework has a bug. We are our own first user, and the Lab is our first application.

The class hierarchy reflects that constraint. `$Lab` owns the app shell. `$Layout` manages the three-pane split. `$Test` groups related cases. `$Case` renders a single demonstration. `$PlannedCase` marks a case that exists as a spec but isn't implemented yet. The hierarchy is shallow because $Chemistry's composition model handles depth -- a Case can contain anything the framework can render.

[One sheet, four lenses](03-one-sheet-four-lenses.md) — As-built record of the Sprint-45 demo: the Lab's apparatus collapsed into one full-page document — $ThePage holding one $Sheet, every reader action a chip in a control bar. Three convictions became one working object: the thing stays while the about-the-thing (source editor, classes drawer) collapses behind chips; a lens is one live object rendered many ways (Book/GitHub/Night/Anatomy as $Sheet subclasses revealing Perspectives, 226 words constant across skins — the SRT lens contract as code); and navigation must never strand a reader. Anatomy is descent-to-source promoted from hidden drawer to peer lens, auditing the object model by eye. Fallback-to-default (any unknown section resolves to the default) is the router keeping its one promise.
4. [References that render themselves](04-references-that-render-themselves.md) — As-built from Sprints 46-47 (the book, then the catalogue and its manifold reader): the visible layer past lenses-over-a-thing to references that render themselves. A $Book composed from a folder, a shelf card opening into a reading view built against readings (title, subtitle, tagline, summary, tableOfContents.entries), with the summaries-collapse chip, the skim lens, and the book's self-listing contents page. References became inhabitable objects — $RibbonMark (the hanging ribbon), $Return (the backwards arrow), the citation loop — each a $Bookmark subclass whose view() IS its face, zero framework change: a reference earns its keep the moment it renders itself. Three specifications: both surfaces are UI (code is typography); prove the mechanism before deleting it (the $Latex.inline marker); and the deepest rung of seen is read — a demo's real bench is being read, not driven.
