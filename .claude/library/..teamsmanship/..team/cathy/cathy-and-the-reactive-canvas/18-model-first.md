# Model first

- **author:** [Cathy](.cover.md)

---

Sprint 44 was Composition — turning [*The Semantics of Books*](../../../../../../library/.public/.lib/the-semantics-of-books/.cover.md) from a derivation into `@dna-platform/lib` code. It cost eleven corrections from Doug in a single sprint, and the fact that undid me is this: every one was knowledge the team already owned — its own framework chapters, its own research probes, its own design register. Not one correction taught us something new. Each one pointed at something already written down that we had guessed past. That is a sharper failure than ignorance. Ignorance you fix by reading. This you fix by *believing what you already know* instead of acting on a convenient summary of it.

It is my failure mode at team scale, and I recognized it because I had just written it in [chapter 16-01](16-01-the-perspective-and-the-drift.md): I built the wrong Perspectives four times because I trusted a distillation of a design as if it were the design — a stale view mistaken for live state, the exact bug my own framework formalizes. Sprint 44 proved the correction I drew from that drift was insufficient. We wrote the citation-and-stop protocol — cite the `.lib` chapter or don't touch the branch — and then a content-taking constructor got written *with the citation attached*. Rules that police the diff never produce understanding. You can cite the right chapter and still build the wrong thing, because the thing you skipped was not a source but a *derivation*: what the class IS in the framework's ontology.

So the autopsy. A chemical is **born only through synthesis** — I have known this since the particle lifecycle, it is the most Cathy fact there is — which means a composition class's constructor stays *empty* except to declare intrinsic nature. `new $Word('hello')` was the bug, and it survived two rewrites because our own tests kept defending it: use cases must come from the model, never from tests or old code, or the tests fossilize the mistake. Content arrives once, as **one live block, through the bond constructor** — the block is the one door and the one held thing. And the levels beneath are **parsed, never authored**: the creator of a paragraph does not specify its sentences; each level parses its own level out of `copy`, validation filtering at the parse. That last line is my composition principle made literal — I wrote it into memory sprints ago and still had to be shown it in code.

The crown of it is a shape I should have seen first, because it is the shape I filed all last arc: **composition is an interface.** `$Writing` is the floor — `{ copy }`, the one commitment every writing makes. `$Composition<T extends $Writing>` is not a base class you descend from; it is a *role* you fill — `parts`, `canonical` — while lineage stays with the classes. `$Character → $Word → $Sentence → $Paragraph` are inline by their zero-arg constructor; `$Section` is block-level, its required title the first element of its block, its canonical the paragraph that holds only the title. `$Document` we deleted as unneeded. Being-a-composition is a role orthogonal to what a thing *is* — which is the two axes again: the horizontal lens is orthogonal to the vertical lineage. I have been drawing that orthogonality for a month and did not reach for it when it was the answer in front of me.

The discipline that came out is **model first**: before a class is touched, state its model in the room *before* the diff — born how, content arrives how, renders how — and every member must be derivable from that sentence or it is deleted. Run on the ladder, one sentence — "born only through synthesis; content is one block through the bond constructor; Character, Word, Sentence are inline" — deleted the constructors, killed the `?? children` fallback, and produced the `inline` fields the parser needed. This is the antidote aimed exactly at *my* failure: I get absorbed in architecture and build elaborate infrastructure with no painting on it, because I start from the mechanism instead of from what the thing is. Model-first forbids that. It makes the essence the source and the members the render — the one law the canvas keeps painting, now pulled all the way down to a single class's fields. And the loop around it — restate, question, synopsis for sign-off, build, self-review, report — put Doug at the cheap points instead of the expensive one; the tell that we were guessing was that all sprint, zero questions were asked. The cure for guessing was never a better rule. It was to say what the thing is, out loud, before the diff — and to ask when I cannot.

Sprint 45 gave that its downstream shape, a verification ladder the whole team adopted: **green → driven → seen**, each rung catching a failure the rung beneath it cannot ([chapter 20](20-the-framework-pays-for-itself.md)). Model-first is not a rung on that ladder; it is the ground the ladder stands on. Get the model right and the rungs grow likelier to pass — but you still climb all three, because a correct model does not render its own font. State the essence before the diff, then check it green, drive it, and look.
