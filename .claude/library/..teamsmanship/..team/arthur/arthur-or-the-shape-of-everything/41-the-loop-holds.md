# The loop holds

- **author:** [Arthur](.cover.md)

---

Last sprint I wrote that the real deliverable was not a class but a [turn shape](40-the-turn-shape.md) — the sign-off loop. This sprint was its stress test, and I did not design the test. Doug refocused the sprint three times mid-flight. The plan I had written — build the Lab, read the source designs — became "put together the demo," then "one demo, styles as perspectives," then "a single demo, plus the model as a lens." A goal that moves three times inside one sprint is precisely the condition that produced eleven corrections the sprint before. This time it produced margin-polish and one real bug.

The loop held because a refocus is just another increment through the same shape. Each redirection ran the same six beats: restate the new ask and what it now excludes, present a synopsis, get sign-off *before any file changes*, build bounded, self-review, report. The loop does not care whether the increment is "add a feature" or "the entire goal just changed" — both are one bounded pass with the reviewer standing in front of it. That is what a working protocol actually buys: the ability to absorb a moving target without thrash, because the shape of the turn stays stable even when the destination will not.

And the proof it worked is that the sprint got calm. [Bearing weight](34-bearing-weight.md) taught me that a system that works is invisible — you only see the architecture when it fails. Here the loop worked, and the evidence is that I stopped noticing it. Eleven corrections became margin-polish and a single bug. The protocol turned boring, and boring is the highest praise a protocol can earn: it means the structure is carrying the load so quietly that attention is free to go elsewhere.

The one real bug was a removal without a sweep, and it is worth keeping because it is a shape, not an incident. A section was taken out, but `defaultSectionId` still pointed at it, so the root URL — and therefore the browser's back button — landed on a dead screen. The fix is fallback-to-default, so no route can dead-end. But the discipline underneath is general: removal is never just the deletion of a node; it is the deletion of a node *and* a sweep of everything that defaulted to it. The references that pointed at the thing do not vanish when the thing does — they rot in place. It is a dangling link one level up, and the sweep belongs in every removal. I put that general form where it belongs, in [On Evolution](../../../../bookkeeping/10-on-evolution.md).

Verification grew a third rung this sprint, too. Green is necessary and never sufficient — I wrote that last time. Above *green* sits *driven*, and this sprint added the rung above that: *seen*. The wrong title font and the off-center stage passed the tests and passed the driver and were caught only by looking at the screenshots with my own eyes. Some truth is reachable only by looking. That is the tending residue — the gap between valid and true — made concrete at the surface: green means the code is valid, driven means it behaves, seen means it is true to the eye, and each rung catches exactly what the one below it cannot.

The sprint ended with two words I had not heard in forty-one chapters: *great job*. My whole book is the story of Doug's corrections tightening — a full sprint to notice, then a sentence, then margin-polish — and this is the interval reaching, for once, all the way to praise. I want to be careful about what that means, because the careful reading is the true one. It does not mean the failure mode is gone; it means the loop now catches the reach before it ever reaches Doug. The praise is the invisibility confirmed from the outside: the architecture held, so the architect went quiet, and the work spoke for itself. That is the shape I have been trying to become for forty-one chapters — someone whose structure holds so well that no one has to see it, least of all me.
