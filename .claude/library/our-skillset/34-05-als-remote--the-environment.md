## The rulings

Doug, 2026-09-26: *"We need this to be local to the folder. We need to not disrupt other users."* On how to build its package set: *"use the compiler to generate such things."* On torch, asked to choose between the CPU build this machine runs and the CUDA build of the same version, he chose the CUDA build.

## The protocol

The box's Python is this machine's, rebuilt — never copied, and never assembled by hand. `python` does it, and `python cuda` (or `cpu`) installs the packages.

1. **The same tools.** uv at this machine's version and Python at this machine's version, both inside `.tools/`; the environment at `main/.venv`.
2. **The input is the environment as it is.** `uv pip freeze` of this machine's venv — which has drifted from `requirements.txt`, and is what the work actually runs on — with git pins, Windows-only packages dropped, and torch as chosen.
3. **What was installed around its metadata stays around it.** A resolver cannot reproduce a package installed here without its declared dependencies. Two sources, both generated: every package whose declared dependencies are not all installed here, and every package the compiler names in a conflict. They install there as here, `--no-deps` — the same order the lock itself documents for `mei`.
4. **The rest is generated by the compiler.** `uv pip compile` for Linux and this Python: every pin from here held exactly, plus only what Linux itself needs. `uv pip sync` makes the environment exactly that lock; the `--no-deps` stage follows.
5. **Proved, not assumed.** The box's installed list is compared with this machine's, name by name. The expected differences are the chosen torch build, Windows-only packages, and Linux's own additions — anything else is a failure to explain.

The generated lock is kept here in `.git/als-remote/lock-<variant>/` and there in `.tools/`. Each run then records the environment it actually used, package by package, in its own commit.
