No, that logic won't preserve private fields with underscores reliably. Let's break down what happens:
typescript
Object.assign(
    Object.create(Object.getPrototypeOf(this)), 
    this
);
Object.create(Object.getPrototypeOf(this)) - Creates a new object with the prototype chain intact
Object.assign(target, this) - Copies enumerable own properties from this to the new object
The issue: Object.assign only copies enumerable properties. If you have:
typescript
class $Chemical {
    private _id: number = 5;  // TypeScript private - still enumerable
    // or
    _id: number = 5;  // Convention-based private - enumerable
}
TypeScript's private keyword doesn't affect runtime enumerability - it's just compile-time checking. So _id WILL be copied.
However, if you're using actual private fields:
typescript
class $Chemical {
    #id: number = 5;  // Real private field - NOT enumerable
}
Then #id will NOT be copied because true private fields aren't enumerable and aren't accessible via Object.assign.
Looking at your current code in chemistry2, you're using TypeScript private with underscores:

These WILL be copied by Object.assign because they're just regular properties at runtime.

class Event<Source = any, Target = any> {
    subscribers: ((source: Source, target: Target) => Target | void)[];
