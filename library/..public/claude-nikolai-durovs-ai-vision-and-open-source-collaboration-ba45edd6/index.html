Ah, this is crucial. TON doesn't use "type theory" in the foundational sense you're thinking of - not Russell & Whitehead's PM, not Church's λ-calculus types, not Martin-Löf or System F.
TL-B (Type Language - Binary) is a domain-specific language for describing data serialization and deserialization in TON. It's a type system for binary encoding, not a foundation for computation or logic.
Here's what TL-B actually does:
Constructors specify how to serialize values, with tags (bit patterns) that enable unambiguous deserialization. Variables prefixed with tilde (~) indicate whether they're computed during serialization or deserialization.
For example:
text
bool_true$1 = Bool;
bool_false$0 = Bool;
The $1 and $0 are binary tags. This is about pattern matching on binary data, not logical foundations.
