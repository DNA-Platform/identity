How do I run OpenScholar LLM
Claude
21:07 UTC, 5 February 2026
Searched the web for “OpenScholar LLM how to run”
There are three main ways to run OpenScholar:
1. Try the Public Demo
The easiest option — just visit the hosted demo at open-scholar.allen.ai. No setup required.
2. Run Locally from GitHub
Clone the repo from github.com/AkariAsai/OpenScholar and set up the environment:
bash
conda create -n os_env python=3.10.0
conda activate os_env
pip install -r requirements.txt
python -m spacy download en_core_web_sm
You'll also need a Semantic Scholar API key, and optionally a you.com web API key if you want web search.
Then run inference with the 8B model:
bash
python run.py \
  --input_file YOUR_INPUT_FILE \
  --model_name OpenScholar/Llama-3.1_OpenScholar-8B \
  --use_contexts --output_file OUTPUT_FILE_NAME \
  --top_n 10 --llama3 --use_contexts \
  --ranking_ce --reranker OpenScholar/OpenScholar_Reranker \
  --posthoc --feedack --ss_retriever \
  --use_abstract --norm_cite --zero_shot --max_per_paper 3
The models are available on Hugging Face under the OpenScholar organization.
3. Use It with a Proprietary LLM Backend
You can swap in a proprietary model like GPT-4o as the generator while keeping the OpenScholar retrieval pipeline:
bash
python run.py \
  --input_file YOUR_INPUT_FILE \
  --model_name "gpt-4o" \
  --api "openai" \
  --api_key_fp PATH_TO_YOUR_OPEN_AI_KEY \
  --use_contexts \
  --output_file OUTPUT_FILE_PATH \
  --top_n 10 --llama3 --zero_shot
Key Configuration Options
0 — number of passages fed to the LM (default 10)
0 — enables the self-feedback loop for iterative improvement
0 + 1 — uses a cross-encoder reranker on retrieved passages
0 — queries Semantic Scholar API during feedback generation
0 — caps passages from a single paper
By default, OpenScholar uses offline retrieval results followed by additional retrieval from Semantic Scholar and web search APIs. The retrieval results are also available pre-computed on Google Drive.
It's a relatively lightweight system — running it costs a fraction of what commercial deep-research tools charge, and the 8B model can run on consumer-grade hardware with a decent GPU.

Does it work better on its own or with backend?
Claude
21:10 UTC, 5 February 2026
Based on the benchmarks from the paper, the combination approach wins. OpenScholar-GPT-4o provides a 12.7-point improvement over GPT-4o alone in the Scholar-CS rubric score, and in human evaluations, experts preferred OpenScholar-GPT-4o responses over expert-written ones 70% of the time, compared to 51% for OpenScholar-8B alone and just 32% for plain GPT-4o.
So the ranking is roughly:
OpenScholar + GPT-4o — best overall quality
OpenScholar-8B standalone — surprisingly strong for its size, outperforming GPT-4o by itself on correctness and citation accuracy despite being a much smaller model
Plain GPT-4o — decent answers but hallucinates citations 78–90% of the time
The key insight is that OpenScholar's datastore, retriever, and self-feedback inference loop improve off-the-shelf LMs — OpenScholar-GPT-4o improves GPT-4o's correctness by 12%. So the retrieval pipeline is doing most of the heavy lifting regardless of which LLM generates the final answer.
If you're optimizing for cost and self-hosting, the 8B model is remarkably competitive. If you want peak quality and don't mind API costs, pair the pipeline with a strong proprietary backend.
