This is well-documented in the actual code — and there's one framing correction worth making up front, then the concrete values.
The Gabor caveat. The published mouse-V1 MEIs from Walker 2019 are deliberately not Gabor-like — that was the paper's headline result. The MEIs deviated substantially from the textbook Gabor notion, showing sharp corners, checkerboard patterns, pointillist textures and curved strokes, often with more high-frequency detail than the linear RF. The smooth Gabor look belongs to the LN/linear-RF control they fit alongside each MEI. So "smooth, not high-frequency noise" is the achievable goal; "Gabor-like" is the LN-RF estimate, not the MEI. The recipe below is what gives you clean, low-noise MEIs; whether they come out Gabor-like depends on your model, not the synthesis settings.
There are two distinct recipes in this codebase, and they produce different looks.
Recipe A — the mei-package datajoint-free demo (minimal, clean-ish)
From demo/quickstart.ipynb (sinzlab/mei), the constrained version (cells 10, 11, 18):
python
# synthesis
seed            = 8
lr              = 1                      # torch.optim.SGD
num_iterations  = 1000
initial         = "mei.initial.RandomNormal"   # torch.randn -> mean 0, std 1, UNSCALED
optimizer       = "torch.optim.SGD"            # kwargs: lr=1
stopper         = "mei.stoppers.NumIterations" # num_iterations=1000

# the only constraint (postprocessing, applied to the IMAGE each step)
postprocessing  = "mei.postprocessing.PNormConstraintAndClip"
p               = 2
norm_value      = 10
max_pixel_value =  2.2606
min_pixel_value = -1.75047
No Gaussian blur, no TV, no LpNorm regularizer. RandomNormal is bare torch.randn — mean 0, std 1, no scaling (mei/initial.py). The pixel-clip bounds are the normalized data extremes (i.e. (0-img_mean)/img_std and (255-img_mean)/img_std). This gives reasonably clean MEIs because the norm budget + pixel clip + the model's own smoothness suppress most noise — but it's noisier than the published figures.
Display (cell 20): plt.imshow(mei[0,0], cmap='gray', vmin=min_pixel_value, vmax=max_pixel_value) — i.e. grayscale, fixed symmetric-ish range = the clip bounds, not per-MEI min/max. That fixed range is what makes a panel of MEIs comparable.
Recipe B — the canonical Walker/nnvision recipe (the published look)
This is the one that produces the smooth publication figures. It lives in `nnvision/nnvision/mei/regularizers.py`, built on the legacy featurevis ops. Verbatim values:
python
# PRECONDITIONING (applied to the gradient each iteration)
walker_gradient = Compose([
    FourierSmoothing(0.04),          # freq-domain smoothing, ~ fft_smooth(precond=0.1)
    DivideByMeanOfAbsolute(),        # normalize gradient magnitude
    MultiplyBy(1/850, decay_factor=(1/850 - 1/20400)/(1-1000)),
    # effective step scale anneals 1/850 -> 1/20400 over 1000 iters
])

# POST-UPDATE (applied to the IMAGE each iteration)
bias, scale = 111.28329467773438, 60.922306060791016   # = img_mean, img_std
walker_postup = Compose([
    ClipRange(-bias/scale, (255 - bias)/scale),         # clip to [-1.827, 2.36]
    GaussianBlur(1.5, decay_factor=(1.5 - 0.01)/(1-1000)),
    # sigma anneals 1.5 -> 0.01 over 1000 iters
])
Driven by the legacy ascent loop (`nnvision/legacy/featurevis/core.py`, line 26): x_{t+1} = post_update(x_t + step_size * gradient_f(x_t.grad)), with default step_size=0.1, SGD optimizer, 1000 iterations, torch.randn initial guess.
The key mechanism for smoothness, and the thing the demo lacks: the annealed Gaussian blur of the image, sigma 1.5 → 0.01. Starting heavy forces low-frequency structure to form first; decaying to ~0 lets fine detail in only late, so noise never gets amplified. The gradient is also Fourier-smoothed and magnitude-normalized before the step. The GaussianBlur annealing is implemented via decay_factor in mei/legacy/ops.py (sigma recomputed as sigma + decay_factor*(iteration-1), truncate=4, reflect padding).
Notably, TotalVariation and LpNorm regularizers are not used in the V1 MEI recipe. They exist in mei/legacy/ops.py (TV default weight=1, anisotropic; LpNorm default p=6) but the smoothness comes from gradient Fourier-smoothing + annealed image blur + the norm/clip budget, not additive penalties. ChangeNorm/ChangeNormAndClip are the norm-budget enforcers when used.
Paper methods confirm the post-hoc step the code doesn't show: they started from a random image, ran regularized gradient ascent to convergence, and afterward matched average luminance and contrast between the MEI and the RF for fair comparison. So final display contrast is normalized post-hoc, not read raw off the optimizer.
Concrete answers to your specific questions
(1) Synthesis
Initial: RandomNormal = torch.randn, mean 0, std 1, unscaled (any contrast is set by the norm budget, not the init).
Optimizer / lr: SGD. Demo lr=1; legacy Walker step_size=0.1 but the effective step is set by the MultiplyBy term (1/850 → 1/20400), so lr is partly cosmetic when you normalize the gradient.
Iterations: 1000, fixed (NumIterations), no early stopping in the published recipe.
Preconditioning blur: in Walker it's Fourier smoothing of the gradient (freq_exp 0.04) plus gradient magnitude normalization — not a Gaussian blur of the gradient. The Gaussian blur is on the image as a post-update, sigma annealed 1.5 → 0.01 over 1000 iters (truncate=4, reflect pad).
Norm budget: enforced as a constraint, not an Lp penalty. Demo: PNormConstraintAndClip, p=2, norm_value=10. Walker: ClipRange + ChangeNorm-style budget.
Regularizers actually used: none additive. No TV, no LpNorm penalty, no explicit frequency penalty in the loss — smoothness is all preconditioning + post-update + clip.
(2) Post-processing / display
Colormap: grayscale (cmap='gray').
Contrast normalization: fixed range = the pixel-clip bounds (vmin=min_pixel_value, vmax=max_pixel_value), not per-MEI min/max — that keeps a panel comparable. Plus the paper's post-hoc luminance/contrast matching against the RF.
Gamma: none.
Masking: a receptive-field mask is used for analysis (the stability correlations are "restricted to pixels inside the MEI mask" per the paper, and mask ops appear in legacy/ops.py), but the displayed MEI itself is typically shown unmasked or with the RF mask applied for the RF-vs-MEI comparison.
Upsampling: none in the optimizer; figures are shown at model input resolution (nearest/bilinear only if enlarging for print).
Paste-ready for your CPU Sensorium-baseline twin
Sensorium static input is single-channel grayscale, so this maps directly. The sensorium repo itself ships no MEI configs — it's a prediction benchmark; MEI generation is the mei package, with production recipes in nnvision. Use the mei package and put the Walker post-update into postprocessing (the package separates gradient precondition from image postprocessing):
python
# compute these from YOUR normalized dataset (neuralpredictors transform)
img_mean, img_std = 111.28, 60.92          # <-- replace with your dataset's values
lo, hi = -img_mean/img_std, (255-img_mean)/img_std

from mei.legacy.utils import Compose
# postprocessing = annealed image blur THEN clip (order matters: blur, then clip)
walker_postup = Compose([
    "mei.legacy.ops.GaussianBlur",   # see note below on instantiation
])

method_config = dict(
    initial   = dict(path="mei.initial.RandomNormal"),
    optimizer = dict(path="torch.optim.SGD", kwargs=dict(lr=1.0)),
    stopper   = dict(path="mei.stoppers.NumIterations", kwargs=dict(num_iterations=1000)),
    precondition = dict(path="mei.legacy.ops.GaussianBlur", kwargs=dict(sigma=1.0)),  # smooth the gradient
    postprocessing = dict(path="mei.postprocessing.PNormConstraintAndClip",
                          kwargs=dict(p=2, norm_value=10,
                                      min_pixel_value=lo, max_pixel_value=hi)),
    objectives = [dict(path="mei.objectives.EvaluationObjective", kwargs=dict(interval=10))],
    device = "cpu",
)
That's the pragmatic CPU version. To exactly reproduce the published smoothness, swap postprocessing for a Compose([GaussianBlur(1.5, decay_factor=(1.5-0.01)/(1-1000)), ChangeNormAndClip(norm=<budget>, x_min=lo, x_max=hi)]) — the Compose/GaussianBlur(decay_factor=...) classes are in mei/legacy/ops.py, and ChangeNormAndClip in nnvision/mei/ops.py. The mei-package gradient_ascent imports a single callable per slot, so you wrap the Compose as your own importable function.
Display every MEI in the panel with the same fixed vmin=lo, vmax=hi, cmap='gray', no per-image rescaling.
Two CPU-specific cautions: 1000 iterations × annealed blur is cheap on CPU at Sensorium resolution, so no shortcut needed; and set norm_value empirically so that the ClipRange/clip almost never actually clips (the demo notes the norm is "established empirically such that ideally value clipping is not necessary") — if you see flat saturated regions, your norm budget is too high for your img_std.
