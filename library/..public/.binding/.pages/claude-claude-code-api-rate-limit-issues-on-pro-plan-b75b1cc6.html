Here's what's going on. There are two separate limit systems that could be hitting you:
5-hour rolling window — this has always existed. It resets 5 hours after your first prompt in a session, not on a fixed clock. The window begins with your first prompt and the clock resets only when you send the next message after 5 hours lapse. So if you hit it last night and it's still happening today, you may be triggering a fresh window before the previous one fully resets.
Weekly limit (newer, since Aug 28 2025) — Anthropic introduced weekly rate limits for Pro and Max subscribers in late August 2025, targeting heavy users. The existing 5-hour limits remained in place, with the weekly caps added on top. Pro and Max plan usage is shared across Claude.ai and Claude Code — all activity in both tools counts against the same limits.
For the Pro plan specifically: Pro users can expect roughly 40–80 hours of Sonnet 4 through Claude Code within their weekly limits — but that's token-based, not actual wall-clock hours, so heavy agentic sessions with large file contexts burn through it much faster.
Your options per the official docs:
You can wait until your usage period resets, enable extra usage (pay-as-you-go API credits at standard rates) to continue within the Pro plan, or upgrade to the Max 5x plan if you consistently hit limits.
The most practical immediate move is to run /status in the Claude Code terminal — it'll show you exactly what's left and when the reset hits. If you're doing research-heavy agentic sessions (which burn tokens fast), the Pro plan is genuinely tight for that workload.

How do I know the API will be associated with my plan and not a separate key?
Claude
13:44 UTC, 8 March 2026
Good instinct to check this. The key is that Claude Code authenticates via your claude.ai login, not an API key. When you add credits to the Anthropic Console, as long as you sign into console.anthropic.com with the same email address as your claude.ai account, the credits are on the same account and Claude Code will draw from them automatically when your plan allocation runs out.
The one gotcha to watch for, from the docs: if you have an ANTHROPIC_API_KEY environment variable set anywhere in your system (in your shell profile, .env file, etc.), Claude Code will use that key instead of your logged-in account. You can check by running:
bash
echo $ANTHROPIC_API_KEY
If it returns nothing, you're fine — Claude Code is using your account login. If it returns a key string, that's a separate API key and you'd want to unset it to make sure you're on your subscription.
You can also run /status in Claude Code once your limits reset to confirm which account and authentication method it's using.
