Let me break this down into related but distinct topics, since there's an interesting connection between them.
Chomsky's Linguistics:
Noam Chomsky revolutionized linguistics with his theory of Universal Grammar, suggesting that humans have an innate capacity for language acquisition. His most significant contributions to linguistics include:
The concept of generative grammar, which describes how finite rules can generate infinite grammatical sentences
The Chomsky Hierarchy of formal languages, which classifies grammars by their generative power
The distinction between deep structure and surface structure in language
Programming Languages and Chomsky:
Chomsky's work directly influenced computer science and programming language design:
The Chomsky Hierarchy is fundamental to compiler design and formal language theory
Context-free grammars (Type-2 in the Chomsky Hierarchy) are used to define programming language syntax
BNF (Backus-Naur Form) notation, used to describe programming language syntax, was influenced by Chomskyan ideas
GNOME:
GNOME (GNU Network Object Model Environment) is a desktop environment for Unix-like operating systems that:
Emphasizes usability and accessibility
Is built using GTK (originally GIMP Toolkit)
Uses a component-based architecture
Is part of the GNU Project
Follows a human interface guidelines document for consistent design
The interesting connection is that both programming languages and human languages can be described using formal grammars from Chomsky's work. For example, a programming language like Python uses context-free grammar rules similar to how Chomsky described natural language syntax.

No, Chomsky did not personally coin the term "recursively enumerable." This term comes from earlier work in computability theory and mathematical logic.
The term "recursively enumerable" (also called "computably enumerable") was developed in the 1930s and 1940s, primarily through the work of mathematicians and logicians like:
Emil Post
Alan Turing
Stephen Kleene
Alonzo Church
When Chomsky developed his hierarchy in the 1950s, he was working with concepts that were already established in mathematical logic. He organized and classified formal languages into his hierarchy, but used the existing terminology from computability theory.
The connection between Type-0 languages and recursively enumerable sets was made because both are recognized by Turing machines, but the term "recursively enumerable" predates Chomsky's work on formal language theory.
This is a good example of how Chomsky incorporated existing mathematical concepts from computability theory into his linguistic framework, rather than creating entirely new terminology. His innovation was more in the systematic classification and its application to linguistics rather than in naming the categories themselves.

So what did he name them and how did he decide to characterize each one?
Claude
04:09 UTC, 1 November 2024
Chomsky originally characterized these grammars in his 1956 paper "Three Models for the Description of Language" and expanded in his 1959 paper "On Certain Formal Properties of Grammars." He actually numbered them in the opposite order from how we commonly refer to them today.
Originally they were:
Type 0: Unrestricted grammars (not originally called recursively enumerable)
Type 1: Context-sensitive grammars
Type 2: Context-free grammars
Type 3: Regular/Finite state grammars
He characterized them based on the form of their production rules:
Unrestricted (Type 0):
No restrictions on production rules
Form: α → β where α and β are any strings of terminals and non-terminals
Context-sensitive (Type 1):
Production rules: αAβ → αγβ
Key insight: replacements depend on surrounding context
The produced string can't be shorter than the original
Context-free (Type 2):
Production rules: A → γ
Where A is a single non-terminal
The replacement can happen regardless of context
Regular/Finite state (Type 3):
Production rules: A → aB or A → a
Most restricted form
Linear structure with no nesting
His characterization was based on studying natural language patterns and formalizing what types of rules would be needed to generate different linguistic structures. The mathematical precision of these definitions made them immediately useful in computer science.
The numbering from 0-3 reflects increasing restrictions on the form of rules, with Type 0 being the most general and Type 3 the most restricted.
Interestingly, while we now associate each type with a corresponding automaton (Turing machine, linear bounded automaton, pushdown automaton, finite automaton), these connections were developed gradually through the work of various researchers in the following years, not all by Chomsky himself.

So if type zero is the most unrestricted is that the touring machine one?
Claude
04:10 UTC, 1 November 2024
Yes, exactly! Type 0 (unrestricted) grammars correspond to Turing machines. Here's why:
Equivalence:
A language is Type 0 ⟺ It can be recognized by a Turing machine
This means Type 0 languages = recursively enumerable languages
Power:
Type 0 grammars are the most powerful
They can generate any language that can be computationally enumerated
No restrictions on production rules (α → β)
Can model any computable process
Hierarchy relationship:
text
Type 3 (Regular) ⊂ Type 2 (Context-free) ⊂ Type 1 (Context-sensitive) ⊂ Type 0 (Turing-complete)
Key insight:
Each type corresponds to a simpler machine than a Turing machine:
Type 3 → Finite State Machine (most restricted)
Type 2 → Pushdown Automaton
Type 1 → Linear Bounded Automaton
Type 0 → Turing Machine (most powerful)
This is why Type 0 is particularly important in computability theory - it represents the theoretical limit of what can be computed. Any problem that can be solved by a computer can be expressed as a Type 0 grammar, though not all Type 0 problems can be solved (due to the halting problem).

No, the term "regular" came later. Chomsky originally called Type 3 grammars "finite state" grammars, reflecting their connection to finite state machines/automata.
The term "regular" became common later through the work of other computer scientists and mathematicians, particularly as the concept of regular expressions developed. The evolution went something like this:
Chomsky's original terminology (1956):
Type 3: Finite state grammar
Type 2: Context-free
Type 1: Context-sensitive
Type 0: Unrestricted
Modern equivalent terms:
Type 3: Regular/Finite state
Type 2: Context-free
Type 1: Context-sensitive
Type 0: Unrestricted/Recursively enumerable
The term "regular" became popular because:
It better described the mathematical properties of these languages
It aligned with related concepts like "regular expressions" and "regular sets"
The term was used in automata theory and formal language theory
So while we commonly say "regular grammar" today, Chomsky himself used "finite state grammar" in his original work, emphasizing the connection to finite state machines.

No, Chomsky wasn't directly trying to add to Turing's theory - he was actually approaching language from a different angle. However, there's an interesting connection in their work:
Turing's Focus (1930s):
Computation and mechanical procedures
What machines can/cannot compute
Universal computation
Focused on mathematical logic and computability
Chomsky's Focus (1950s):
How humans acquire and process language
Innate linguistic capabilities
Universal features across all human languages
Focused on cognitive and linguistic structures
The Connection:
Both were interested in "universal" properties
Turing: Universal computation
Chomsky: Universal grammar
Both used formal systems
Both influenced computer science
Key Difference:
Turing asked: "What can be computed?"
Chomsky asked: "How do humans naturally acquire language?"
While Chomsky used mathematical tools similar to those in computability theory, his Universal Grammar theory was more about:
How children can learn any language so quickly
Why all human languages share certain properties
What mental structures must exist to make this possible
He wasn't trying to extend Turing's work, though his formal language hierarchy ended up being very relevant to computer science and complemented Turing's ideas about computation.
