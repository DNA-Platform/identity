What formal models from category theory apply to self-modifying software systems? I am interested in how endofunctors and fixed-point combinators relate to programs that rewrite their own source code or specifications.

This sits at a nice intersection, and the honest version of the answer requires separating two fixed-point phenomena that people routinely conflate, because they live at different levels and answer different parts of your question.
Two levels of fixed point
The term-level fixed point is the Y/Z combinator: Y f = f (Y f), giving fix : (A → A) → A. Categorically this is the Kleene/Knaster–Tarski least fixed point in a category of domains (CPOs with least element), where fix g = ⊔ₙ gⁿ(⊥). This is about fixed points of functions between values.
The type/object-level fixed point is the one that actually models self-reference in the structure of programs. Given an endofunctor F : C → C, an initial F-algebra μF and a terminal F-coalgebra νF satisfy Lambek's lemma: their structure maps are isomorphisms, so μF ≅ F(μF) and νF ≅ F(νF). That isomorphism is the categorical statement "this object is a fixed point of F." A datatype of program syntax (ASTs for some grammar) is exactly μF for the polynomial/signature functor F encoding the grammar. So the moment you talk about "a program manipulating its own source," you are talking about an object that satisfies a fixed-point equation under an endofunctor.
The reason this matters for self-modification specifically is that the dangerous equation is D ≅ [D → D] — "the space of programs is its own function space." In Set this is impossible by cardinality. Two escapes, and which one you take dictates the whole flavor of your model:
Untyped route — reflexive objects. Give up well-pointedness. A reflexive object in a CCC is a U with a retraction [U → U] ◁ U (maps U → [U → U] for application and [U → U] → U for abstraction). Scott's D∞, built as the bilimit of the chain X ↦ [X → X], makes this an actual isomorphism — and notice that D∞ is itself a fixed point of an endofunctor on a category of domains. This is the precise sense in which untyped self-application is "the space of programs being a fixed point of the function-space endofunctor." Self-modification is unproblematic here because everything is already U.
Typed route — a modality that separates code from meaning. Keep types, but stratify. Introduce a comonadic modality □A = "code/quotation of a program of type A" (Davies–Pfenning's modal staging calculus; □ is an endofunctor with counit eval : □A → A and comultiplication □A → □□A, the ability to quote code-of-code). This breaks the size paradox because □A is a genuinely different object from A, while still giving you reflection. Self-modifying programs then live as manipulations of □-values, and the self-referential knot is tied with a fixed point at the type level — □ of a recursively defined code type. MetaML / staged computation is this made executable.
Where self-reference, self-modification, and the diagonal meet
The unifying abstraction over all of this is Lawvere's fixed-point theorem: in a CCC, a point-surjective map A → Yᴬ forces every endomorphism of Y to have a fixed point. The contrapositive gives Cantor, Russell, the halting problem, and Gödel; the positive direction gives the existence of Y. This is the cleanest formal statement of why self-reference (a system rich enough to represent its own programs/proofs) automatically produces fixed points — which is what self-modification exploits and what the negative results constrain. Yanofsky's "universal approach to self-referential paradoxes" works this out as one diagram.
Models aimed squarely at "rewrites its own source/specifications"
A few constructions go beyond the foundational picture and target your exact phrasing:
Reflective rewriting logic (Meseguer/Maude) is the most concrete formalism for self-modifying specifications. A rewrite theory is an object; computations are arrows; and there is a universal theory U such that R ⊢ t → t' iff U ⊢ ⟨R̄, t̄⟩ → ⟨R̄, t̄'⟩. Because theories are represented as terms inside the logic, the system can rewrite its own rules — and this reflection is grounded in the existence of that universal (reflective) object, a fixed-point-like construction at the level of theories. If you want "a specification that edits its own specification," this is the implemented, semantically-grounded answer.
Inheritance as a generator fixed point (Cook & Palsberg). An object's method suite is fix(G) for a generator G : Self → Self; inheritance is a transformation of G before taking the fixed point. Overriding/self-modification of behavior is literally pre-composition on the generator, with the term-level fix tying the knot. This is the most down-to-earth instance of "modify the thing, then re-take the fixed point."
Recursion schemes over 0. If the program rewrites ASTs, structure-preserving transformation is a catamorphism/paramorphism (and unfolding new code is an anamorphism); a self-rewriting process that produces successive statesincluding new code is a coalgebra X → F(X), with the long-run behavior captured by νF. The μ-vs-ν choice is exactly the choice between self-modification that must bottom out (inductive, terminating rewriting) and one that runs as an ongoing productive process (coinductive).
Guarded recursion and the "later" modality 0 (Nakano, Birkedal et al., topos of trees = presheaves over ω). ▶ is an endofunctor, and the guarded fixed point fix : (▶A → A) → A gives well-defined self-reference for processes that reference themselves over time without ill-foundedness. This is the modern tool for giving denotational semantics to systems that loop on themselves productively. The shape of fix here matches Löb's theorem □(□A → A) → □A from provability logic — guarded fix is essentially Löb's computational content, which is a satisfying closure of the loop, since Löb is the modal principle governing exactly the self-referential reasoning Gödel's machinery is built on. (Foner's loeb :: Functor f => f (f a -> a) -> f a evaluating a spreadsheet is the toy version worth playing with.)
Futamura projections are the operational payoff: specializing an interpreter is a self-application, and self-applying the specializer mix to itself yields a compiler generator. This is "a program operating on its own representation" in real partial-evaluation practice, and it's the most tangible Y-combinator-flavored phenomenon in actual metaprogramming.
The one honest takeaway
If I had to compress it: genuine self-modification forces the equation D ≅ [D → D], which is unsatisfiable in well-pointed settings, so every real model either drops well-pointedness (untyped reflexive objects, D∞) or introduces a modality (□, ▶) that separates code from what code denotes. In both cases the self-referential equation is solved as a fixed point of an endofunctor, and whether you take the least or greatest fixed point decides whether the self-modification is required to terminate or is allowed to run forever as a productive process. The fixed-point combinator and the fixed-point of a functor are the value-level and type-level shadows of the same diagonal, unified by Lawvere.
A couple of things I deliberately did not overclaim: the Y-combinator/Löb correspondence is a correspondence of shape under the guarded reading, not an identity across all settings; and rewriting-logic reflection is a genuine theorem about a universal theory, not a loose analogy. If you want, I can go deeper on any one thread — the D∞ bilimit construction, the modal-staging type theory, or the Maude reflective tower are each worth a full treatment, and the third is probably the closest fit if your real interest is specifications rewriting specifications.
