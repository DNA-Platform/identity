The document builds the formalism incrementally across four layers:
§1 (λ→) — The irreducible core: variables, functions, application. Three typing rules. This is the skeleton everything else hangs on.
§2 (λ<:) — Adds the subtype relation <: and a single bridge rule, T-SUB (subsumption). This is inheritance, formally. §5 covers the extensions TypeScript needs beyond F<: — unions, intersections, conditional types, mapped types, recursive types — each specified as incremental additions. §6 shows how Haskell's type classes desugar into essentially the same structure via dictionary passing.
The key connection to your SRT work: notice how the entire edifice rests on a single judgment form (Γ ⊢ e : τ) relating terms to types through a context — a referential structure. Subtyping is a relation on types that propagates through subsumption. Your x =t> y with inheritance -> is doing analogous structural work but grounded in semantics rather than syntax.

The Bedrock — Syntax and Concepts That Never Waver
These appear in every document, from the earliest sketches to the latest papers. They're used reflexively, never questioned, never revised:
The primitive: R(x,y,t) written x =t> y. This is absolutely fixed. Every document treats it identically — "x refers to y through relationship type t." The three positions (subject, relationship, object) are invariant.
Equality internalized: E[eq]: x = y <iff> x =eq> y, written x == y. This appears everywhere and is never revised. The commitment that equality is a referent in the domain rather than an external logical relation is foundational and stable.
The canonical symbol (x) satisfying (x) =(x)> x. This appears in every document from the earliest to the latest, always with the same meaning — the symbol that represents x through itself. The self-referential structure ((x),x) == (x) is equally invariant.
The most specific relationship (x,y) satisfying x =(x,y)> y where (x,y) inherits from all other relationship types between x and y. This is used everywhere — in the axioms, the representation language, the algebra of perspective, the identity document.
Self-relationship as property: x =p> x written also as x.p. Properties are self-relationships; this is never questioned. The grounding p -> eq (all properties ultimately inherit from the equality relationship) is stable from your earliest sketches through the latest papers.
Inheritance: s -> t meaning s inherits from t (s is more specific). The transpilation s -> t := s =of> t appears in the transpilation document and the relationship paper. The direction is consistent: specific inherits from general, more specific is "below."
