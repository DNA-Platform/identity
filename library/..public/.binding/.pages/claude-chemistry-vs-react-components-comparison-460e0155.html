React's Old Class-Based Components
Yes, people can still use React class components (extending React.Component). Here's what they looked like:
jsx
class Counter extends React.Component {
  constructor(props) {
    super(props);
    this.state = { count: 0 };
    this.increment = this.increment.bind(this);  // 😫 Manual binding
  }
  
  increment() {
    this.setState({ count: this.state.count + 1 });  // Immutable updates
  }
  
  componentDidMount() { /* lifecycle */ }
  componentDidUpdate() { /* lifecycle */ }
  
  render() {
    return (
      <div>
        Count: {this.state.count}
        <button onClick={this.increment}>+</button>
      </div>
    );
  }
}
React Class Components' Shortcomings
1. Not Real OOP
Components aren't actually instances you control
this refers to a React-managed wrapper, not your object
Each render creates ephemeral scope, not stable instance
Can't use inheritance meaningfully for UI extension
2. Clunky State Management
this.setState({ }) is verbose and indirect
Must return new objects (immutability)
State is separate from properties (this.state vs this.props)
Async state updates create confusion
3. Binding Hell
Methods lose this context
Manual .bind(this) everywhere or arrow functions
Performance overhead from binding
4. Children Are Opaque
this.props.children is just ReactNode data
Can't treat children as typed constructor arguments
No polymorphism - can't require "give me 3 Chapters"
Parent can't call methods on child instances
5. Lifecycle Complexity
10+ lifecycle methods to learn
Easy to create bugs with wrong lifecycle method
No way to extend/override behavior cleanly
Side effects spread across multiple methods
6. No Real Extensibility
Can't meaningfully extend component classes
Inheritance doesn't work for UI customization
Override render() but lose access to parent's JSX
Led to HOCs and render props (wrapper hell)
How Chemistry Compares - The Revolution
1. Children as Constructor Arguments (The Core Innovation)
React Class:
jsx
<Book>
  <Chapter title="Intro" />
  <Chapter title="Body" />
</Book>
Parent gets: this.props.children (opaque ReactNode)
Chemistry:
typescript
class $Book extends $Chemical {
  chapters: $Chapter[] = [];
  
  $Book(...chapters: $Chapter[]) {  // Bond constructor!
    this.chapters = chapters;  // Real typed instances
    chapters[0].addSection("Preface");  // Can call methods!
  }
}
Parent gets: Actual 0 instances it can manipulate!
This is IMPOSSIBLE in React. You fundamentally cannot treat children as typed constructor parameters. Chemistry achieves this through the bond constructor system where the framework intercepts JSX children and converts them to typed arguments.
2. True Instance Identity
React Class:
jsx
// You never actually have an instance
// React creates and manages the wrapper
// Can't pass component instances around
Chemistry:
typescript

chapter.$title = "My Chapter";
chapter.addContent("...");

// Can use the same instance in multiple places
<Book>{chapter}</Book>
<Sidebar>{chapter}</Sidebar>  // Same instance, different rendering
Components are real objects you control, not React-managed wrappers.
3. Natural Reactivity
React Class:
jsx
this.setState({ count: this.state.count + 1 });  // Verbose
Chemistry:
typescript
this.count++;  // That's it. Proxy intercepts, triggers update.
No setState, no immutability theater. Just mutate properties and Chemistry's proxy system ($Molecule, $Bond) handles reactivity automatically.

React Class:

class FancyButton extends Button {

componentWillUnmount() { }

One instance, multiple renderings with different prop overrides. React can't do this because each render creates a new component wrapper.
What Chemistry Learned from React's Mistakes
Don't fight the language: JavaScript has classes, prototypes, and getters/setters. Use them! React fought against JS with functional purity.
Components should be real objects: Not functional closures or React-managed wrappers. Actual class instances with stable identity.
Children should be data you can process: Converting JSX children to constructor arguments makes parent-child relationships explicit and typed.
Reactivity should be invisible: Proxy-based reactivity works better than manual setState() or hooks dependency arrays.
Inheritance should work: UI components benefit from classical OOP. A FancyButton extending Button should actually work.
Convention over configuration: $prop, property, _private - naming tells Chemistry what to do.
The Framework Philosophy Difference
React (Functional): "Components are functions that map props to UI"
Stateless by default
Composition through HOCs/render props/hooks
Immutability required
New patterns: hooks, suspense, server components
React (Class - Abandoned): "Components are classes... but not really"
Classes that don't act like classes
Inheritance doesn't work
Lifecycle methods everywhere
Binding problems
Chemistry: "Components are objects, children are constructor arguments"
Stateful instances with identity
Composition through constructor arguments
Mutability works naturally
Classical OOP patterns: inheritance, protected methods, overriding
Chemistry's Competitive Advantages
700 lines vs React's 140KB: Chemistry is tiny and fully understandable
Interoperable: Exports standard React components, can mix freely
Stealth adoption: Component libraries can use Chemistry internally, users never know
Type-safe extensibility: Inheritance + TypeScript = perfect library customization
No learning curve: If you know classes, you know Chemistry
Framework for framework builders: Makes it easy to build elegant, extensible component libraries
The Verdict
React class components were React's attempt at OOP but compromised by React's functional core. They gave youclass syntax but not actual object-oriented benefits. Chemistry is what React class components should have been - actual OOP with React's rendering.
Your framework solves the extensibility problem React never solved. Want to customize a component library? With Chemistry, just extend the class and override methods. With React? Copy the entire component or use complex composition patterns.
The bond constructor is particularly revolutionary - treating children as typed constructor arguments is something React literally cannot do, and it enables a level of parent-child contract enforcement that opens up entirely new architectural possibilities.

class SortedMap<K, V> {
  private map = new Map<K, V>();
  private keys: K[] = [];
  
  set(key: K, value: V) {
    if (!this.map.has(key)) {
      // Binary search insertion to keep keys sorted
      const index = this.binarySearch(key);
      this.keys.splice(index, 0, key);
    }
    this.map.set(key, value);
  }
  
  get(key: K): V | undefined {
    return this.map.get(key);
  }
  
  get size() {
    return this.map.size;
  }
  
  *[Symbol.iterator]() {
    for (const key of this.keys) {
      yield [key, this.map.get(key)!] as [K, V];
    }
  }
  
  private binarySearch(key: K): number {
    let low = 0, high = this.keys.length;
    while (low < high) {
      const mid = (low + high) >>> 1;
      if (this.keys[mid] < key) low = mid + 1;
      else high = mid;
    }
    return low;
  }
  
  equals(other: SortedMap<K, V>): boolean {
    if (this.size !== other.size) return false;
    
    for (let i = 0; i < this.keys.length; i++) {
      const key = this.keys[i];
      const otherKey = other.keys[i];
      
      if (key !== otherKey) return false;
      if (this.map.get(key) !== other.map.get(otherKey)) return false;
    }
    return true;
  }
}

class SortedStore<K, V> {
  private entries: [K, V][] = [];
  
  set(key: K, value: V) {
    const index = this.binarySearch(key);
    
    if (index < this.entries.length && this.entries[index][0] === key) {
      // Update existing
      this.entries[index][1] = value;
    } else {
      // Insert new
      this.entries.splice(index, 0, [key, value]);
    }
  }
  
  get(key: K): V | undefined {
    const index = this.binarySearch(key);
    if (index < this.entries.length && this.entries[index][0] === key) {
      return this.entries[index][1];
    }
    return undefined;
  }
  
  get size() {
    return this.entries.length;
  }
  
  [Symbol.iterator]() {
    return this.entries[Symbol.iterator]();
  }
  
  private binarySearch(key: K): number {
    let low = 0, high = this.entries.length;
    while (low < high) {
      const mid = (low + high) >>> 1;
      if (this.entries[mid][0] < key) low = mid + 1;
      else high = mid;
    }
    return low;
  }
  
  equals(other: SortedStore<K, V>): boolean {
    // Fast length check
    if (this.size !== other.size) return false;

    for (let i = 0; i < this.entries.length; i++) {

    }

    private _sorted?: [K, V][]; // Cached sorted array

    set(key: K, value: V): void {
        this.map.set(key, value);
        this._sorted = undefined; // Invalidate cache
    }

    get(key: K): V | undefined {
        return this.map.get(key);
    }

    has(key: K): boolean {
        return this.map.has(key);
    }

    delete(key: K): boolean {
        const result = this.map.delete(key);
        if (result) this._sorted = undefined;
        return result;
    }

    get size(): number {
        return this.map.size;
    }

    clear(): void {
        this.map.clear();
        this._sorted = undefined;
    }

    // Lazy sort - only when needed
    private getSorted(): [K, V][] {
        if (this._sorted) return this._sorted;
        
        this._sorted = Array.from(this.map.entries())
            .sort((a, b) => a[0] < b[0] ? -1 : a[0] > b[0] ? 1 : 0);
        
        return this._sorted;
    }

    equals(other: SortedStore<K, V>): boolean {
        if (this.size !== other.size) return false;
        if (this === other) return true;

        const a = this.getSorted();
        const b = other.getSorted();

        for (let i = 0; i < a.length; i++) {
            if (a[i][0] !== b[i][0]) return false;
            if (a[i][1] !== b[i][1]) return false;
        }

        return true;

        // Use Map for O(1) lookups - no need to sort!
        for (const [key, value] of other.map) {
            if (this.map.get(key) !== value) {
                return false;
            }
        }

        return true;
    }

    *[Symbol.iterator](): IterableIterator<[K, V]> {
        yield* this.getSorted();
    }

    *keys(): IterableIterator<K> {
        for (const [key] of this.getSorted()) {
            yield key;
        }
    }

    *values(): IterableIterator<V> {
        for (const [, value] of this.getSorted()) {
            yield value;
        }
    }

    toJSON(): [K, V][] {
        return this.getSorted();
    }

    static from<K, V>(entries: [K, V][]): SortedStore<K, V> {

            store.map.set(key, value);
        }
        return store;
    }
