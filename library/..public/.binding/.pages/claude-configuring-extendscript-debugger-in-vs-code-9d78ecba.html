Based on the documentation and your debug configuration, you can modify the "script" field to point to the build folder by using VS Code variables. Here's how:
json
{
    "version": "0.2.0",
    "configurations": [
        {
            "type": "extendscript-debug",
            "request": "launch",
            "name": "Run File in Illustrator",
            "script": "${workspaceFolder}/build/${relativeFilename}",
            "preLaunchTask": "npm run build",
            "engineName": "main",
            "hostAppSpecifier": "illustrator-29.064"
        }
    ]
}
If your build folder has a different structure (e.g., if it changes the extension to .jsx), you can use:
json
"script": "${workspaceFolder}/build/${fileBasenameNoExtension}.jsx"
Key VS Code variables:
${workspaceFolder}: Path to your project root
${fileBasenameNoExtension}: Current file name without extension
${relativeFilename}: File name relative to workspace root
Make sure your build task generates files in the correct location that matches this path.

Let's debug this. We can modify the configuration to log information using console.log() to see what path it's trying to use. Add this to your VS Code settings.json:
json
{
    "extendscript.advanced.debugLevel": 2
}
Then modify your launch configuration:
json
{
    "version": "0.2.0",
    "configurations": [
        {
            "type": "extendscript-debug",
            "request": "launch",
            "name": "Run File in Illustrator",
            "script": "${command:extension.extendscript-debug.getScriptPath}",
            "preLaunchTask": "npm run build",
            "engineName": "main",
            "hostAppSpecifier": "illustrator-29.064"
        }
    ]
}
This will show what file path it's attempting to use. Also, can you share your project structure and build script? That would help diagnose where the path resolution is failing.
