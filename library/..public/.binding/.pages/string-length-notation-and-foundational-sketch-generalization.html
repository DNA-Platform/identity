Reading your two lines against the Sketch's five forms:
string =length> string          identification form: identity =identification> identity
length =(length,string)> string relationship form:  subject =relationship> object,
                                                     relationship == (subject, object)
So length occupies two positions: identification in the first line, subject in the second. The generalization is that move — an identification descends into the subject position and relates to its identity. Nothing in the primitive forces x =p> x =|> p => x; that's the claim your notation is adding. Once it's added, Specification supplies (p,x), and the call notation is just a name for the witness:
x =p> x  &  p => x  =|>  p(x) := (p, x)
x.p      == p(x)                (object-first spelling of the same referent)
"Length of string" reads subject-first; string.length reads object-first; both denote (length,string).
Run it through the other Sketch forms and each one gives the call a fixed-point shape:
relationship:    subject(object)             == (subject, object)     -- unconstrained
reference:       reference(referent)         == reference
representation:  representative(representation) == representation
individuality:   individual(individual)      == individual
So the canonical symbol is the self-call: x(x) == (x,x) == (x). And Uniqueness keeps the calls apart — length(string), hash(string), first(string) are three distinct most-specifics of three distinct pairs.
One thing your example leaves open: length(string) names a relationship, not the number 5. To get the value in, the natural candidate seems to be a second identification, string =5> string with 5 -> length — the specific value inheriting into the general identification — but that's a guess for your ruling, not something I can derive from the Sketch.
