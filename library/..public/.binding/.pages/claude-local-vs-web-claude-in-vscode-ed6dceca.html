On Claude code in vscode, I have the option between local and web. What's the difference?
Claude
20:54 UTC, 22 June 2026
Local runs Claude Code on your own machine — the agent executes in your VS Code environment, reads and writes files on your local disk, runs commands in your local terminal, and uses your local Git checkout. Everything happens on your computer, so it has direct access to whatever project you've got open.
Web (the "web sessions" you're seeing) runs Claude Code on Anthropic's cloud infrastructure instead. You kick off a session that operates on a remote sandbox — typically working against a repo it clones there rather than your local files. These are the same sessions you can start and monitor from claude.ai/code or the mobile app, which is the main appeal: you can launch a task, close your laptop, and check on it later from your phone. The work runs remotely and persists independently of your machine.
The practical split:
Local is for hands-on work where you want the agent touching the actual files in front of you, using your local environment, dependencies, and tooling. Lower latency, full access to your working directory, but it only runs while your machine is on and the session is active.
Web is for delegating longer or asynchronous tasks — fire it off, let it run in the cloud, pick it up from any device. It needs the repo accessible remotely (e.g. on GitHub), and it won't see uncommitted local changes or your local environment quirks.
Your screenshot shows "No web sessions yet" because you haven't started a cloud-based one — the link just points you to claude.ai/code to spin one up.
One caveat: cloud-based agent features change fairly often. If you want the precise current details on what web sessions can access and how they're configured, I can check Anthropic's docs — want me to?

Yes — long tasks are exactly what web sessions are built for. That async, hand-it-off-and-walk-away model is the whole point of running in the cloud rather than locally.
Here's the practical picture for kicking one off:
The web session runs on Anthropic's cloud, gets an isolated VM with your repo cloned into it, and sessions persist even if you close your browser, and you can monitor them from the Claude mobile app. So you can start something substantial, shut your laptop, and check progress from your phone later. Web sessions are a good fit for drafting a PR to fix a bug while you focus on something else, running a codebase-wide refactor across many files, or generating documentation without interrupting your local environment.
The one thing that trips people up — and is probably why "how to kick one off" isn't obvious — is thatweb sessions clone from GitHub, not from your local disk. The session clones your current directory's GitHub remote at your current branch, so you have to push first if you have local commits, since the VM clones from GitHub rather than your machine. If your repo isn't on GitHub or your latest work is only local, the cloud session won't see it.
Two ways to start one:
From the browser — go to claude.ai/code, connect your GitHub account, pick the repo, and describe the task. It clones, works, tests, and prepares a PR for you to review.
From the terminal — if you're already in a project, claude --remote "your task description" spins up a cloud session for you. Each --remote command creates its own independent cloud session, so you can fire off several that run simultaneously, and monitor them all with /tasks in the CLI. When one finishes you can create a PR from the web interface, or teleport the session to your terminal to continue working on it locally.
For genuinely complex long tasks, the recommended pattern is to plan locally and execute remotely: start Claude in plan mode to collaborate on the approach, then send the work to the cloud once you're happy with the plan. That gives you control over strategy while letting it grind through execution autonomously.
A couple of caveats worth knowing:
The cloud VM has limited network access by default, so if your task needs to hit external APIs or fetch packages from unusual sources, you may need to configure the environment's network access first.
There's a related-but-different feature called Routines (the old /schedule) for recurring cloud tasks on a cron schedule — daily code reviews, dependency audits, etc. Each run is a fresh session that clones the repo from the default branch. That's a separate thing from a one-off long task, but worth knowing it exists if "long-running" for you ever means "runs every night" rather than "runs for two hours once."
