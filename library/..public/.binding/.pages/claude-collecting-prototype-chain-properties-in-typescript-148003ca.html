Based on your coding style from chemistry.ts, here's a method that collects properties from the prototype chain:

private _collectPrototypeProperties(): Set<string> {
    const properties = new Set<string>();
    const chemical = this._chemical;
    let prototype = Object.getPrototypeOf(chemical);
    
    // Walk up chain until we hit $Chemistry (exclusive)
    while (prototype && prototype.constructor.name !== '$Chemistry') {
        // Collect own properties from this prototype
        const descriptors = Object.getOwnPropertyDescriptors(prototype);
        for (const property in descriptors) {
            // Skip constructor
            if (property === 'constructor') continue;
            properties.add(property);
        }
        
        // Move up the chain
        prototype = Object.getPrototypeOf(prototype);
    }
    
    return properties;
}
This follows your style patterns:
Terse with semantic naming (properties, chemical, prototype)
Early return/continue for validation (if (property === 'constructor') continue)
Direct iteration without unnecessary abstractions
Clear intent through variable names rather than comments
Assumes $Chemistry exists in the chain (as you specified)
The method uses Object.getOwnPropertyDescriptors to ensure we capture all properties including getters/setters and non-enumerable ones, which seems important for your framework's metaprogramming approach.

private _collectPrototypeProperties(): Set<string> {
    const properties = new Set<string>();
    const chemical = this._chemical;
    let prototype = Object.getPrototypeOf(chemical);
    
    // Walk up chain until we hit $Chemistry (exclusive)
    while (prototype && prototype.constructor.name !== '$Chemistry') {
        // Collect own properties from this prototype
        const names = Object.getOwnPropertyNames(prototype);
        for (const name of names) {
            // Skip constructor
            if (name === 'constructor') continue;
            properties.add(name);
        }
        
        // Move up the chain
        prototype = Object.getPrototypeOf(prototype);
    }
    
    return properties;
}
Better choice - getOwnPropertyNames gives us exactly what we need (the names including non-enumerable ones) without the overhead of creating descriptor objects we don't use.
