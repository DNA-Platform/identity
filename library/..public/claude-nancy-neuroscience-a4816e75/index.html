Your design isn't ad hoc — it's a rediscovery of two named architectures, and naming them gives you the reference literature plus a sharper sense of where the discipline has to live. Here are the six patterns that actually carry weight, mapped to what you've already built.
1. Functional core / imperative shell + ports-and-adapters. Your "pure core, effects at the edges" split is exactly Gary Bernhardt's functional-core/imperative-shell, and the io/viz boundary is Cockburn's hexagonal (ports-and-adapters) architecture. Worth naming because it tells you what the payoff is and where it leaks: a genuinely pure core is deterministic and unit-testable with no fixtures or disk, and io/viz become adapters you can mock or swap. The discipline this demands is that no hidden effects sneak into the core — the moment a stats function lazily reads a file, the purity guarantee (and the cheap testing) is gone. The other cost is that the types crossing io→core have to be explicit and stable; that boundary is where you'll spend design effort.
2. Monorepo, src-layout, 0 + 1. For a codebase whose whole point is a shared core outliving many analyses, a monorepo with one installable package beats many repos — many repos means the core fragments into divergent vendored copies within a year, which is the failure mode you're explicitly trying to avoid. Use src-layout (pyproject.toml,src/yourpkg/) so analyses import the installed core, not whatever's shadowing the path. Tradeoff: the monorepo couples release cadence and grows large; you mitigate that by treating the core as internally versioned (pattern 3) rather than splitting the repo.
3. Core as an internally-versioned library with contracts, deprecation, and asymmetric testing. The thing that destabilizes a shared core is never a new analysis adding to it — it's a new analysis needing the core to change to make its hypothesis work. So the contract is: analyses live in the volatile layer and may not edit the core to get unstuck; core changes are deliberate, tested, and versioned. Concretely: semver the core, have each analysis record the core version it ran against, define the io/model/stats boundaries astyping.Protocol or ABCs so analyses depend on interfaces not implementations, and use DeprecationWarning with a real window before removal. Test asymmetrically — hammer the core (pytest, high coverage, and Hypothesis property-based tests especially on the null/confound machinery, since every downstream claim inherits its correctness), while analyses get only "does it still run" smoke tests. Your stats layer is the part of the core that should be the most frozen and most heavily property-tested. Tradeoff: semver discipline is genuine overhead for a two-person lab; the payoff is that a six-month-old analysis still reproduces.
4. Checkpoint/data provenance: manifest-sidecar → DVC or DataLad. Your "one provenance-stamped checkpoint anchor" needs the stamp to capture what produced it: data hash + training commit + config. Don't reach for heavy tooling first — start with a git-tracked JSON/TOML manifest beside the gitignored checkpoint, recording checkpoint hash, train commit SHA, data hash, and config. Graduate only when storage outgrows that: DVC is the lighter, pipeline-and-remote-storage option (.dvc pointers, dvc.lock for lineage); DataLad (git-annex based) is heavier but its datalad run/rerun captures the exact command, inputs, and outputs as re-executable provenance, which is the stronger fit if "regenerate this checkpoint from scratch" is a requirement rather than a nice-to-have. For your scale I'd run the manifest pattern now and keep DVC in reserve.
5. Steal the catalog, skip the framework. Kedro reached 1.0 in 2025 and graduated within LF AI & Data, so it's real and maintained — but it's opinionated pipeline orchestration (node wiring, a declarative data catalog, a DAG), and that ceremony actively fights a codebase dominated by short-lived exploratory analyses. The valuable 10% is its data catalog idea: a declarative registry mapping dataset names to loaders. Build that thin thing inside your io layer and skip the framework; adopt Kedro proper only if and when one analysis hardens into a pipeline you re-run on a schedule. Same verdict on cookiecutter-data-science (now v2, with a ccds CLI and more tool optionality): take its directory conventions as a reference, don't be religious about them. Tradeoff: rolling your own catalog is a few hundred lines you own forever versus inheriting Kedro's plugins and Kedro-Viz lineage for free — but the latter only pays off at pipeline scale.
6. Analysis registry + docs-as-code + literate provenance. This is the part that answers "what analyses do we have, what's alive." The highest-leverage single thing is a machine-readable manifest per analysis subpackage — title, the question it asks, a controlledstatus field (alive / dead / superseded), checkpoint hash, headline results, and a link to its prose page — plus a top-level harvester that compiles them into an index. That index is your registry; it's the same pattern as a model or dataset registry, pointed at analyses instead. Layer docs-as-code over it: MkDocs-Material or Sphinx with mkdocstrings so the core's API docs come straight from docstrings and the prose library lives in-repo, versioned with the code it describes. For the analysis write-ups themselves, use literate provenance — Quarto (the language-agnostic Rmarkdown successor) or Jupyter Book / MyST, with Jupytext keeping notebooks as diffable .py — so a write-up executes against the pinned checkpoint and embeds its own figures, which means the prose physically cannot drift from the code that produced it. Tradeoff: the registry only stays honest if someone actually sets status = dead when a hypothesis dies; an unmaintained status field is worse than none because the index then lies with authority.
If I had to name the one discipline that makes all six hold: the boundary between core and volatile is asocial contract, not just a directory. The architecture won't stop an analysis from reaching into the core and bending it — only the rule "if you need the core to change, that's a versioned core PR with a test, not a quick edit" does that. Everything else is scaffolding around enforcing that line.

# Initial Data Exploration
![](figures/cover-psychedelic.jpg)

**Matched two-photon V1 recordings before and after DOI — a first descriptive pass**
*Animal 33328 · session 6 (baseline), session 7 (DOI) · 2026-06-23*

---

## What this exploration is for

These are matched recordings of mouse V1 before and after DOI: the same stimuli, the same
repeated test images, the same cells tracked across both sessions. The data are sound; what is
unsettled is how to analyze them. A first pass has three jobs — confirm that the data can bear the
comparisons we intend, characterize the pre/post differences at face value, and surface the
confounds that decide whether a naive contrast means anything at all. The sequence works inward:
from a single image, to the whole population, to the same cells in both sessions, closing on the
behavioural confound that governs every reading above it. What it produces is a decision about how
DOI must be analyzed — not a claim that DOI does anything.

## What the design provides

![The two recordings](figures/00_recordings.png)
![Example stimuli](figures/01_stimuli.png)

Two preconditions make the rest possible. First, both sessions carry the repeated test tier — about
100 images shown roughly 10× each — which is the only lever for estimating a per-cell noise ceiling.
Second, the sessions are balanced over the same stimuli (1,654 cells / 5,936 trials at baseline;
1,449 / 5,996 under DOI), so same-image and cross-session comparisons are licensed. Both are checks
that the analyses are well-posed, not results.

## A single image, on the cortical surface

![One image, two states](figures/02_single_image.png)

What does a single stimulus do to the population, and where on the cortex? For one image presented
in both sessions, every neuron is plotted at its cortical position and shaded by its response on
that trial, on a shared scale.[^single] The code is sparse: the image drives a scattered minority
of cells, with no spatial clustering and no artifact. That fixes the regime we are working in —
mean rates ride on a handful of high responders, and single-image contrasts are underpowered — so
the analysis moves to distributions over all cells and trials, carrying with it a first qualitative
look at whether the same image recruits different cells under DOI.

## Behavioural state, per session

![Behavioural state differs](figures/03_behavior.png)

V1 is powerfully modulated by arousal and locomotion, so each session's behavioural state has to be
characterized before any neural comparison can be trusted. The three covariates — pupil size, its
derivative, and running speed[^behchannels] — are shown as per-session distributions. They differ,
and most visibly in running: the animal is near-stationary at baseline and frequently locomoting
under DOI. This lays the confound on the table at the outset, and sets up the final analysis — how
much of the pre/post distinction is nothing more than this.

## Per-cell reliability (the noise ceiling)

![Per-cell reliability](figures/04_reliability.png)

Reliability sets the ceiling on how much of a cell's response any model could hope to explain, which
makes it the natural basis for choosing analyzable cells. Within a session it is the split-half
correlation across the repeated images: split each image's repeats into two, average within each
half, and correlate the two per-cell half-means across images.[^splithalf] The ceiling is usable —
a broad spread reaching ~0.9, with a baseline median near 0.5 — and it falls under DOI (median
0.51 → 0.38). That drop is two things at once: a data-quality fact, since DOI fits will look worse
for reasons that are not mechanistic, and a candidate effect — though one already shadowed by the
state difference above, because a more variable behavioural state inflates apparent noise on its
own.

## Population rate structure

![Population code](figures/05_population.png)

The gross population statistics — sparsity, dynamic range, any global shift in scale — guide
normalization and reveal whether a difference is global or cell-specific. The panels show each
neuron's trial-averaged mean, sorted, alongside the density of all response values.[^units] The code
is sharply long-tailed in both states, and the baseline rate profile sits above DOI across the
entire rank range: the reduction is broad rather than confined to a subset. That sharpens the
question for the matched-cell analysis — does the shift survive once cell identity is held fixed?

## Population co-activity

![Population raster](figures/06_population_raster.png)

Trial-averaging discards exactly the structure that justifies population methods, so it is worth
looking directly for co-active ensembles and population-wide events. Neurons are ordered by a

1 · Open Q9 — is there a recoverable within-scan gain signature?
Start with the algebra, because it settles what's possible. Per-scan per-neuron std normalization maps each cell's response to rᵢ/sd(rᵢ), computed within each scan. Any factor that multiplies all of a cell's responses by the same constant — z-drift gain gᵢ, bleaching, a flat DOI gain — appears in both numerator and denominator and cancels exactly. So:
The litmus test: a gain signature is recoverable iff it can be written as a ratio or shape within one neuron's stimulus-response profile, within one scan. Anything expressible as "neuron i's responses, all multiplied by a scalar" is gone — and that includes not just absolute gain but the per-cell distribution of gains and the cross-cell gain map. Your conclusion, and the correction to my modulator idea, are both right at this level: a flat multiplicative DOI gain is mathematically unrecoverable here, and a modulator fit on normalized responses outputs gain in normalized units, so its absolute level inherits the same erasure.
But "response gain reduction" in the Michaiel sense is not a flat scalar, and that's the opening. Michaiel reports a reduction in response amplitude and in surround suppression — and surround suppression is a within-neuron ratio. The recoverable, scale-invariant, within-scan signatures, in rough order of how clean they are:
Surround suppression / size-tuning ratio. SSI = 1 − R(large)/R(optimal-size), a ratio of one cell's responses to two stimulus sizes. Both responses carry the same gᵢ, so it cancels — SSI is invariant to both z-drift and per-scan normalization, and it is one of the two effects Michaiel actually documents. Synthesize size-varying stimuli in-silico from each twin (the Franke move, applied to size instead of color).This is the cleanest gain-control read available and it's the one most aligned with the literature.
Contrast-response function shape. Sweep MEI contrast in-silico and fit the normalized CRF: c50 (semi-saturation contrast), exponent/slope, saturation. A flat gain leaves the shape unchanged; a divisive/contrast-gain change (Carandini–Heeger normalization) shifts c50. Shape is scale-invariant; the y-scale you can't trust is exactly the part you don't use.
Behaviour→gain coupling, as a within-scan ratio. Your parenthetical instinct is valid once you read the ratio, not the level: gain(active)/gain(quiet) within a scan is scale-invariant, and DOI changing how steeply arousal/locomotion multiplies responses is a real, recoverable question. The modulator answers it — provided the behaviour ranges overlap (they barely do; see §2).
SNR / reliability shape. A pure scalar leaves split-half reliability invariant, yet you see 0.51→0.38. That drop isitself proof of a non-scalar change (added noise or an SNR change), and reliability/SNR is scale-invariant. It won't give you "gain," but it's a recoverable signature that a flat-gain account cannot produce — worth stating as positive evidence, not just a caveat.
Evoked/spontaneous ratio, if you have blank or inter-stimulus epochs — both scale with gᵢ, the ratio survives, and a signal-to-baseline change is gain-adjacent.
Sparseness / kurtosis of each cell's response distribution — invariant to a scalar, sensitive to threshold/nonlinearity changes.

Interleaving requirement. z-drift and bleaching add a within-scan temporal gain trend that per-scan std (one constant per cell) does not remove. 2 · The other silent constraints, exhaustively
The overarching one — drug is perfectly confounded with scan order. n=1 mouse, no vehicle, DOI always second. Everything that differs between scan 1 and scan 2 — bleaching, z-drift, fatigue, adaptation, time-on-task, behaviour drift, deconvolution-baseline drift — is confounded with the drug. Conditioning on behaviour removes one of these confounds, not the rest. The honest object of study is "how the represented features differ between an earlier and a later scan, of which DOI is the salient but not isolated difference." State this as the frame above Part 8; it's stronger than the behaviour-decode caveat alone.
Volumetric (beyond the amplitude z-drift):
z-drift is a temporal trend, not a per-scan scalar. Per-scan std removes the scalar part but leaves trial-order-correlated amplitude. Any non-interleaved split (including a temporally-ordered train/val/test split) is confounded. Check the split is random, not chronological.
Per-plane timing. A volume is planes scanned sequentially, so different depths are sampled at different phases and at a lower per-plane rate. Behaviour (pupil/running) alignment to neural response differs by plane; the shifter/modulator assume one alignment. Confirm per-plane temporal offsets are handled in the loader, or deep cells get mis-conditioned.
Matched cells are re-sampled at a different z. z-drift means the same physical soma sits at a slightly different optical cross-section in scan 2 — a per-cell amplitude and waveform change that isn't biology, and a survivorship bias: the ~50% that match are the drift-stable cells (likely larger/brighter, possibly specific depths). Your matched population is non-random in a way correlated with the imaging, not the drug.
Depth/layer heterogeneity. A volume spans L2/3 (maybe L4); 5-HT2A receptor density and behavioural modulation vary by layer, so one twin pools heterogeneous populations and DOI sensitivity is depth-varying. Carry depth as a covariate in Part 8; don't average it away.
Per-scan normalization (beyond gain erasure):
The normalizer is behaviour-state-dependent. std is taken over the whole scan, and the two scans have very different behaviour mixtures (near-stationary vs frequent locomotion). High-running trials have larger responses, inflating the post scan's std, so the normalization constant itself carries the behaviour difference. Even "scale-invariant" comparisons route a residual behaviour-mixture confound through the divisor. Consider normalizing on a behaviour-matched subset, or at least testing sensitivity to the normalizer's trial set.
Zero-inflation sensitivity. Deconvolved responses are non-negative with a point mass at zero; std of a zero-inflated variable depends on sparsity, which changes with SNR/state — so the normalization interacts with #deconvolution below.
Behaviour (the one that quietly breaks Part 5):
The behaviour ranges barely overlap, so "same fixed state for both twins" is an extrapolation. The baseline twin never saw high locomotion; the post twin saw little stationarity. Synthesizing MEIs/CRFs at a fixed active (97th-pct) state queries the baseline twin far out of its training distribution — the modulator extrapolates and the read is unreliable. You must pick the fixed state inside the intersection of both scans' behaviour distributions; if that overlap is thin, the fixed-state comparison is fragile and may only be defensible at the quiet end. This is a direct, silent breakage of Parts 5/8 and it's caused by the same 45-min behaviour shift that gives you the 97% decode.
DOI alters the pupil itself. A 5-HT2A agonist plausibly changes pupil dynamics/baseline directly, so "pupil size" is partly a drug readout, not a pure arousal covariate. Conditioning on it doesn't cleanly subtract state, because the covariate is drug-contaminated — and the shifter's pupil-position input may shift in reliability too.
Session / pharmacokinetics:
Photobleaching adds its own monotonic within-scan amplitude decline in scan 2 — a second temporal-trend confound stacked on z-drift, removed in scalar form by per-scan std, surviving as a trend.
The "post" scan is not a stationary drug state. Over ~45 min the DOI level rises/peaks/declines; one twin trained on the whole post scan averages a moving pharmacological state confounded with time-in-scan and bleaching. If anything, fit/inspect early-vs-late post sub-windows.
Matching:
Confirm the match is anatomical-position-only. "Functional-stack coordinates" is ambiguous; if matching uses any response/tuning similarity, you select against the very cells whose tuning DOI changed — building the null into the matched set. This is the most dangerous silent trap after the order confound. It must be purely structural registration.
Twin design:
Two separate twins lose the comparability a shared core gives. Franke varied state in-silico within one model; you train two, so every MEI/metamer difference conflates representation change with two cores converging differently on differently-normalized, different-SNR data. The cleaner design (and closer to the state-factor template you started from) is a single shared-core twin with a drug-state factor, so pre/post outputs live in one model. The trade-off is real and worth a decision, not a default: a shared core assumes the core features are invariant — which is partly what you want to test — so two twins are more flexible but less comparable. At minimum, acknowledge which you're buying.
learned-μ fit independently per twin → mask misalignment. "MEI×MEI correlation in the RF mask" assumes the same cell's μ matches across twins; independent fits jitter μ, inflating apparent MEI change. Share or co-register μ across the pre/post twins before computing spatial-change metrics.
Deconvolution:
The deconvolution transform is not stationary across scans. Its nonlinearity/threshold depends on SNR, which moves with z-drift/bleaching/DOI, so a "nonlinearity change" (your CRF/sparseness reads) could be partly a deconvolution artifact. Where possible, sanity-check key gain-control reads against raw ΔF/F, not only deconvolved activity.
Statistics:
Pseudoreplication. With one mouse and one session, 749 cells are not 749 independent tests of the drug — they're n=1 for "DOI in mice." Cell-wise p-values test "these cells differ between scans," not "DOI has an effect." Report paired within-cell effect sizes descriptively; don't let cell count masquerade as statistical power for a drug claim.
Reliability-selection circularity. Masking to cells reliable in both states (correct for FEVE) can bias the feature comparison toward cells DOI didn't destabilize — under-representing exactly the cells that changed most. Report how the matched/reliable filtering shifts the population.
The thread you keep pulling is one knot: a per-neuron multiplicative subspace (z-drift, bleaching, flat gain, behaviour-mixture in the normalizer) is both unavoidable and unidentifiable, and the design confounds drug with order. Everything addressable lives in ratios and shapes within a scan — surround suppression, CRF shape, behaviour-gain coupling, tuning correlations, sparseness — and everything you have to surrender lives in levels across scans. If you make that the organizing principle of the spec (ratios in, levels out) rather than discovering it constraint-by-constraint, most of the remaining silent traps announce themselves.

1 · The toolkit
The point metrics, and exactly what each does:
CCabs — Pearson correlation between prediction and repeat-averaged response, CCabs = Cov(r̄,ȳ)/√(Var(r̄)Var(ȳ)) (your "corr-to-avg"). Affine-invariant: blind to gain/offset errors.
CCmax — the ceiling, Schoppe 2016 (from Hsu 2004): CCmax = √[(N·Var(ȳ) − mean_t Var(y)) / ((N−1)·Var(ȳ))], N = repeats. Depends only on the data and N, not the model.
CCnorm = CCabs/CCmax (Schoppe Eq. 8); CCnorm² is meant to read directly as "percent explainable variance explained."
SPE / FEV-explained — the signal-power-explained metric (Sahani & Linden 2003), which is what neuralpredictors.get_fev computes (your FEVE). Crucially it is MSE-based, so unlike CCabs it penalizes gain/offset miscalibration. Schoppe's key result: SPE and CCnorm² are nearly identical above ~50% performance but diverge sharply below it (his Fig. 2; Eq. 7 vs Eq. 28 coincide only as prediction error → 0). So FEVE and CCnorm² are not interchangeable in your low range — and their divergence is itself diagnostic (see Q3).
FEV (fraction of explainable variance, SP/TP) — a property of the data (the ceiling), report it separately so you can see whether the ceiling or the fit moved.
Oracle correlation (leave-one-out: one repeat vs. mean of the rest) — the empirical ceiling; Walker 2019 / Lurz 2021 report fraction-oracle = model_corr / oracle_corr.
Single-trial correlation — the Sensorium 2022 leaderboard's primary metric (predictions vs single trials, averaged over neurons); repeat-averaged correlation and FEVE are the characterization metrics, not the leaderboard score.
Held-out − train gap — overfitting; report per arm.
Poisson calibration / residuals — note PoissonLoss here is a quasi-likelihood: deconvolved calcium is continuous, non-negative, zero-inflated, not counts, so a formal Poisson GOF test (deviance, QQ of randomized-quantile residuals) will show misspecification by construction. Use held-out Poisson log-likelihood (bits/response) as a relative score, not a generative test.
A goodness-of-fit *test*, not a point metric — the field is metric-heavy and test-light. The rigorous substitute isPospisil & Bair 2021 confidence intervals (below): the "test" becomes whether the CI on the corrected fraction excludes chance / overlaps the ceiling.
2 · The key one: comparing fit across different noise ceilings
FEVE/CCnorm normalize by the ceiling, so in expectation they correct for a lower explainable variance. They do not fully correct, for three reasons that all get worse exactly where you are (post-DOI, lower SNR):
Ratio-of-noisy-estimates bias. FEVE is (estimated explained)/(estimated explainable); both are noisy and the expectation of the ratio is only approximately the ratio of expectations. As the denominator (explainable variance) shrinks under DOI, the estimate gets more biased and heavy-tailed. Median-over-cells dampens but does not remove this.
Direction-of-bias flips by method. Naive r²/CCabs is pessimistically biased — as trial-to-trial variability rises, measured correlation falls, so a perfect model looks poor. Naive normalized estimators can swing the other way: Pospisil & Bair find some commonly used methods substantially overestimate model fit. So an uncorrected FEVE can understate post-DOI fit (via the raw-r² component) or overstate it (via the normalization) — and which dominates depends on SNR, which differs across your conditions. That is precisely the confound you're worried about, and normalization alone doesn't kill it.
Variance explosion + residual bias at low SNR. At low SNR the corrected estimators become so variable that confidence intervals can cover the entire [0,1] range, and an appreciable bias remains in the population average that they could not fully correct (their Eq. 16).
The right way to compare across conditions with different ceilings:
Fix the cell set (reliable-in-both — your discipline; see Q4) so population composition is constant.
Use a bias-corrected estimator with CIs: Pospisil & Bair's r²_ER (subtracts unbiased noise-term estimates from numerator and denominator of r²) with BCa bootstrap CIs. Report the CI, and use their SNR metric to threshold and to report each condition's SNR, so a fit-difference is interpreted against the SNR-difference rather than instead of it.
Report the ceiling itself (oracle corr / FEV) alongside the normalized score, so "the encoder got worse" vs "there was less to explain" is visible, not inferred from one ratio.
Lean on the ceiling-matched contrasts you already have (the within-condition A-vs-B), where this entire problem is absent.
Bottom line: FEVE is the right direction but not a sufficient correction across your pre/post ceiling gap; it must be paired with SNR reporting and CIs, and the strongest claims should ride on the ceiling-matched arm contrast.

Shifter check. Arm A also carries the eye-position shifter; under DOI pupil-centre tracking may degrade, and a bad shifter hurts A but not B. Test arm A with the shifter disabled.
The DOI-pupil contamination. Under a 5-HT2A agonist, pupil is partly a drug readout, so in a single-state twin the behaviour channels are collinear with nuisance — a structural reason behaviour conditioning can stop helping post. This favors (a) and is not fixable by retraining.
My read of the pattern (behaviour helps pre, actively hurts post, same cells/ceiling): most consistent with(a) — the behaviour→response coupling the model exploited at baseline is non-stationary under DOI, with covariate shift amplifying it. But run the ablation before committing; it cleanly separates (a) from (b).
4 · Gotchas with 456 vs 369 reliable cells
Fixed-reliable-in-both is necessary but not sufficient. Intersecting the reliable sets removes the population-composition confound (you're no longer comparing different cells). It does not remove the within-cell SNR difference: the same cell has a lower ceiling post, so its FEVE carries a different (larger) bias post than pre (Q2 point 3). Fixed cell set + per-cell SNR reporting + CIs, not fixed cell set alone.
Selection is correlated with the effect. The cells that drop out post (456→369) are the ones DOI made unreliable — plausibly the cells whose coupling changed most. Reliable-in-both therefore under-samples the cells that changed, biasing the feature comparison toward stability. Report how the intersection shifts the population (depth, baseline reliability, tuning).
Check N (usable repeats) is matched. CCmax depends on N; if motion/behaviour rejection drops more repeats post, CCmax is estimated from fewer trials and is itself noisier. Match or report N per condition.
FEVE instability at low ceiling. Expect post FEVE values that clip >1 or go negative per cell; that's the ratio blowing up, not a bug. (The fMRI literature even floors CCmax at 0.3 to stop CCnorm exceeding 1 — a hack that signals how unstable this gets at low SNR.) Report medians with bootstrap CIs, and consider an SNR floor à la Pospisil & Bair (who note ~40% of some recordings fail even a liberal SNR criterion).
Don't let cell count read as power. 369 vs 456 is not a sample-size story about DOI — it's n=1 mouse/session either way; the counts are descriptive, and the per-cell estimates are paired within cell.
If you want one upgrade that addresses Q2 and Q4 together: replace bare median-FEVE comparisons with Pospisil & Bair r²_ER + BCa CIs on the reliable-in-both set, reporting each condition's SNR and oracle ceiling next to the score — and make your headline claims on the ceiling-matched within-condition arm contrast, where none of this bias applies.

The audit axis that matters is exactly the one you named: confirmed vs. merely built. For each item below the question isn't "is it in the pipeline" but "is there an artifact — a sweep, a figure, a control — that proves it holds on this scan." I'll keep it to the checklist and the killers, no lit review.
(1) The encoding twins
Gamma plateau on *this* scan. Sweep gamma_input and gamma_readout ~1 order of magnitude each around the frozen Sensorium values; confirm a flat validation plateauand that gamma_input isn't in a regime where it changes MEI structure. Built = pasted; confirmed = the sweep exists. (Your open one.)
Ensemble saturation, not just "n=5." Confirm every seed early-stopped on val-correlation (not the max_iter ceiling) and that a seed-count curve shows the metric and the MEIs stop moving by 5. The ensemble is the MEI sharpness lever, so saturation is the thing to show.
Readout retinotopy is 2-D. The learned-μ map must be a smooth 2-D retinotopic progression, not collapsed to a line — the figure, not the assertion.
Validation is ceiling-referenced and bias-aware. FEVE (Schoppe) + oracle + corr-to-avg on held-out repeat-averaged test, on reliable-in-both cells, full-length get_fev (the survivorship fix), with per-condition SNR and CIs (Pospisil & Bair). A bare correlation is not confirmation.
The post/A collapse is explained, not shipped. From the parallel thread this arm is the outlier; the behaviour-freeze/shuffle ablation must have been run to establish (a) coupling non-stationarity vs (b) a pathology. An unexplained worst-arm is not publication-final.
First-layer filters oriented/healthy; train−test gap comparable across the four twins.
(2) MEIs
Recipe verbatim. The Walker preconditioning schedule (Fourier smoothing, blur anneal, norm) lifted from Walker's Methods / the nnvision walker-op defaults — numbers matching, not "structure looks right."
Energy constraint *and* post-hoc match. Confirm both the fixed L2 budget during ascent (PNormConstraintAndClip p=2) and mean-luminance + RMS-contrast matching before any comparison. Without the latter every MEI×MEI metric is contrast-confounded — this is the step most often silently absent.
Fixed state, identical and in-distribution. Same Franke 3rd/97th percentile state for both twins, and that state inside the intersection of both scans' behaviour distributions — not an extrapolation into a state the baseline twin never saw (the covariate-overlap trap).
Non-Gabor as a positive control. MEIs must be complex/non-Gabor (Walker); if they come out Gabor-like the core is under-regularized or collapsed toward the linear RF. Confirm via the MEI-vs-linear-RF contrast — this doubles as proof the twin captured V1 nonlinearity.
Init stability (Walker's ρ≈0.99 across random starts) and RF-localization at μ.
(3) Metamers
Re-evoke validity. The twin's response to the synthesized metamer correlates with the target population response, compared against the repeat-reliability ceiling — the reference-free criterion. This is the metamer confirmation.
Labeled honestly. Pixel-space inversion is the underdetermined baseline, not Cobos's VAE/flow-prior headline method; either build the prior or name the deliverable "pixel-space reconstruction (Cobos baseline)."
Multi-seed stability — underdetermined problem; show seeds converge or report the spread.
Per-scan σ/step tuning is criterion-based and identical across scans — tuned on re-evoke/SSIM, not chosen visually, and the same protocol for pre and post (not different σ that flatter the comparison).
(4) The pre/post comparison
Matching is anatomical-only. Confirm reciprocal-NN uses registration coordinates, no response/tuning-similarity term — otherwise you select against the cells DOI changed and the comparison is circular.
μ co-registration across twins before any RF-mask MEI×MEI metric; independent learned-μ fits jitter the mask and fake "spatial change."
Within-scan temporal-drift / no-drug control. Drug is perfectly confounded with scan order (n=1, no vehicle, DOI always second). Confirm a control that isolates drug from time: e.g. early/late split of each scan, showing the pre→post change exceeds within-scan drift; or a baseline-only pseudo-comparison as the null. Without it, "DOI effect" reads as "second-scan effect."
Scale-invariance discipline. Every reported comparison metric is a ratio/shape/correlation — no cross-scan amplitude, since per-scan normalization erased gain.
Behavioural null pre-specified against Franke's "state leaves spatial structure ~unchanged," and cell-wise stats framed as within-animal descriptive (n=1), not a population test.
The 2–3 most-skipped — the reviewer-rejection set
The temporal-drift / order control. The single most likely killer for a two-scan n=1 psychedelic design, and the easiest to skip because you have to build the null from within-scan splits. A Reimer/Tolias reviewer will ask "how do you know it's DOI and not scan two?" first.
Matching circularity — proving the match is position-only. Skipped because matching is upstream and "just works"; if it's functional, the entire comparison is circular.
The gamma plateau-check on this scan — your third. The frozen gammas shape the MEI/non-Gabor result, so an imported hyperparameter means the headline output rests on someone else's dataset. The archetypal built-not-verified trap.
