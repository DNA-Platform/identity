This is a rich and somewhat surprising landscape — Adobe's actual contributor infrastructure is more constrained than most people expect. Here's a comprehensive breakdown:
The Hard Truth: No Public Contributor Upload API
Adobe explicitly states there is no API for Stock Contributors — no public endpoint to upload new content, get sales data, see top sellers, or see creation dates. Requests for Contributor API access are rejected outright. This is the wall everyone hits first.
The Adobe Stock API that does exist is for customers (buyers/licensors), not suppliers. It supports searching for photos, videos, illustrations and vectors, and lets applications handle licensing of assets programmatically — but that's entirely the buyer side.
The Real Programmatic Path: SFTP
The closest thing to automation Adobe offers contributors is SFTP. Qualified accounts can use SFTP to upload file types, and when uploading large volumes of video content, SFTP is specifically recommended.
The catch: Only qualified accounts can use SFTP to upload files — if the SFTP option doesn't appear in the contributor portal, you must use the drag-and-drop method. The qualification criteria are opaque. No one seems to know exactly why certain accounts have access. It appears to be older, established accounts — contributors active since 2016 or earlier seem to have it, but the criteria have never been officially specified.
If you do have SFTP access, the server is sftp.contributor.adobestock.com on port 22. Once files are on the SFTP site, they are automatically imported by a recurring job. This means you can script uploads using standard ssh2-sftp-client in Node.js or paramiko in Python — the file delivery itself becomes fully automatable.
Metadata via SFTP works through either embedded XMP/IPTC tags in the files themselves, or through a companion CSV file. If a file doesn't have a title or any embedded keywords, Adobe Stock will automatically suggest a title and up to 25 keywords — but if you've already added titles and keywords in Photoshop, Lightroom, Bridge, or another image editor, Adobe Stock will preserve them. That XMP-embedding path is important for a code-first workflow.
The Metadata Layer: Where Coders Win
Even without upload API access, the metadata pipeline is fully automatable using standard open formats.
XMP/IPTC embedding is the key. Adobe reads dc:title, dc:description, and dc:subject (keyword array) from XMP sidecar data embedded in the file. You can write this programmatically with libraries like exiftool (command-line, wraps everything), sharp in Node.js, or pillow/pyexiftool in Python. A code-savvy contributor can generate 500 files, run them through an AI vision model to generate titles and keywords, embed the metadata programmatically, then batch-push via SFTP — with zero manual UI interaction for the upload itself.
CSV import is the other path. Adobe's contributor portal accepts CSV files to bulk-apply metadata to already-uploaded files. Contributors who upload titles, tags, and releases through CSV files have flagged a limitation: there's no way to mark content as AI-generated through CSV — that checkbox must be done manually in the portal. For non-AI content, CSV is fully scriptable.
The Ecosystem of Automation Tools
A whole category of desktop software has emerged to fill the gap Adobe left:
Xpiks — Cross-platform (Windows/Mac/Linux), it automates metadata workflows and uploads to microstocks and any server supporting FTP, SFTP, or FTPS. It automatically creates zip archives for vectors and previews and detects the best uploading mode. The primary benefit is that it lets you tag, title, describe, and do automatic uploads to all marketplaces from one interface. It has AI keywording and costs ~$35 one-time for Pro, ~$79/year for Pro+. It handles upload but not submission (you still confirm in the portal).
StockSubmitter — Completely automates the microstock workflow: filling, translating and storing metadata, uploading and submitting content to dozens of agencies simultaneously. It includes a QuickMeta tagging system and lets you track sales and approval of content. Windows-only, subscription-based.
SendStock AI — A newer desktop app that integrates metadata editor, CSV exporter, and FTP uploader in one tool. It includes a local AI model that runs entirely on your computer with no API costs, plus portfolio analytics synced from your Adobe Stock contributor account.
Auto Metadata AI / CSVNest / Adobe Contributor — A new wave of web-based tools that use OpenAI's vision API or local models to auto-generate titles, descriptions, and keywords, then export Adobe-compatible CSV files. One tool claims you can process up to 10,000 image metadata entries with approximately $10 of OpenAI credit.
Other Platforms: Shutterstock Has More
Shutterstock in 2025 expanded options for developers by launching self-serve API subscription plans that make it easier to preview and license images within applications at scale. Their API is far more open than Adobe's, with an official JavaScript SDK. That said, like Adobe, the public Shutterstock API is also oriented toward buyers, not contributors submitting content.
In a major industry development, Getty Images announced a planned merger with Shutterstock in early 2025, creating what many observers expect to become an even more dominant force in licensed imagery. This consolidation matters for strategy decisions about where to focus your distribution effort.
What a Coder-Contributor Automation Stack Looks Like at Scale
Putting this all together, here's the actual architecture a technical microstock contributor would build:
Generation pipeline — AI image generation (Midjourney, SD, Firefly) or procedural generation (which is exactly what DNA Patternity could become)
Quality/compliance filter — automated checks for min resolution (4MP), anatomical errors in AI art, restricted brand names in metadata
AI metadata generation — vision model (GPT-4o, Gemini Vision, or a local model) generates title, description, and 25–50 ranked keywords per image, optimized per platform's SEO rules
XMP embedding — exiftool or equivalent writes the metadata directly into the file headers
Batch SFTP push — Node/Python script deposits files to sftp.contributor.adobestock.com and equivalent endpoints for Shutterstock, Dreamstime, Pond5, Depositphotos simultaneously
CSV fallback — for platforms without SFTP, export a companion CSV and automate browser submission using Playwright or Puppeteer
The single biggest remaining bottleneck is the final submission click on Adobe's side — once files are uploaded and indexed, you still need to confirm each batch through the UI (or let tools like StockSubmitter handle it via browser automation). The AI checkbox for generative content is an additional manual step with no current CSV workaround.
Relevance to DNA Patternity

Procedurally generated vector patterns like what you're building could be an ideal fit for the stock market — patterns, backgrounds, and seamless tiles are consistently high-demand categories. Your WebAssembly-accelerated generation pipeline could produce hundreds of unique, mathematically sound variations from a single algorithm, each with programmatically derived metadata describing the pattern properties. What StockSubmitter Actually Is Under the Hood

The Microstock+ FTP Path — The Closest Thing
M+ will recognize all the metadata and statuses saved in StockSubmitter. For now you can upload directly to M+ using its web uploader or FTP. This is the crack in the wall. Microstock+ (the cloud sibling of StockSubmitter) accepts files via FTP — meaning you can script a push to their ingest endpoint with XMP metadata embedded in the files, and their servers handle submission to all agencies from there.

If SFTP is available:
Claude Code uses ssh2-sftp-client (Node) or paramiko (Python) to push files directly to sftp.contributor.adobestock.com. Files land in the contributor portal's "Uploaded Files" tab automatically. XMP metadata embedded in the files pre-populates title and keywords. The only remaining manual step is clicking "Submit for Review" — which is a single targeted Playwright script that logs in, selects all pending files, and clicks submit. Fully headless, fully scriptable, Claude Code owns the entire pipeline.
If SFTP is not available:
You're in StockSubmitter territory — browser automation all the way. The contributor portal upload is a drag-and-drop web UI, which means Playwright driving a real browser session: navigate to contributor.stock.adobe.com, authenticate, trigger the file input element, feed it the generated files, wait for processing, fill metadata fields, click submit. This is exactly what StockSubmitter does internally. It's more fragile (Adobe can change the DOM and break it) but entirely doable. The metadata pre-population via XMP still helps because the portal reads embedded tags and auto-fills fields, reducing how much the browser script needs to type.
The practical difference:
SFTP path is stable, fast, and Claude Code–native. The browser path needs maintenance when Adobe updates their UI, but it's the same class of problem StockSubmitter has been solving for 10+ years — meaning it's a solved problem, just one you'd be owning yourself rather than paying them to maintain.
