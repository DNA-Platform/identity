What a message of Claude's is made of beyond what was said: an action and its result, an artifact and an attachment, each a writing of its own that the importer writes and the page draws as Claude's application does. They specialize what my reference manual says a conversation is in general, a book of messages, each by a speaker at a time, with its participants on the cover; the conversations themselves are filed under Our Conversations.
The Action and the Result
What Claude does in a message that is not said, a search, a fetch, a run of code, a read of a file, as a writing of its own; and the result, what came back, a writing the import counts and leaves out.
Done, and what came back
A message of Claude's holds more than prose. Where he searched the web, fetched a page, ran code or read a file, the message holds an action, one line saying what was done in plain words. What came back is a result, and the import does not write it: a fetched page or a run's output is the machine's and not the conversation's, it was what filled a page when it was kept, and the export still holds it, so the import counts the results it leaves out and a result that matters is kept by hand. Neither is a paragraph of what was said, so neither is a paragraph wearing a mark: each is a writing of its own, a paragraph in shape and not in meaning, which the page can fold, show as the application does, or count. They are Claude's, so they stand in this manual and not in the library's, where a message is said to be a speaker, a time and what was said.

The Artifact and the Attachment
A file Claude made in a message and a file given to him in one, each a figure where it entered the conversation, showing the file that stands beside the chapter.
Made, and given
An artifact is a file Claude made as he answered, a document, a page, a program, and went on changing as the conversation went on. The conversation's chapter holds an artifact where each version was made: a figure, as a code listing is, that names the version's file beside the chapter and shows it under one line saying what was done; every version stands beside the chapter and the last under its own name, each listed at the chapter's foot as the listing shows files. An attachment is a file given to Claude in a message, pasted or uploaded: a figure the same way, naming the file when the export carried its text, which it does for what was pasted and not for what was uploaded, and then the line alone. Both are writings of their own and not paragraphs of what was said, as an action is; each is a figure, since what it shows is the file.

The Project
The project a conversation with Claude was held in, said on the conversation's cover as a fact of Claude's, and the conversation with Claude that draws it.
Held in a project
In the application a conversation is held in a project, or in none, and the project holds the files Claude reads while it goes. That is a fact about Claude's conversations and not about conversations in general, so it is said here and not in the library's manual: a project is an annotation of a conversation's cover, as the author and the subject are, holding the project book's name and standing a reference to it, and the cover writes it with the form that says the project catalogues the conversation besides, so the project book's table answers it. It is not a topic. A topic is what a conversation, or a part of one, is about, and the same conversation may turn to several; the project is where it was held, one at most, whatever it turned to.
A conversation with Claude is the library's conversation specialized here: it answers its project, and draws a project line beside its byline, a word said to be a label and the project's name leading to its book, the way back from a conversation to its project. The project book itself is a project manual, the files as spreads and the conversations as entries.

The Page
How a conversation with Claude is shown on its page: the form the application itself gives a conversation, read off the application, and the browser this library keeps open to read it.
The form the application gives
A conversation is shown as the application shows it, since that is the form its reader knows, and annotations and flourishes come on that base. The form is read off the application's own page in a browser, element by element and style by style, and written as the theme of a conversation with Claude, so that the message, the speaker, the time, the action, the artifact and the attachment are dressed as the application dresses them.
The browser this library keeps open
The application's pages need my sign-in, so the library opens a browser of its own, with a profile that keeps the sign-in once I have logged in there, and leaves it open with a port a later command attaches to: one command opens it on the application and keeps it open, and the others list its tabs, open a page, say what an element says, print its tree or its computed styles, photograph it, scroll to an element, hover or press one and say what changed, or name what runs past the right edge at a width. The file beside this chapter is that tool, run from the repository's root. It is an essential tool of developing this library and is opened at the start of a session, in the background, with the command said there: node .me/.claude/.manual/4-the-page~browser.mjs open; it stays open as a resource until I close it, and I log in there once. It is a browser and not an interface for calls: it keeps one tab per place, the application, the workbench, the built site, a file, and goes to an address in the tab it has rather than opening another, and what it leaves open is closed with its close command.
