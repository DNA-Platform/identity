The Real Issue: Template's Bond Backing Field
When __createComponent() runs:

The formula is initialized on the template, not the instance. This means:
Template's formula.init() creates bonds with backing fields
When the bond for _condition is created, it captures the current value as backingField
The question is: What's the value of _condition on the template at this moment?
The Class Field Initialization Timing Problem
In JavaScript/TypeScript, class field initializers run during construction:
typescript
class $When extends $Chemical {
    protected _condition = true;  // This runs DURING constructor
    
    constructor() {
        super();  // $Chemical constructor runs first
        // _condition = true runs HERE, after super()
        this.$action = this.undefined;
    }
}
But __createComponent() might be called on a template that hasn't fully constructed yet, or the bond might be looking at the prototype rather than the instance.
The Smoking Gun: First Load vs Second Load
The key observation:
First load: Bond captures wrong value (undefined/false)
Second load: Bond has correct value (true)
This suggests the template's _condition value changes between first and second use. Perhaps:
First time: Template created, bonds initialized before _condition = true runs
Template gets used, _condition gets set to true
Second time: Template already exists with _condition = true, bonds see correct value

The Culprit: Template State Persistence
Looking at the Chemistry architecture:
typescript

        return this[$type][$template] as any;
    }

Templates are stored statically on the class. When you navigate away and back:
First visit: Fresh template created, shouldLoad = false (Test 2), _condition = undefined? (Test 1)
User interacts: Changes state on template or instance
Navigate away: Template persists (it's static!)
Navigate back: Same template with modified state!
Test 1: _condition now properly true
Test 2: shouldLoad still true from previous interaction!
The Evidence
Test 2's $IfConditionalLoader:
typescript
export class $IfConditionalLoader extends $Chemical {

If you clicked the toggle button before navigating away, shouldLoad remains true when you come back!
The Core Problem
Templates are being mutated and the mutations persist across navigations. The template should be immutable, but:
Methods like $toggleCondition() modify the template directly
Bonds might be caching state on the template
The template's formula/bonds persist across component instances
The Fix
Templates need to be truly immutable. Options:
Option 1: Reset template state on navigation

// When creating a new component instance
if (this.__template && this.__isTemplate) {

// Ensure instances, not templates, hold state
private createChemical(parent?: $Chemical): T {

    // Copy ALL field values to instance so template isn't mutated
    Object.keys(this.$template).forEach(key => {
        if (!key.startsWith('$')) {
            chemical[key] = this.$template[key];
        }
    });
}
Option 3: Create fresh templates

// Don't reuse templates across navigations
static [$template]: $Chemical;  // Make this instance-specific, not static
