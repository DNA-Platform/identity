The Recursive Bond Formation Pattern in $Chemistry
The bond formation system in $Chemistry represents a sophisticated marriage of prototypal inheritance and recursive initialization that fundamentally reimagines how properties propagate through an object hierarchy. At its core, this pattern exploits a critical insight: by recursively initializing templates before instances, we create a guarantee that when any chemical examines its own properties, its predecessor's molecular structure is already complete. This temporal ordering eliminates the need for complex chain traversal and enables a simple, elegant comparison between a chemical's own properties and its template's existing bonds.
The recursion begins with a fundamental observation about JavaScript's prototype chain: every object has own properties and inherited properties. But rather than traversing the entire prototype chain to discover all properties, the bond system only examines Object.getOwnPropertyNames() for each chemical. This is possible because of the recursive guarantee - when a chemical reactivates, its template has already reactivated, which means the template's molecule already contains bonds for all properties it should have. The chemical only needs to ask: "For each of my own properties, does my template's molecule have a bond for this property?"
This creates a beautiful symmetry with the $Bond.double() and $Bond.create() methods. When a property exists in both the chemical and its template, we call double() - this creates a bond that shares certain characteristics with the template's bond while maintaining its own identity. The double bond represents the relationship between template and instance, where the instance's property shadows the template's but maintains a connection to it. When a property exists only in the current chemical, we call create() - this forms an entirely new bond with no predecessor, representing a property that this level of the hierarchy introduces.
The template/instance duality becomes crucial here. Templates are the static prototypes that hold the "shape" of a class - they're created once and shared. Instances are the living chemicals that actually participate in reactions. When an instance reactivates, it uses its class's template as the predecessor. When a template reactivates (in the case of subclass templates), it uses its prototype's template as the predecessor. This creates two parallel inheritance chains - one for templates, one for instances - that mirror JavaScript's own prototype chain but with additional semantic meaning.
The halting condition for this recursion is elegant: the $Chemical prototype itself. When we reach $Chemical.prototype, we know we've reached the root of the inheritance tree. There's no template above this - it IS the ultimate template. Its properties are always created fresh with $Bond.create() because there's no predecessor to double from. This mirrors how Object.prototype sits at the top of JavaScript's prototype chain, but with the added semantic that $Chemical.prototype defines the base properties that every chemical must have.
The "reactivate" metaphor captures something essential about this process. A molecule isn't catalyzed - it doesn't need an external catalyst.     if (first) viewSymbol = this.viewSymbol;

    const element = node as React.ReactElement<any>;
    const props = element.props;
    const type = element.type;

    let $element = element;
    let $props = props;

        $props = { ...$type.$chemical[$lastProps], key: first ? viewSymbol : $type.$chemical[$symbol] };
        needsViewSymbol = false;  // We've handled the key

            $type = $type.$bind();
            for (const prop in props) {
                if (prop !== 'key')  // Don't overwrite the key we just set
                    $props[prop] = props[prop];
            }
            if (!first)
                $props.key = $type.$chemical[$symbol];
        }
    }

Exactly! You've identified the issue. When Chemistry creates instances from templates using Object.create(template), the _type property is on the prototype (the template), not on the instance itself.
The problem is that when you create bound instances via $bind(), they inherit _type through the prototype chain, but if something accesses this._type directly, it gets the template's value.
