Here's what the research found, per platform:
Alamy — FTP upload (EPS + matching JPEG to Vectors/ folder), metadata via IPTC embedded in the JPEG before upload. Illustrator's IPTC Description maps to their caption field, keywords map to tags. The only wrinkle: QC is batch-level — if one image fails, the whole batch fails, so small batches (same discipline as Adobe). They don't accept any AI-generated images, which is the main concern for DNA Patternity assets — framing matters. Supertags (10 out of 50 max) require Playwright on the Image Manager since they can't be set via IPTC.
Shutterstock — FTPS to ftp.shutterstock.com, credentials are in the contributor portal Upload page. Metadata goes in via a CSV uploaded on the Submit content page (not via FTPS) — this is the key two-step: FTP the files, then Playwright to hit the Submit portal, upload the CSV, and click Submit. CSV columns are Filename, Description, Keywords, Categories, Illustration, Mature Content, Editorial. Files are auto-deleted if not submitted within 21 days.
Spoonflower — No API integration available. Full Playwright dependency. Accepts PNG and JPEG, up to 10 files at a time for logged-in accounts, 40MB max, sRGB only. The Design Library List View supports batch metadata edits which is the efficient Playwright target.
The doc is stored at docs/metadata/RECIPE_alamy_shutterstock_spoonflower.md and is structured as a CC handoff spec.

Good questions — a few significant findings here.
Alamy — yes, identical to iStock. EPS + matching JPEG pair, same filename, JPEG carries the IPTC. The only difference is Alamy's FTP folder is Vectors/ and their QC is batch-level. The file prep pipeline you already have for iStock works as-is.
Shutterstock — two important things:
1. No .AI files. Shutterstock only accepts EPS, compatible with Illustrator 8 or 10. So your .AI files can't go there directly — they'd need to be saved out as EPS first (same export you do for iStock/Alamy anyway).
2. Embedded metadata does work — and you no longer need a JPEG at all. Shutterstock now automatically generates the JPEG preview from your EPS on ingest, so you only need to upload the EPS. They also read descriptions and keywords embedded in the EPS file itself. This means if you embed IPTC/XMP into the EPS via exiftool before upload, the Submit portal will pre-populate with your metadata — CSV becomes optional, not required.
3. On "most premium" format — there's no premium tier by file type. They accept JPEG and TIFF for raster, but all images are converted to JPEG on approval anyway. For vectors, EPS is the only option. Premium = resolution and content quality, not format.
One more flag: Shutterstock does not allow AI-generated content from contributors, even though they have their own AI generator. Same policy as Alamy. Both platforms are closed to contributor-submitted AI content.

The 150-char caption limit is the meaningful difference. iStock's title field is longer. If you're generating captions programmatically you need platform-specific truncation.
The supertag system is also unique to Alamy — not a concept iStock has. They can't be set via IPTC, so if you want them you need the Image Manager (Playwright). For an automated pipeline you'd skip supertags initially and do a periodic cleanup pass.
Shutterstock — metadata fields
FieldiStock/Getty ESPShutterstock
Title/DescriptionSeparate title + description fieldsSingle description/title field, max 200 characters
KeywordsGIV controlled vocabularyFree-text, minimum 7, maximum 50
CategoriesRequired1 required, 2nd optional — from Shutterstock's own taxonomy
Keyword spammingNot specifiedActively enforced — no repeated root words (e.g. "seamless pattern blue, seamless pattern green" is flagged as spam)
Editorial flagSeparate fieldOptional column in CSV
Illustration flagAuto-detectedCSV column Illustration: Yes/No — must be set explicitly for JPEGs
The category codes are the biggest pipeline difference. Shutterstock uses its own numeric taxonomy — you can't reuse Getty's GIV categories. You'd need a lookup table mapping your asset types to Shutterstock category IDs, or hardcode a default (e.g. Backgrounds/Textures and Abstract for patterns). The category list is in their docs.
The keyword spam rule is also operationally important for pattern assets — "seamless pattern blue, seamless pattern geometric" would be flagged. Keywords should be individual concepts, not compound phrases with a repeated stem.
So: not identical. The file delivery model is similar (EPS + metadata), but caption length, category system, and keyword constraints differ enough that metadata.js needs platform-specific output branches for each.

On the open commons question specifically: there is no disclosure field on either platform, and no submission mechanism for it. Both platforms ask contributors to certify IP ownership of submitted content — what matters is that the output is original work yours to license. Using open-license or public domain data as input to your own generative pipeline is fine. The output produced by your code is your IP.
The one thing to keep separate is Shutterstock's data licensing toggle — that's their own program for selling contributor content as AI training data, nothing to do with your source inputs. Ana sets it once in account settings and it never touches the submission pipeline.
The main actionable differences CC needs to implement are the 150-char caption truncation for Alamy, the Shutterstock-specific category ID lookup, and a keyword spam filter that strips repeated root words — that last one is a real rejection risk for pattern assets specifically, since Shutterstock explicitly uses "seamless pattern blue, seamless pattern green" as their example of what not to do.
