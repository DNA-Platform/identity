14:36 UTC, 24 January 2025
Here's how to use BridgeTalk in ExtendScript for Illustrator:
javascript
// Send message to Photoshop
var bt = new BridgeTalk();
bt.target = "photoshop";
bt.body = "alert('Hello from Illustrator')";
bt.send();

// Handle response
bt.onResult = function(response) {
    alert(response.body);
};

// Check if application is running
var isRunning = BridgeTalk.isRunning("photoshop");

// Get available applications
var apps = BridgeTalk.getSpecifiers();

// Wait for response
bt.timeout = 30; // seconds
bt.onTimeout = function() {
    alert("Request timed out");
};
Key specifications:
Target applications use lowercase names: "photoshop", "illustrator", "indesign"
Body contains JavaScript code as string
Response handling is asynchronous
Timeout defaults to 10 seconds
Can check app status with isRunning() before sending
Error handling via onError callback
Let me know if you need specific implementation examples.

BridgeTalk executes JavaScript code that's passed as a string in the body property. It doesn't only run files - it can execute any valid ExtendScript code. The receiving application (Illustrator in this case) interprets and runs this code in its scripting engine.
Example of different ways to send commands:
javascript
// Direct command
bt.body = "app.documents.add()";

// Multiple commands
bt.body = "app.documents.add(); \
           var doc = app.activeDocument; \
           doc.artboards[0].name = 'New Board';";

// Can also run file content
var scriptContent = File("path/to/script.jsx").read();
bt.body = scriptContent;

The primary purpose of BridgeTalk is actually inter-application communication and script execution in Adobe applications. It can handle both direct code execution and script file execution effectively.
For running external script files, here are the standard approaches:
javascript
// Method 1: Read and execute script file
var scriptFile = File("path/to/script.jsx");
var bt = new BridgeTalk();
bt.target = "illustrator";
bt.body = scriptFile.read();
bt.send();

// Method 2: Use $.evalFile
bt.body = '$.evalFile("path/to/script.jsx")';
bt.send();
The second method using $.evalFile is often preferred when running script files as it maintains proper file paths and scope. This approach is particularly useful when your script needs to reference external files or resources.

Yes, BridgeTalk offers both synchronous and asynchronous execution options for managing UI responsiveness.
For asynchronous execution (non-blocking):
javascript
var bt = new BridgeTalk();
bt.target = "illustrator";
bt.body = "app.documents.add()";
bt.send();
// Code here runs immediately without waiting

// Optional callback when command completes
bt.onResult = function(response) {
    // Handle completion
};
For synchronous execution (blocking):
javascript
var bt = new BridgeTalk();
bt.target = "illustrator";
bt.body = "app.documents.add()";
bt.send(true); // true parameter forces synchronous execution
// Code here waits for completion
The asynchronous approach is generally preferred for maintaining UI responsiveness. You can chain commands using the onResult callback if you need sequential execution while keeping the UI responsive:
javascript
bt.onResult = function(response) {
    // Send next command here
    var nextBt = new BridgeTalk();
    nextBt.target = "illustrator";
    nextBt.body = "// next command";
    nextBt.send();
};

That's a perceptive question about BridgeTalk's behavior within the same application. When sending commands from Illustrator to Illustrator, BridgeTalk actually creates a separate thread for execution. This means that while you can technically send a "blocking" command using send(true), it won't behave the same way as synchronous code executed directly in your script.
The primary purpose of BridgeTalk is inter-application communication, so using it for same-application execution can be considered a non-standard usage. For managing UI responsiveness within Illustrator, there are more conventional approaches:
javascript
// Standard approach for non-blocking operations
app.scheduleTask("app.documents.add()", 100, false);

// Or using setTimeout
$.sleep(0); // Allows UI to update
If you need to ensure sequential execution while maintaining UI responsiveness, I recommend using app.scheduleTask() or carefully placed $.sleep() calls rather than relying on BridgeTalk for same-application communication. Would you like me to explain more about these alternative approaches?
