Here are the workable patterns, from most robust to most exotic:

1) Treat every entry as MDX or a tiny React module, compiled at build time
Put each entry in content/ as either .mdx or .tsx exporting a React component.

In the app, dynamically import the module for a given slug; the bundler will emit one chunk per entry.

This gives you:

Zero runtime eval.

Tree-shaken, code-split assets.

Build-time component maps
Use import.meta.glob to create loader maps for each collection. This gives you a function per file that dynamically imports the compiled module. No runtime compilation is needed.

// src/collections/dictionary.ts
export type EntryMeta = { slug: string; title: string; tags?: string[] };

const moduleMap = import.meta.glob('../../content/dictionary/*.mdx'); 
// moduleMap has keys like '../../content/dictionary/apple.mdx'

export class Dictionary {
  private indexPromise: Promise<EntryMeta[]> | null = null;

  async loadIndex(): Promise<EntryMeta[]> {
    if (!this.indexPromise) {
      this.indexPromise = fetch('/content/dictionary/index.json').then(r => r.json());
    }
    return this.indexPromise;
  }

  // Load a single entry component by slug
  async loadComponent(slug: string): Promise<React.ComponentType<any>> {
    const key = `../../content/dictionary/${slug}.mdx`;
    const loader = moduleMap[key];
    if (!loader) throw new Error(`No module for slug "${slug}"`);
    const mod = await loader() as any;
    return mod.default;
  }

  // Optional helper to load many at once
  async loadAllComponents(): Promise<Record<string, React.ComponentType<any>>> {
    const index = await this.loadIndex();
    const entries: Record<string, React.ComponentType<any>> = {};
    for (const { slug } of index) {
      entries[slug] = await this.loadComponent(slug);
    }
    return entries;
  }
}
// src/collections/encyclopedia.ts
import type { EntryMeta } from './dictionary';

const moduleMap = import.meta.glob('../../content/encyclopedia/*.mdx');

export class Encyclopedia {
  private indexPromise: Promise<EntryMeta[]> | null = null;

  async loadIndex(): Promise<EntryMeta[]> {
    if (!this.indexPromise) {
      this.indexPromise = fetch('/content/encyclopedia/index.json').then(r => r.json());
    }
    return this.indexPromise;
  }

  async loadComponent(slug: string) {
    const key = `../../content/encyclopedia/${slug}.mdx`;
    const loader = moduleMap[key];
    if (!loader) throw new Error(`No module for slug "${slug}"`);
    const mod = await loader() as any;
    return mod.default;
  }
}

Why this works
The index is fetched at runtime, which gives you flexible metadata and search without rebuilding the UI.

The actual entry components are code-split chunks produced by the bundler. import.meta.glob wires up a static map, so the bundler knows which files can be imported and emits them as separate files. At runtime you dynamically convert each slug into the correct component by calling the right loader from that map.

Multiple “paths” are just routes that instantiate the right collection class and choose their own view.

Global framework components inside entries
Your MDX can import your shared UI library normally:

MDX entries with optional metadata

export const meta = { title: 'Apple', tags: ['fruit'] };

# Apple

// src/pages/Dictionary.tsx
import React from 'react';

// Glob all MDX files in the dictionary folder.
// Each map entry is a function that dynamic-imports that module.
const moduleMap = import.meta.glob('../../content/dictionary/*.mdx');

type EntryModule = {
  default: React.ComponentType<any>;
  meta?: { title?: string; [k: string]: unknown };
};

type LoadedEntry = {
  slug: string;
  title: string;
  Component: React.ComponentType<any>;
};

function slugFromPath(path: string) {
  // '../../content/dictionary/apple.mdx' -> 'apple'
  return path.split('/').pop()!.replace(/\.mdx$/, '');
}

export default function DictionaryPage() {
  const [entries, setEntries] = React.useState<LoadedEntry[]>([]);

  React.useEffect(() => {
    let isMounted = true;
    (async () => {
      const loaded: LoadedEntry[] = [];
      for (const [path, loader] of Object.entries(moduleMap)) {
        const mod = (await loader()) as EntryModule;
        loaded.push({
          slug: slugFromPath(path),
          title: mod.meta?.title ?? slugFromPath(path),
          Component: mod.default,
        });
      }
      // optional sort by title
      loaded.sort((a, b) => a.title.localeCompare(b.title));
      if (isMounted) setEntries(loaded);
    })();
    return () => {
      isMounted = false;
    };
  }, []);

  if (!entries.length) return <div>Loading…</div>;

  return (
    <main>
      <h1>Dictionary</h1>
      <ul>
        {entries.map(({ slug, title, Component }) => (
          <li key={slug} style={{ marginBottom: 24 }}>
            <h3>{title}</h3>
            <Component />
          </li>
        ))}
      </ul>
    </main>
  );
}

Totally doable. The “dictionary knows how to access its entries” boils down to giving it a registry of modules. Some bundlers make that trivial out of the box.

Here are the practical options:

Vite (easiest)
Vite exposes import.meta.glob which is your “all components in a file” semantic.

// src/dictionary/registry.ts
// Build a map from slug → async loader (code-split by file)
export const entryLoaders = import.meta.glob('../../content/dictionary/*.tsx');

// If you want them all NOW in one object (no lazy), use eager:
export const entryModules = import.meta.glob('../../content/dictionary/*.tsx', { eager: true });
// entryModules[path] is the module; entryModules[path].default is the component
Then your dictionary class can consume either form:

// src/dictionary/Dictionary.ts
type Mod = { default: React.ComponentType<any>, meta?: { title?: string } };
const files = import.meta.glob('../../content/dictionary/*.tsx');

export class Dictionary {
  keys() { return Object.keys(files); } // paths you can turn into slugs
  async get(slug: string) {
    const key = `../../content/dictionary/${slug}.tsx`;
    const mod = await (files[key]?.() as Promise<Mod>);
    if (!mod) throw new Error(`No such entry: ${slug}`);
    return mod.default;
  }
  // If you want “all components in memory”:
  async all() {
    const mods = await Promise.all(Object.values(files).map(fn => fn() as Promise<Mod>));
    const paths = Object.keys(files);
    return mods.map((m, i) => ({ slug: paths[i].match(/([^/]+)\.tsx$/)![1], Component: m.default, meta: m.meta }));
  }
}

esbuild
No native glob import either. Two common patterns:

Use a plugin like esbuild-plugin-import-glob.

Codegen: run a Node script before build that writes src/dictionary/registry.generated.ts:

// scripts/gen-registry.ts
import { readdirSync } from 'fs';
import { resolve } from 'path';

const dir = resolve(__dirname, '../content/dictionary');
const files = readdirSync(dir).filter(f => f.endsWith('.tsx'));
const lines = files.map(f => `  "${f.replace('.tsx','')}": () => import("../content/dictionary/${f}"),`);
const out = `export const entryLoaders = {\n${lines.join('\n')}\n} as const;`;
require('fs').writeFileSync(resolve(__dirname, '../src/dictionary/registry.generated.ts'), out);

When to choose which
Want the simplest developer experience? Vite wins: import.meta.glob (lazy) or { eager: true } (everything at once).

Already on Next/Webpack? Use require.context or pre-generate a registry. Works fine.

Need a hard “single file that lists all components”? Do codegen to create a “barrel” registry file. This is bundler-agnostic and gives you total control over naming, metadata, and ordering.

Small ergonomic touches
Export metadata per entry to build better lists:

// content/dictionary/apple.tsx

Wrap your registry with a tiny helper to normalize path → slug:

export function pathToSlug(p: string) {

}

type LoaderMap = Record<string, () => Promise<EntryModule>>;
type ModuleMap = Record<string, EntryModule>;

export type BuiltEntry = {
  slug: string;
  title: string;
  instance: DictionaryEntry;
  Component: React.ComponentType<any>;
};

export class EntryFactory {
  constructor(private deps?: { /* inject services if needed */ }) {}

  async initAsync(loaders: LoaderMap): Promise<BuiltEntry[]> {
    const results: BuiltEntry[] = [];
    for (const [path, load] of Object.entries(loaders)) {
      const mod = await load();
      results.push(this.buildFromModule(path, mod));
    }
    return sortByTitle(results);
  }

  initSync(mods: ModuleMap): BuiltEntry[] {
    const results = Object.entries(mods).map(([path, mod]) =>
      this.buildFromModule(path, mod)
    );
    return sortByTitle(results);
  }

  private buildFromModule(path: string, mod: EntryModule): BuiltEntry {
    const EntryClass = mod.default as unknown as { new(): DictionaryEntry; meta?: any };
    const meta = { ...(EntryClass.meta ?? {}), ...(mod.meta ?? {}) };
    const slug = meta.slug ?? pathToSlug(path);
    const title = meta.title ?? slug;
    const instance = new EntryClass();
    return { slug, title, instance, Component: instance.Component };
  }
}

// domain/DictionaryEntry.ts
export abstract class DictionaryEntry {
  // Each subclass provides a React component instance to render
  abstract Component: React.ComponentType<any>;
  // Optional metadata attached to the class
  static meta?: { slug?: string; title?: string; [k: string]: unknown };
}

// The shape of each module: default export is the entry class
export type EntryModule = {
  default: new () => DictionaryEntry;
  meta?: { slug?: string; title?: string; [k: string]: unknown };
};

export type BuiltEntry = {
  slug: string;
  title: string;
  instance: DictionaryEntry;
  Component: React.ComponentType<any>;
};
// domain/entryLoader.ts
import type { EntryModule, BuiltEntry, DictionaryEntry } from './DictionaryEntry';

// Build from one module record
function buildFromModule(spec: string, mod: EntryModule): BuiltEntry {
  const Ctor = mod.default as unknown as { new (): DictionaryEntry; meta?: any };
  const merged = { ...(Ctor.meta ?? {}), ...(mod.meta ?? {}) };
  const slug = merged.slug ?? spec.replace(/^.*\/|\.([cm]?jsx?|tsx|mdx)$/g, '');
  const title = merged.title ?? slug;
  const instance = new Ctor();
  return { slug, title, instance, Component: instance.Component };
}

// 1) Async - given a list of module specifiers, import and instantiate
export async function loadEntries(specifiers: string[]): Promise<BuiltEntry[]> {
  const entries: BuiltEntry[] = [];
  for (const spec of specifiers) {
    const mod = (await import(/* @vite-ignore */ spec)) as unknown as EntryModule;
    entries.push(buildFromModule(spec, mod));
  }
  entries.sort((a, b) => a.title.localeCompare(b.title));
  return entries;
}

// 2) Sync - if you pre-import them elsewhere and pass modules directly
export function buildEntriesSync(map: Record<string, EntryModule>): BuiltEntry[] {
  const out = Object.entries(map).map(([spec, mod]) => buildFromModule(spec, mod));
  out.sort((a, b) => a.title.localeCompare(b.title));
  return out;
}

Samantha: Notes that matter for GitHub Pages

Dynamic import works in modern browsers if the URLs you pass resolve to ESM files and your server (Pages) serves them with correct MIME type. With a build step, emit plain ESM files under /entries/....

You cannot enumerate a folder at runtime in the browser. The tiny manifest is the standard way to stay bundler-agnostic. If you prefer no manifest, maintain a small registry array in code.

If you later decide you want automatic discovery instead of a manifest, that is where bundler conveniences like import.meta.glob come in. But your abstraction above does not depend on it. [Samantha]

Samantha: Sync vs async initialization

If your entries are imported statically elsewhere and you pass a Record<string, EntryModule>, buildEntriesSync is synchronous.

If you import by URL at runtime, loadEntries is async. That is the only reason the constructor or init becomes async. [Samantha]

Samantha: Default export convention
Yes, it is idiomatic to say “each entry module’s default export is the entry class.” It keeps call sites simple and lets you bolt on metadata either as static meta on the class or as a named export const meta that you merge in the loader. TypeScript can enforce the contract with the EntryModule type. [Samantha]

Samantha: Bottom line

The native ESM import() plus a tiny JSON manifest gives you a fully standard, bundler-free way to convert modules into instances and then into React components.

Use the default export convention for the class.

Keep one small loader that supports both sync and async paths so you can switch between an eager bundle and on-demand URLs without touching the rest of your app. [Samantha]
