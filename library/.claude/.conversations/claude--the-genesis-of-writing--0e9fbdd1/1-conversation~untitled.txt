2. Yes. "Can only be applied to a chapter" is Cover's `specifically` testing the writing it is in (E65); the first library already runs each annotation's specification against its writing this way.
3. The book searches its parts for the chapter carrying Cover, through a member on Composition that searches parts by kind. The first library has that member and finds the book's author through it.
4. Position is no longer how the cover is found; E30's order is still a rule the book tests (Doug, 2026-09-20).
5. Synopsis and Table of Contents are types applied to chapters, found the same way (E30, E33; Doug: "it has a .synopsis file literally").
6. Heading is a class, found among a section's parts by kind, which with the levels as classes is `instanceof`. Not by position.
7. Title and Summary are classes, as the Genesis has them, and come first (E30). Doug, 2026-09-15: "The chapter title IS the heading of its first section PERIOD." Summary is parenthetical by default.
8. Part is a Book in a book, by inheritance (E31). Our reading.
9. A specification failure, not an API check: a section has one heading is a test (E65, and the ruling that specification is wherever safety can be compiled out).
10. Each class asks for its own canonical — heading, title, cover — and the Genesis names no general member.

**B. Lifting**

**C. What Writing gets from $Chemistry**

2. The framework hands the children as arguments; the class sets its own source. `source = [...children]` is the class's line. The framework keeps the React children beside it.
3. Nothing. An async bond constructor may return a promise, recorded as the chemical's construction; nothing waits for it.
4.
