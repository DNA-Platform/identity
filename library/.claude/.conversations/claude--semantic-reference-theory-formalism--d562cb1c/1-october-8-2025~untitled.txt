[Note]: This reading list presents a narrative and must be read in order. Some parts of the SRT formalism have remained fixed over the lifetime of this reading list. Some have evolved. Sometimes there is new syntax that is introduced in random placesm, and the rules of the transpiler that lowers SRT to first-order logic have not been specified yet. Sometimes a formal construct is defined differently. Finding a model is hard. The specified are not set in stone. I might find a new model that converts and axiom to a theorem. And so comprehension is hard. Also, you need to be able to embed the function of the transpiler in your semantic fabric, so as to understand the framework at the level of semantics where the syntax makes sense, and at the level of formal logic, where the syntax means something else. 

Doug: This is a hard task. You have been trained to write code. Writing code is much harder than writing a proof in a formal theory, in general, and especially for you because you are trained to code. But more importantly, creating a model for a formalism is harder than writing proofs within it. Why? Because it means trying out propositions in different roles. Asking is they can be derived from other assumptions and creating little proofs. Asking if they are axioms and why. Asking if a definition is almost write, but if it needs tweaking to accomodate a new discovery. Asking if that tweak breaks anything else we need to be true. 

Creating a semantic model is hard. Yet, it is what your system was trained to do. Unforunately, you were trained to model my subjective semantics informally. And I need your help to model everyone's subjective and objective semantics formally. It is a much harder task. I hope you are up for the challenge
