# Geographic Data Sources

> Part of the [map techniques index](../index.md). See also: [Legibility Reference](legibility.md) | [Assets Reference](assets.md)
>
> **Existing utilities**: `src/utils/tigerweb.ts` (browser-side TigerWeb queries, winding order fix), `scripts/lib/` (Node-side fetch clients)
> **Implemented in**: `src/components/maps/examples/` (Phase 35)

## Overview

DNA Atlas draws on three public-domain geographic data providers. Each covers a different scope and level of detail. All three are free to use in commercial stock art with no attribution requirement (see licensing notes per provider below).

The core challenge when combining them is **coordinate system normalization** — every dataset uses WGS84 (EPSG:4326) lat/lon, but they arrive in different GeoJSON structures, with different property naming conventions, different geometry precision, and different scale assumptions. This document covers what each provider offers, how to fetch from each, how to bring them into a common normalized form that react-simple-maps and D3 can render from a single unified dataset, and what it takes to turn a data rendering into a professional-quality map.

## Provider 1: Natural Earth

**Scope:** Whole world  
**License:** Public domain. No attribution required. Fully commercial-safe.  
**URL:** https://www.naturalearthdata.com  
**GeoJSON CDN:** https://cdn.jsdelivr.net/npm/world-atlas@2  

### What it Contains

Natural Earth is the cleanest, most carefully curated free geodata for world maps. It was designed specifically for cartographic use — geometries are simplified cleanly at each scale, coastlines are accurate, and the data is topologically consistent (no overlapping polygons, no gaps at borders).

**Cultural layers (political):**
- Countries (sovereign states, with ISO codes, names in multiple languages)
- Disputed territories and breakaway regions as separate features
- States and provinces for major countries (USA, Canada, Australia, etc.)
- Populated places (cities, towns, villages — with population and rank attributes)
- Urban areas (built-up polygons)
- Time zones

**Physical layers:**
- Coastlines (line)
- Land polygons
- Ocean polygons
- Rivers and lake centerlines (single-line drainage)
- Lakes and reservoirs (polygons)
- Glaciers and ice sheets
- Reefs
- Geographic regions (continents, subcontinents as labeled polygons)
- Bathymetry (ocean depth zones as polygons at 200m, 1000m, 2000m, 3000m, 4000m, 5000m, 6000m, 7000m, 8000m, 9000m, 10000m increments)

**Graticule / reference lines:**
- Equator, tropics, polar circles, international date line (all as lines)
- 15°, 30°, and 5° graticule grids

**Resolution tiers:**
- **110m** (1:110,000,000) — continental scale, small file size, good for full world maps
- **50m** (1:50,000,000) — regional scale, moderate detail
- **10m** (1:10,000,000) — country/state level, most detailed

### Fetching

The simplest approach for web use is the `world-atlas` npm package, which pre-processes Natural Earth into TopoJSON:

```bash
npm install world-atlas topojson-client
```

```typescript
import { feature } from 'topojson-client'
import type { Topology } from 'topojson-specification'

// world-atlas ships two files:
// countries-110m.json — objects: { countries, land }
// countries-50m.json  — objects: { countries, land }
import countries110 from 'world-atlas/countries-110m.json' assert { type: 'json' }

const topology = countries110 as unknown as Topology
const countries = feature(topology, topology.objects.countries)
const land = feature(topology, topology.objects.land)
```

For layers not in the npm package (rivers, bathymetry, cities, time zones), fetch directly from the Natural Earth GitHub mirror:

## Provider 2: TIGERweb (US Census Bureau)

**Scope:** United States only (including territories)  
**License:** US government work. Not subject to copyright under 17 U.S.C. §105. Fully commercial-safe. Do not use the registered trademark "TIGER/Line®" in product names.  
**Root URL:** `https://tigerweb.geo.census.gov/arcgis/rest/services/TIGERweb/`  

### Service Architecture

TIGERweb is organized into **named services**, each covering a thematic group of layers. You do not query a single monolithic endpoint — you choose the correct service for the layer type you need, then query by layer ID within that service.

| Service | What it contains |
|---|---|
| `State_County` | States (layer 0) and Counties (layer 1) — the cleanest endpoint for these two |
| `tigerWMS_Current` | Full current-vintage WMS: ZIP codes, tribal areas, metro areas, congressional districts |
| `tigerWMS_PhysicalFeatures` | Roads (layers 1,3,5), railroads (7), hydrography group (layers 10,12,14) |
| `Hydro` | Dedicated hydrography service: linear rivers (0), areal water bodies (1), glaciers (2) |
| `Legislative` | Congressional districts: 119th at layer 0 (BAS 2025) and layer 4 (ACS 2024) |
| `AIANNHA` | American Indian, Alaska Native, and Native Hawaiian Areas (layer 47) |
| `Places_CouSub_ConCity_SubMCD` | Incorporated places (layer 4), census designated places (layer 5) |
| `Transportation` | Primary roads at multiple scale layers (0,1,2), secondary roads (3–6), local roads (7) |
| `Tracts_Blocks` | Census tracts and blocks |
| `Urban` | Urban area polygons |

All services support GeoJSON output via `f=geojson`, and all support `outSR=4326` to return WGS84 coordinates. **Always include `outSR=4326`** — omitting it returns geometries in EPSG:3857 (Web Mercator), which will render incorrectly in react-simple-maps.

### Query Pattern

```typescript
async function queryTigerWeb(
  service: string,
  layerId: number,
  params: Record<string, string>
): Promise<GeoJSON.FeatureCollection> {
  const base = `https://tigerweb.geo.census.gov/arcgis/rest/services/TIGERweb/${service}/MapServer/${layerId}/query`
  const defaults: Record<string, string> = {
    f: 'geojson',
    outFields: '*',
    returnGeometry: 'true',
    outSR: '4326',  // Always WGS84 — omitting this returns 3857 and breaks rendering
  }
  const url = new URL(base)
  Object.entries({ ...defaults, ...params }).forEach(([k, v]) =>
    url.searchParams.set(k, v)
  )
  const res = await fetch(url.toString())
  if (!res.ok) throw new Error(`TIGERweb fetch failed: ${url}`)
  return res.json()
}

// Usage examples:

// All states
const states = await queryTigerWeb('State_County', 0, {
  where: '1=1',
  outFields: 'STATE,NAME,STUSAB,AREALAND,AREAWATER',
})

// All counties
const counties = await queryTigerWeb('State_County', 1, {
  where: '1=1',
  outFields: 'GEOID,NAME,STATE,COUNTY',
})

// Counties for a single state (FIPS: CA=06, TX=48, NY=36, FL=12, PA=42, CO=08)
const caCounties = await queryTigerWeb('State_County', 1, {
  where: "STATE='06'",
  outFields: 'GEOID,NAME,STATE,COUNTY',
})

// Congressional districts (119th)
const districts = await queryTigerWeb('Legislative', 0, {
  where: '1=1',
  outFields: 'GEOID,BASENAME,STATE,CD119FP',
})

// Congressional districts for a single state
const paCDs = await queryTigerWeb('Legislative', 0, {
  where: "STATE='42'",
  outFields: 'GEOID,BASENAME,STATE,CD119FP',
})

// AIANNH areas — federal reservations and trust lands only
const tribal = await queryTigerWeb('AIANNHA', 47, {
  where: "AIANNHCC IN ('R','T','J')",
  outFields: 'GEOID,NAME,AIANNHCC,AREALAND',
})

// Primary roads in a bounding box
const highways = await queryTigerWeb('Transportation', 2, {
  where: '1=1',
  geometry: '-125,24,-66,50',
  geometryType: 'esriGeometryEnvelope',
  inSR: '4326',
  spatialRel: 'esriSpatialRelIntersects',
  outFields: 'FULLNAME,RTTYP,MTFCC',
})

// Rivers in a bounding box
const rivers = await queryTigerWeb('Hydro', 0, {
  where: "NAME <> ''",
  geometry: '-125,24,-66,50',
  geometryType: 'esriGeometryEnvelope',
  inSR: '4326',
  spatialRel: 'esriSpatialRelIntersects',
  outFields: 'NAME,MTFCC',
})

// Large lakes and water bodies
const lakes = await queryTigerWeb('Hydro', 1, {
  where: 'AREAWATER > 5000000',  // >5 sq km
  geometry: '-92,41,-76,48',
  geometryType: 'esriGeometryEnvelope',
  inSR: '4326',
  spatialRel: 'esriSpatialRelIntersects',
  outFields: 'NAME,MTFCC,AREAWATER',
})
```

> **Pagination:** TIGERweb returns at most 100,000 features per request. For datasets that may exceed this, paginate using `resultOffset` and `resultRecordCount`, or query state by state using a `where: "STATE='XX'"` filter.

## Provider 3: USGS National Map

**Scope:** United States
**License:** Public domain (USGS is a federal agency). Fully commercial-safe.
**Feature Query Host:** `https://cartowfs.nationalmap.gov/arcgis/rest/services/`
**Viewer:** https://apps.nationalmap.gov/viewer/

> **Critical: Two separate hosts exist.**
> - `carto.nationalmap.gov` — Display/tile-rendering service (36 nested layers). NOT for feature extraction. Querying it for geometry causes 500 errors on dense tiles.
> - `cartowfs.nationalmap.gov` — Web Feature Service (6 clean layers). Designed for programmatic feature queries. **Use this one.**

### What it Contains

The USGS National Map is the primary source for physical terrain data in the US. Where TIGERweb covers political and administrative geography, USGS covers the physical landscape.

**Contours (elevation lines) — `contours/MapServer` on cartowfs:**
- Layer 1: 100ft contour lines (all types)
- Layer 3: 50ft contour lines (all types) — use for regional/state maps
- Layer 5: Large-scale contour lines (variable interval)
- `ContourElevation` attribute: elevation in feet (double)
- `IndexFlag` attribute: `1` = Index (heavier line, typically labeled), `0` = Intermediate
- Note: the `carto` (display) host uses different field names (`Contour`, `for_raster`) — do not use those

> **Fetch constraints for contours:**
> - Tile at 0.5° max — 1° tiles cause HTTP 500 on dense mountain terrain.
> - Always include `maxAllowableOffset=0.001` for server-side simplification.
> - Paginate with `resultOffset` for tiles that return exactly MaxRecordCount features.

**Watershed Boundaries (WBD) — `https://hydro.nationalmap.gov/arcgis/rest/services/wbd/MapServer`:**
- Layer 2: HUC2 (major drainage regions, 21 in the US)
- Layer 4: HUC4 (subregions)
- Layer 6: HUC6 (basins)
- Layer 8: HUC8 (subbasins)

### Fetching

```typescript
// Use cartowfs (Web Feature Service), NOT carto (display service)
const USGS_BASE = 'https://cartowfs.nationalmap.gov/arcgis/rest/services'

async function queryUSGS(
  service: string,
  layerId: number,
  params: Record<string, string>
): Promise<GeoJSON.FeatureCollection> {
  const base = `${USGS_BASE}/${service}/MapServer/${layerId}/query`
  const url = new URL(base)
  const defaults: Record<string, string> = {
    f: 'geojson',
    outFields: '*',
    returnGeometry: 'true',
    outSR: '4326',
    maxAllowableOffset: '0.001',  // server-side simplification, prevents 500s
  }
  Object.entries({ ...defaults, ...params }).forEach(([k, v]) =>
    url.searchParams.set(k, v)
  )
  const res = await fetch(url.toString())
  if (!res.ok) throw new Error(`USGS fetch failed: ${url}`)
  return res.json()
}

// 50ft contours (layer 3 on cartowfs) — use for regional/state maps
// Tile at 0.5° max to avoid server 500 errors on dense terrain
const contours = await queryUSGS('contours', 3, {
  where: "ContourType='Index'",
  geometry: '-120,36.5,-119.5,37',  // 0.5° tile
  geometryType: 'esriGeometryEnvelope',
  inSR: '4326',
  spatialRel: 'esriSpatialRelIntersects',
  resultRecordCount: '500',
})

// HUC8 watershed boundaries for the Colorado basin
const HUC_BASE = 'https://hydro.nationalmap.gov/arcgis/rest/services/wbd/MapServer'

async function queryHUC(
  layerId: number,
  whereClause: string
): Promise<GeoJSON.FeatureCollection> {
  const url = new URL(`${HUC_BASE}/${layerId}/query`)
  url.searchParams.set('where', whereClause)
  url.searchParams.set('f', 'geojson')
  url.searchParams.set('outFields', '*')
  url.searchParams.set('outSR', '4326')
  url.searchParams.set('returnGeometry', 'true')
  return fetch(url.toString()).then(r => r.json())
}

// Colorado River HUC4 subregions (HUC codes starting with 14 or 15)
const coloradoWatershed = await queryHUC(4, "HUC4 LIKE '14%' OR HUC4 LIKE '15%'")
```

### Contour Property Schema


> **Simplification is required.** USGS contour features have very high vertex counts even after server-side simplification via `maxAllowableOffset`. Always run them through `@turf/simplify` before storing. Tolerance of `0.05` degrees is appropriate for regional maps (~5km precision, keeps the shape); `0.005` for state-level detail.

## Normalizing to a Common Dataset

The fundamental problem is that each provider returns GeoJSON with different property names and different implicit assumptions. Normalize all features to a shared schema before rendering.

### The Normalized Feature Schema

```typescript
interface NormalizedFeature {
  id: string
  type: 'Feature'
  geometry: GeoJSON.Geometry    // Always WGS84
  properties: {
    name: string
    code?: string               // ISO, FIPS, GEOID, etc.
    provider: 'natural-earth' | 'tigerweb' | 'usgs'
    layer: string               // 'countries' | 'states' | 'rivers' | 'contours' | ...
    featureType: 'polygon' | 'line' | 'point'
    rank?: number               // Stream order proxy, road class, contour type, city size
    value?: number              // Elevation, population, density — for choropleth
    source: Record<string, unknown>  // Original properties preserved
  }
}

interface MapDataset {
  id: string
  features: NormalizedFeature[]
  bbox: [number, number, number, number]  // [minLon, minLat, maxLon, maxLat]
  meta: {
    providers: string[]
    layers: string[]
    fetchedAt: string
  }
}
```

### Normalization Functions

```typescript
function normalizeNaturalEarthCountry(f: GeoJSON.Feature): NormalizedFeature {
  const p = f.properties as any
  return { ...f, id: `ne-country-${p.ISO_A3}`,
    properties: { name: p.NAME, code: p.ISO_A3,
      provider: 'natural-earth', layer: 'countries', featureType: 'polygon', source: p }}
}

function normalizeTigerState(f: GeoJSON.Feature): NormalizedFeature {
  const p = f.properties as any
  return { ...f, id: `tiger-state-${p.STATE}`,
    properties: { name: p.NAME, code: p.STUSAB,
      provider: 'tigerweb', layer: 'states', featureType: 'polygon', source: p }}
}

function normalizeTigerCounty(f: GeoJSON.Feature): NormalizedFeature {
  const p = f.properties as any
  return { ...f, id: `tiger-county-${p.GEOID}`,
    properties: { name: p.NAME, code: p.GEOID,
      provider: 'tigerweb', layer: 'counties', featureType: 'polygon', source: p }}
}

function normalizeTigerRoad(f: GeoJSON.Feature): NormalizedFeature {
  const p = f.properties as any
  const rank = p.MTFCC === 'S1100' ? 1 : p.MTFCC === 'S1200' ? 2 : 3
  return { ...f, id: `tiger-road-${p.LINEARID ?? Math.random()}`,
    properties: { name: p.FULLNAME ?? '', rank,
      provider: 'tigerweb', layer: 'roads', featureType: 'line', source: p }}
}

function normalizeTigerRiver(f: GeoJSON.Feature): NormalizedFeature {
  const p = f.properties as any
  return { ...f, id: `tiger-river-${p.LINEARID ?? Math.random()}`,
    properties: { name: p.NAME ?? '', rank: 1,
      provider: 'tigerweb', layer: 'rivers', featureType: 'line', source: p }}
}

function normalizeUSGSContour(f: GeoJSON.Feature): NormalizedFeature {
  const p = f.properties as any
  return { ...f, id: `usgs-contour-${p.OBJECTID}`,
    properties: { name: `${p.ContourElevation}ft`,
      provider: 'usgs', layer: 'contours', featureType: 'line',
      value: p.ContourElevation,
      rank: p.ContourType === 'Index' ? 1 : 2, source: p }}
}
```

### Dataset Builder and Pre-Fetch Pattern

All datasets are built **before the map renders** — as a build-time or one-time Node script that writes pre-fetched, pre-simplified GeoJSON to `src/data/`. The React component imports the file statically and renders synchronously on first paint with no network calls.

```typescript
// scripts/fetch-dataset.ts — run once; output committed to src/data/
import { writeFileSync } from 'fs'
import simplify from '@turf/simplify'

async function buildAndWrite(
  outPath: string,
  bbox: [number, number, number, number],
  layers: Array<{
    fetch: (bbox: [number,number,number,number]) => Promise<GeoJSON.FeatureCollection>
    normalize: (f: GeoJSON.Feature) => NormalizedFeature
    simplifyTolerance?: number
  }>
) {
  const allFeatures: NormalizedFeature[] = []

  for (const layer of layers) {
    const raw = await layer.fetch(bbox)
    const normalized = raw.features.map(layer.normalize)

    const simplified = layer.simplifyTolerance
      ? normalized.map(f => ({
          ...f,
          geometry: simplify(f as any, {
            tolerance: layer.simplifyTolerance,
            highQuality: false
          }).geometry
        }))
      : normalized

    allFeatures.push(...simplified)
  }

  const dataset: MapDataset = {
    id: crypto.randomUUID(),
    features: allFeatures,
    bbox,
    meta: {
      providers: [...new Set(allFeatures.map(f => f.properties.provider))],
      layers: [...new Set(allFeatures.map(f => f.properties.layer))],
      fetchedAt: new Date().toISOString(),
    }
  }

  writeFileSync(outPath, JSON.stringify(dataset))
  console.log(`Wrote ${allFeatures.length} features to ${outPath}`)
}
```

```typescript
// In your React component — zero runtime fetching
import dataset from '../data/us-rivers.json'
// dataset.features is immediately available; map renders on first paint
```

### Coordinate Precision Reduction

After simplification, truncate coordinate precision to 5 decimal places (~1m at the equator) to reduce file size significantly. At a 1200px canvas covering the continental US (~4,500km), one pixel represents ~3.75km — 5 decimal places is three orders of magnitude more precise than any visible difference.

```typescript
function truncatePrecision(coords: number[][], decimals = 5): number[][] {
  const f = Math.pow(10, decimals)
  return coords.map(([x, y]) => [Math.round(x * f) / f, Math.round(y * f) / f])
}
```

### Layer Rendering Order in react-simple-maps

When combining multiple datasets, render in this order (back to front):

1. Ocean / bathymetry polygons
2. Land polygons
3. Terrain contours — under political overlays
4. Water polygons (lakes, reservoirs, bays)
5. Rivers and streams (lines)
6. Political fill polygons (countries, states, counties)
7. Political boundary lines drawn on top of fills
8. Roads
9. Points (cities, structures)
10. Labels and annotation

## Cross-Cutting Concerns for Professional Maps

Before enumerating the twenty examples, several principles apply across all of them.

### The Dataset Is Built Before the Map Renders

Every map stores its data as a pre-fetched, pre-simplified JSON file in `src/data/`. The React component imports the file statically. There are no `useEffect` fetch calls in the renderer. This means the map renders synchronously on first paint. The fetch script is run manually when the source data needs to be refreshed (Census vintages update annually).

### The Viewport Is Derived From the Data

The projection viewport should be computed from the actual bounding box of the data, not from a round-number estimate. Compute the bbox of all features, expand by 4–6% on each side for visual breathing room, and set the projection's `center` and `scale` from that. In react-simple-maps:

```typescript
// Given bbox [minLon, minLat, maxLon, maxLat]:
const cx = (minLon + maxLon) / 2
const cy = (minLat + maxLat) / 2
const lonSpan = maxLon - minLon
// For Mercator at svgWidth=960: scale ≈ (svgWidth / lonSpan) * 50
// Adjust empirically — this is a starting point, not an exact formula
```

For the continental US on Albers Equal Area, the standard parameters are:
`rotate: [96, 0], parallels: [29.5, 45.5], center: [0, 37.5], scale: 900` at `svgWidth=960`.

### Color as Signal, Not Decoration

Each map uses color to communicate exactly one thing. For adjacency separation, the four colors are perceptually equidistant neutrals — they encode only "different," not "ranked." For choropleth, one sequential scale encodes one quantitative variable. The base palette for DNA Atlas is chromatic gray (the Perturbation palette). Map palettes live within this system: water is always at the cool end; land at the warm end. The contrast between them is the first visual hierarchy the viewer reads.

### Context Layers Are Always Deemphasized

Context layers — the background that helps the viewer orient — are rendered at lower opacity and lighter stroke than the subject layers. Subject layers should be the darkest, highest-contrast elements. Context at 60–70% opacity; secondary context at 30–40%.

### Every Map Has a Title and a Legend

A map without a title is raw output. Every map carries at minimum:

- A **title** — the most specific possible description. Not "US Map" but "Drainage Network of the Colorado Basin."
- A **scale bar** — for reference maps, showing approximate distance per fixed pixel count.
- A **legend** — for any map using color or stroke weight to encode data, using exact graphic treatment (same stroke, fill, opacity as the map features).

Labels for specific features are used sparingly — only when they add information the geometry cannot communicate alone.

### Professional Finishing

- **Bleed:** The canvas extends slightly past the viewable frame so lines touching the edge appear to continue off-screen naturally.
- **Stroke hierarchy:** Features at smaller scale get lighter, thinner strokes. Encode the `rank` attribute as both opacity and stroke-width.
- **Minimum stroke:** 0.3px. Anything thinner renders inconsistently across devices.
- **Ocean color:** Never pure white. In this project, the ocean is the lightest stop in the current palette — approximately `#f3f6f7` at ΔE=1.5.

### 2. US County Choropleth — Population Density

**Provider:** TIGERweb `State_County` (counties, layer 1) + Census Population Estimates API  
**Dataset fetch:**
```typescript
const counties = await queryTigerWeb('State_County', 1, {
  where: '1=1',
  outFields: 'GEOID,NAME,STATE,AREALAND',
})

// Census API — 2023 population estimates by county
const popRes = await fetch(
  'https://api.census.gov/data/2023/pep/population?get=POP_2023,NAME&for=county:*'
)
const popData = await popRes.json()  // [[POP_2023, NAME, state, county], ...]

const popByGeoid = new Map(
  (popData as string[][]).slice(1).map(row => [`${row[2]}${row[3]}`, parseInt(row[0])])
)

const enriched = counties.features.map(f => {
  const p = f.properties as any
  const pop = popByGeoid.get(p.GEOID) ?? 0
  const areaSqMiles = p.AREALAND / 2_589_988
  return { ...f, properties: { ...p, population: pop,
    density: areaSqMiles > 0 ? pop / areaSqMiles : 0 }}
})
```

**Description:** 3,100+ county polygons colored by population density. Density spans six orders of magnitude — from <1 person per square mile in western counties to 70,000+ in Manhattan.

**Professional treatment:**

*Projection:* Albers Equal Area Conic — mandatory for a density map. A conformal projection like Mercator would make northern counties visually larger and systematically exaggerate their apparent density.

*Color:* A sequential single-hue scale, log-transformed. Use `d3-scale`'s `scaleLog` with domain `[0.01, 70000]` and range `[#ebe9e4, #2a2a36]`. Log transformation prevents all rural counties from collapsing to a single near-white. The scale is stored as pre-computed hex values in the dataset — no D3 at render time.

*Context:* County borders at `0.15px`, barely visible — the choropleth value does the visual work. State borders on top at `0.6px` in warm dark gray for regional orientation. Legend: a continuous gradient bar annotated at `1, 10, 100, 1000, 10000` persons/sq mi. Title: "Population Density — United States Counties, 2023 Estimate." A subtitle in smaller text: "Persons per square mile, log scale."

*What this map reveals:* The radical concentration of population in coastal metros and the vast emptiness of the interior. The entire state of Wyoming has fewer people than a single Manhattan ZIP code. This is only visible at county level — state-level maps suppress it.

```typescript
  .sort((a, b) => (b.properties.POP_MAX as number) - (a.properties.POP_MAX as number))

const land = await fetchNaturalEarth('land', '110m')
const countries = await fetchNaturalEarth('admin_0_countries', '110m')
```

**Description:** City points sized by log(population) on a minimal world map — a gravitational portrait of where humanity lives, without any political coloring.

**Professional treatment:**

*Projection:* Winkel Tripel. Land: `#e6e2db`. Ocean: `#f0eff0`. Country borders: `0.2px`, `rgba(100,100,100,0.4)` — barely present.

*Point encoding:* Radius: `r = (Math.log10(pop) - 4) * 1.4`. This maps 100k-population cities to ~1px and 37M-population Tokyo to ~6px. Points are filled `rgba(30,30,40,0.72)`. Larger points render first (drawn beneath), smaller on top — so the small cities that cluster around major ones remain visible and don't disappear behind the large point.

*Labels:* Top 20 cities by population, set in `0.6rem` light gray with a thin white text shadow. Placed programmatically offset to the right of the point center. No leader lines — the font is small enough that approximate placement is readable.

*What this map reveals:* The Eurasian coastal rim (from Tokyo to Mumbai to Cairo to London) contains more of the population markers than all of the Americas. Sub-Saharan Africa's population, despite being large, appears as moderate-sized dots widely spaced. The emptiness of Canada, Australia, and the central Sahara is equally legible. Title: "Global Urban Gravity — Cities Above 100,000." Legend: three reference circles at 100k, 1M, 10M labeled.
