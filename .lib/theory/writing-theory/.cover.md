How the project writes mathematics, and why it does it this way. The shelf is
[`library/theory/`](../../.cover.md). Every document is LaTeX from its first line, because LaTeX is how
mathematics is published and because `amsthm` numbers definitions, lemmas, theorems and proofs so they
can refer to one another. Tectonic builds the documents and LaTeX Workshop shows them in VS Code beside the
source. They all share one preamble and one notation file, so a symbol means the same thing in every
document.

Each document is sent as a pair: a PDF with every font embedded, and a single `.tex` file. That file is
generated from the source by inlining the shared files. The build proves the pair can be sent by compiling
the `.tex` alone in an empty folder.

Checking an argument is a separate question from writing it, and the answer depends on the kind of
mathematics. This book says plainly what each tool can and cannot check. The first document on the shelf,
*What a first-order inversion leaves in a calcium trace*, was written on 2026-09-29 to prove the whole
path, from editing to rebuilding to a sendable pair. Doug had asked to *"prove that we can edit latex and
generate latex documents that could be sent around."*

## Chapters

1. [Why LaTeX](01-why-latex.md): the options Doug set out (LaTeX, Markdown with KaTeX, a React theory
   browser), why LaTeX won, and why Tectonic and LaTeX Workshop.
2. [The shelf](02-the-shelf.md): one folder per document, the shared preamble, notation and template, the
   label prefixes, and why figures and references are written inside the source.
3. [Building and sending](03-building-and-sending.md): the preview on save, and `build.py`, which makes
   the standalone pair, proves it compiles alone, checks the fonts and runs the document's checks. It also
   records what the build does not yet handle.
4. [Checking](04-checking.md): computer algebra, simulation and proof assistants, what each can establish,
   and how the first document was checked.
