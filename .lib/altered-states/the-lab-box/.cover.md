---

The lab's Linux GPU machine, `lipshutzlab-01`, and how the team works on it without living on it. The team stays on Doug's machine and drives the box over Tailscale SSH; the box holds a clone of this repository in `~/doug/altered-states/main`, which only ever moves by pulling from GitHub — nothing is committed to it. Work runs under one protocol: commit everything here, pull there, branch the run into a worktree beside `main`, commit everything about the run there, and pull it home through GitHub. The ignored files (the scans, the caches) cross by tar over SSH, each path verified by sha256 on arrival; Python is rebuilt inside the folder rather than copied, and nothing lands in the lab's shared home. Identity — `.claude/`, `CLAUDE.md`, every `.lib/` — never travels. The executable form is the [`/als-remote`](../../../.claude/library/our-skillset/34-als-remote.md) skill; this book holds the rulings it follows, what broke on the way in and why, and what is still open.

## Chapters

1. [Reaching the box](01-reaching-the-box.md) — what a connection needs at each end and what failed first: Tailscale on the box alone gave this machine no route, Tailscale SSH has to be switched on separately, the ACL's `check` mode would stall every non-interactive command, and ProtonVPN's kill switch refused every socket to the tailnet with a local `Permission denied` while `tailscale ping` still answered. The link runs through Tailscale's Dallas relay at a measured 0.75 MB/s.
2. [The box](02-the-box.md) — the machine as surveyed on 2026-09-26 (Ubuntu 24.04, 24 cores, 60 GB, 3.4 TB free, an NVIDIA RTX card), the folder layout and the deploy key already wired into the clone, where the sudo password lives and why there; the environment kept inside the folder because the account is the lab's, its lock generated by the compiler from this machine's actual packages (`mei` and `egg` installed around their metadata, as here), and the package-by-package proof that it matches; and what is open: the NVIDIA driver has no module for the running kernel.
3. [Parity](03-parity.md) — the first parity, made before the run protocol existed. Doug's rulings verbatim (nothing committed on the box, identity never travels, `main` the only branch until a job is dispatched), and how parity is made and proved: a bundle for the commits, two git-built patches for the index and working tree so CRLF lands as LF, three hashes equal on both ends; the branch library taken out of the project's git because identity is its object of record; the ignored files sent one verified path at a time.
4. [The run](04-the-run.md) — the protocol, in Doug's words and then in five steps: commit everything here; pull there; branch `run-<YYYYMMDD-HHMM>-<name>` as a worktree beside `main`, the scans linked in from `main` rather than copied; run detached and commit everything about it — command, base commit, environment, log, outputs, failures too — with anything over GitHub's limit kept on the box by hash; then pull it home through GitHub. Why git carries the results: they arrive with their history.
