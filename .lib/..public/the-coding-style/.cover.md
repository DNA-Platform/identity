## Chapters

1. [The Unit of Code](01-the-unit-of-code.md) — Three programs, three answers to what one piece of code is — and one rule that decides all three: THE UNIT OF CODE IS WHATEVER THAT PROGRAM STATES ITS INVARIANTS OVER. A program's file boundaries should fall where its promises fall, because a promise that spans two files is a promise neither file can keep, and the way that failure arrives is always the same.
2. [The Order of a Class](02-the-order-of-a-class.md) — The member order inside a class, given by Doug four times in one sitting and quoted rather than paraphrased because paraphrase is what kept getting it wrong. AMENDED 2026-08-30, when he gave it again and it had changed. THE ORDER IS NOW SEVEN GROUPS: fields, then properties, then the bond constructor, then the constructor, then methods, then protected methods, then private methods. AMENDED AGAIN 2026-09-22: within a method group the top-level methods come first and what they depend on stands beneath them in the order met — in a class that draws, view is the first method, what it draws with follows, the machinery under them.
3. [The Coding Style](03-the-coding-style.md) — THE INDEX OF EVERY RULE IN FORCE, so a refactor finds the ruling before it undoes one — each row saying what a document RULES and the day the ruling was given. Carries the four chapters on how code here is written, where a class lives, the $-fetch and timing law, the spec convention, WE DO NOT INNOVATE, NO INVENTED LANGUAGE with its struck-word table, the CODE PATTERNS given 2026-09-21 and 22 on the redraft's first class — a name says what TYPE a thing is and never what role it plays, a body stands on its own line, a framework type never carries a library's word, writing is not inline, no statics and no predicted polymorphism, minimize members and caching, the top-level methods first with view at the top, a CSS class the library puts on an element is prefixed pd- and the code never hides or styles by a component type, the TSX tells the story stacked and indented with no blank lines and the rest of the class is terse — what is never okay, the seen gate, the comment lifecycle, NO PERSPECTIVES, styling, the drawing conventions and the minifier caution. THE ANCHORS ARE THREE: this is the public library; it is closed under books; and the design is Doug's while the implementation is ours.
4. [The Closeness Rule](04-the-closeness-rule.md) — The law the other style chapters are expressions of: PROXIMITY encodes relatedness, SIZE encodes relevance inverted, the order always wins, art operates only where the convention is silent. The four instruments — ordering, stacking, compactness (bracketless one-liners, guards on one line, housekeeping fors small), paragraphs in code with extraction earned by polymorphism alone. What the law forbids: readability blank lines, doubles, moved members, guards drawn as branches, comments.
5. [The Spelling of a Kind](05-the-spelling-of-a-kind.md) — How a kind is spelled, in the order a file declares them: the class, the type with its name and cache as one act, the bond (super FIRST so a carried type wins, then a default through $check with the make marker), formula = 'new' only where a kind must not answer to names its siblings filed…
6. [The Shape of TSX](06-the-shape-of-tsx.md) — HOW TSX IS LAID OUT, HOW A COMPONENT IS NAMED, AND WHAT $ IS FOR — written 2026-09-04 because the branch had rules for the layout of a class and none for TSX, which is most of the code. Given 2026-09-22: the TSX tells the story and the rest of the class is terse — a view opens its element on its own line, indents its parts and stacks them with no blank line between, since the elements are the separation, and names what it needs just above the return; every other method stays terse.
7. [What Natural Means](07-what-natural-means.md) — Doug asks for it constantly and it was never written down — what natural MEANS, so that ceremony and ugly member have a referent. NATURAL MEANS NO FIGHTS, the tolerance given 2026-09-13: a wart is a fight the implementer meets — saying a thing twice, dodging a base seam, waiving in two places, reaching through, hand-writing what the framework writes, hiding, positional selection — and it trickles, the base paying once and everything beneath forever; the fix is always in .public, never patched where met; promises are not gospel; a fix is judged as a wart too, and so is a design of his; deleting has the same test (an interface member is intentional, a sketch keeps its essence, read the chain with tools); parenthetical is by design. THE THREE TESTS: it says the thing in the domain's own words; it ASKS where it had been deriving or storing (the tell is a roster); it uses the mechanism already there (a new member is a feature the framework should have). The measure: a natural change SUBTRACTS. Six shapes of unnatural, each with a real one behind it; the coherence test; and the warning that naturalness is no licence to restructure — friction is the design speaking, and a design that fails its own promise is a HALT. THE REACH, given the same day: the fix is in the framework you control, and chemistry is that framework too — when .public re-implements what the wrapped library gives, the answer is one pitch to chemistry, not a battle; three tells, and the rule that when a fix is a fight you ask which layer the feature lives in. AND THE CSS SHAPES, rules that do not collide: a rule names a kind, sets its own element, takes its numbers from the theme, places by named areas, and never restates a default or an attribute — when no two authors set one property, the cascade is never asked to choose.
8. [How a Class Is Documented](08-how-a-class-is-documented.md) — THE DOCUMENTATION SYSTEM OF .public, focused on extension, ruled 2026-09-22 — hand-written, four parts per class, living in the branch library beside the package: one book per src folder with front matter for what its classes share, one chapter per class holding what it is with every member cited, how it is extended, its promises and its gate; the chapter links to the code and never the reverse, every name of ours is flagged, a question for Doug is asked in the code and moves to the chapter when answered, the chapter is edited at every pass; and when a class is called done. Generalizes the plan first written for Writing; Utilities is the first book written to it.
