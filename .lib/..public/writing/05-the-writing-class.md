## The review of 2026-09-21, evening

**Doug: *"Clean the code, make sure it has the highest of coding standards, that I have approved all the members, that it is organized, that it looks like code I would approve, and that it doesn't have any complex contraptions added because we didn't think through something and it needs more thought."*** Read whole after the last edit, all three files.

**Approved by his word, in the table above:** every member of `$Writing` and `$Annotation` but one, and every operation of the collection E65 names plus the two questions. **Ours, flagged, and approved as his on 2026-09-22:** `_is`, the backing the getter answers; `drop` and `prepend` on the collection, which `$is` and the bond need; the collection's five readings, which the rendering and the rules need; and the `Given` type — *"those words require deep thought and must go through me."* **Struck at the review:** two fields on Writing that the annotations wrote — *"How could these be there?"* — a type question turned into a flag; `Formal`, `Informal` and the Specification's `expressed`, since the binder is what checks; `inert`; the word *trait* as ours — his hint for the model, whose name is the annotation-based writing model. **Order of the class:** no private member, on his word — *"No privacy on writing. Protected if you need it"* — the protected backings first and the public fields after, as he reorganized the file himself on 2026-09-22; then the properties; the bond; the methods with `view` first, `specify` beside it as the other entry, then `write` and `annotate` that `view` draws with, then `$Define` and `define` that all of them rest on — as [The Order of a Class](../the-coding-style/02-the-order-of-a-class.md#the-story-first) rules since 2026-09-22, and with the view's TSX the one place written to be looked at, indented and stacked with no blank line inside, as [The Shape of TSX](../the-coding-style/06-the-shape-of-tsx.md#the-story) rules. **Contraptions:** named with their reasons in [the annotation system's chapter](07-the-annotation-system.md#what-made-it-complex-and-what-was-done).

**Writing is not inline, and a block has no special powers.** The first draft opened the framework's blocks in every reading, on the first library's habit of making writing inline so that it flowed inside prose. Doug: *"This writing, btw, will not be so inline. Blocks wont have special powers."* The framework's `inline` is false by default and the draft leaves it so, which means a writing written among prose arrives as its own argument beside the blocks of prose, never inside one; so no reading opens a block, and what comes in is `$Chemical[]` exactly as E64 says. The same day the type the first draft imported for a block's elements, `$Written`, was found to be the framework carrying writing's word — *"a flaming breaking of levels"* — and renamed `$Inline` in chemistry.

**What is not here, by ruling.** No tail rule: an annotation may stand anywhere among what comes in (*"we can have them wherever and they are ignored in scans"*). No companion type and no interface; the specification is a detached class beside the writing. No parse: strings are calligraphy and nothing is made beneath them (E12, E14, E32; *"Yes, the parse is gone"*). No `source`: what came in is sorted once into the two collections. No cache. No static members and no member the base predicts for its subclasses. No `$Reorganize`, no ancestor climb, no specification in the bond, no field for what an annotation means. No sugar props and no opposites that name a class: the day's designs that grew past the system, each struck by Doug and recorded in [the annotation system's chapter](07-the-annotation-system.md#where-the-design-came-from).

**The binary pattern, and where it went.** Doug, reading the first draft: *"For the binary pattern, no need for a backing field: `$parenthetical?: boolean = false; get $narrative() { return !this.$parenthetical; } set $narrative(value) { this.$parenthetical = !value; }` This pattern can be used for permissive vs strict and open vs closed."* That is still the shape for a pair of props on a class whose two halves are one stored value. For parenthetical the pair became two annotations and a question the view asks; for formal it became nothing, since the binder is what checks. Whether Composition's pairs stay props or become annotations is his to say when Composition is written.

**The shape of `formal` took five passes and ended in none, and the record keeps them because each was a ruling.** A plain accessor over a backing field beside a `$formal` prop, struck — *"Why are you putting disconnected backing fields for things without the setter?"*; a prop made the thing, *"`protected _formal = false; get $formal()…`"*; then an annotation, *"You can make something formal by adding `<Formal />`"*; then, on seeing that a written Formal cannot reach a child at the child's bond, the specification left the bond — *"formal can't propagate down. Then let's have specify be separate"*; and last, *"Oh true, we don't need formal at all! specify is just called in the test. Good. Drop it."*

## The pattern in his corrections

**Eight passes in one day, and every correction struck something added for mechanism.** Read together they are one rule seen from four sides: the code says what it means and nothing about how it gets there. A type question is answered by the type, never by a flag. A name says what a thing is, never what it does in the algorithm. A member exists only when it is a Genesis word or a framework shape — so a backing field without a setter, a prop standing beside a property, a convenience reading and a proxy name are one fault. And the layout shows the structure at a glance: flat properties stacked, long ones shaped like methods, a body on its own line. The evening added a fifth side: a mechanism that grows past what was asked is struck even when it works — the opposites toggled, and went, because *"this system is too complex"*; and the two fields went with *"How could these be there?"*, the first rule seen again. Asked what else he might want changed, the team put its questions in the file at the lines they concern, each beginning `ask:`, for him to answer in place; at the review the questions left the code for the chapter.
