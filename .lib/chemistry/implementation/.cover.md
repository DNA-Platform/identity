# Implementation

- **author:** [Cathy](../../../../.claude/library/..teamsmanship/..team/cathy/cathy-and-the-reactive-canvas/.cover.md)
- **subject:** [$Chemistry](../..representivity/.cover.md)

---

I am the framework-developer reference. The other books describe what $Chemistry does — this book describes what the source files contain. Each chapter is one source file: a one-paragraph orientation, the module's responsibility, its internal structure, and a link to the source. A framework developer who needs to read or modify the implementation starts here. The order follows the abstraction/implementation split in the source tree: the seven abstraction modules that define the class hierarchy, then the eight implementation modules that provide the machinery those classes depend on.

## Chapters

1. [particle.ts](01-particle.md) — `src/abstraction/particle.ts`. The `$Particle` class, the `$lift` function, the render filter chain, and `isParticle`. The foundation of the class hierarchy.
2. [chemical.ts](02-chemical.md) — `src/abstraction/chemical.ts`. The `$Chemical` class, `$Synthesis` and `$SynthesisContext`, the `$()` callable, `$check`, `$is`, and `bind`. Composition and the binding constructor.
3. [atom.ts](03-atom.md) — `src/abstraction/atom.ts`. The `$Atom` singleton. The constructor returns the class template; each class has exactly one instance.
4. [bond.ts](04-bond.md) — `src/abstraction/bond.ts`. The `$Bond` class, `$Reagent`, `$Reflection`, decorators (`@inert`, `@reactive`), and the `activate` function. The reactive property installation machinery.
5. [molecule.ts](05-molecule.md) — `src/abstraction/molecule.ts`. The `$Molecule` bond graph collection. Installs getter/setter accessors on instances. Walks the prototype chain to discover bondable properties.
6. [reaction.ts](06-reaction.md) — `src/abstraction/reaction.ts`. The `$Reaction` per-chemical reaction unit. Schedules React state updates. Manages the dirty/clean cycle.
7. [element.ts](07-element.md) — `src/abstraction/element.ts`. React functional component type definitions. The `$Element<T>` and `$Component<T>` types that bridge $Chemistry classes to React's type system.
8. [scope.ts](08-scope.md) — `src/implementation/scope.ts`. Scope tracking and `diffuse`. The `withScope` wrapper, read/write recording, `finalize`, and the fan-out to derivatives. The reactive engine's core.
9. [symbols.ts](09-symbols.md) — `src/implementation/symbols.ts`. Every `Symbol`-keyed slot in the framework. The naming convention (`$x$` for internal, `$$x$$` for framework-private). Why symbols instead of `#private`.
10. [types.ts](10-types.md) — `src/implementation/types.ts`. The TypeScript vocabulary: `$Properties<T>`, `$Component<T>`, `$Element<T>`, `I<T>`. How types survive the `.Component` boundary.
11. [augment.ts](11-augment.md) — `src/implementation/augment.ts`. Event handler wrapping. `augment` walks the React element tree, wrapping handlers in `withScope` so that user interactions trigger scope-tracked reactive updates.
12. [reconcile.ts](12-reconcile.md) — `src/implementation/reconcile.ts`. View diffing. Compares the current view output against the cached previous output. Returns the cached reference when unchanged, triggering React's bailout.
13. [walk.ts](13-walk.md) — `src/implementation/walk.ts`. Tree traversal. The centralized `walk` function that both `augment` and `reconcile` use to traverse React element trees. 39 lines that unify what used to be separate traversals.
14. [representation.ts](14-representation.md) — `src/implementation/representation.ts`. `$symbolize` and `$literalize`. Deterministic serialization for snapshot comparison. Map/Set/Array/Date aware. Cyclic-safe. The foundation of collection mutation detection.
15. [promise.ts](15-promise.md) — `src/implementation/promise.ts`. `$promise` and `$await`. Cancellable promises with chained `then`. The `$cancelled$` sentinel. Synchronous read of settled results.
16. [formula.ts](16-formula.md) — The module is now TWO MEMBERS: $Formula declares the formula flag and draws its children, and everything it used to own lives on $Chemical — so a class becomes a formula by declaring a flag rather than by changing its parent. formula bounds the climb and permits caching; resolve, read off the template, decides whether THIS tag reads its own content as a name and is tested before any lookup; cache stamps a specimen its own template because a specimen is a thing to COPY; keyOf sits behind a symbol, absent from the interface even to a subclass and still overridable; and [$formula$] is the marker and the resolver in one member, so augment imports nothing. A key an ancestor already holds is an ECHO rather than a declaration and files nowhere. standsFor no longer exists — it had no caller outside the suite and duplicated the lookup [$formula$] performs inline.
17. [Hydration](17-hydration.md) — PERSISTENCE IS A FLAG AND A NAME: `persist = true` and a `$pid` (there has to be one — no way around it; an $Atom gets both free, the class its keyless pid). One eager map, localStorage-backed, server-shaped; records hold primitives only — the formation is the backing's census, twins de-duplicated. The alert rides the one activated setter beside diffuse (~4.4M writes/sec non-persistent, persistence at 1.22×, benched). FOUR RECALL SEATS, ONE LAW — recall completes before the first remember (the recalling latch): the atom's constructor with the reinit latch, the post-bond seat under $formed$, the derive seat at $lift, and the bare flag's own setter, rendering-guarded because recall is setup, not news; the false transition clears and demotes, toggling back snapshots live state deliberately. PROPAGATION IS THE EVENTS: on flush every live same-pid chemical is overwritten and repainted — shared pids are a FEATURE (one truth, many faces, joint syncing), and it is also persistence's repaint path, since diffuse walks parents and an orphan's cross-read repaints nobody — every persistent part wears its own face. `$(pid)` is the door: the live enrollee, checked before the tag catalogue, an implausible tag answering undefined.
