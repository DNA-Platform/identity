# Particle

- **author:** [Cathy](../../../../.claude/library/..teamsmanship/..team/cathy/cathy-and-the-reactive-canvas/.cover.md)
- **subject:** [$Chemistry](../..representivity/.cover.md)

---

I am the foundation. Every chemical, every atom, every particularized carrier begins here — in the `$Particle` class that gives the framework its ground. I describe the primitive: the identity fields that make each particle uniquely addressable, the lifecycle that orders its phases, the lift function that creates per-mount derivatives, and the view contract that every subclass fulfills. A reader who finishes this book understands what a particle IS before they encounter what a particle can DO in composition. The class is 290 lines. The concepts it carries are the load-bearing floor of everything above.

## Chapters

1. [Identity](01-identity.md) — the three identity fields (`$cid$`, `$symbol$`, `$type$`), the `isParticle` marker, and the static symbol-creation machinery. A reader either understands all of it or none of it.
2. [Lifecycle](02-lifecycle.md) — six phases (`setup`, `mount`, `render`, `layout`, `effect`, `unmount`), the `next(phase)` progression, `$resolve` propagation up the prototype chain, and the queued-resolver mechanism.
3. [Particularization](03-particularization.md) — the constructor's second mode. `new $Particle(particular)` lifts methods onto an existing object, stamps the marker, reparents. The carrier preserves `instanceof`. Self-contained; depends on identity but nothing else.
4. [Lift](04-lift.md) — per-mount-site derivation via `Object.create()`. Two parents, the first-mount path, the re-entry path, the render hooks, and the cleanup path. The hooks ARE the derivation flow as React sees it.
5. [Render Filters](05-render-filters.md) — the cross-cutting interception chain. `$show`/`$hide`, `registerFilter()`, filter ordering where first non-undefined wins. Tied to lift but conceptually distinct — a reader can need filters without re-reading lift.
6. [View](06-view.md) — `view()`, `$apply`, augmentation, `$rendering$`, `$viewCache$`. The rendering boundary. Subclass authors override `view()` and the cache mechanism deserves explicit treatment.
7. [Component](07-component.md) — the `$()` callable and the Component getter. Class form returns the Component for the class. Instance form lifts a held instance. String form looks up an HTML catalogue entry. The lift-path on `$Particle` vs the template-path override on `$Chemical`.
8. [Looks](08-perspectives.md) — A particle draws through ONE OF A NUMBERED SERIES of views — view is 0, $view is 1, $$view is 2, each further $ the next — and a subclass extends the series by declaring the next member. Every instance holds a dictionary under $views$ keyed BOTH by position and by the name @look gave, so look={1} and look="github" reach the same function. The look attribute is typed number | string and lands on an ordinary reactive field, which is the whole reactivity story. Replaced the two perspective axes, the Perspective class, five symbols and a hand-built cursor on 2026-08-25 — and says plainly what that cost.
9. [The Composition of Looks](09-the-composition-of-perspectives.md) — WHAT IT IS FOR, in plain words: a class used to have ONE drawing, so a default view was a decision you could only replace; now it carries several at once and a subclass adds or replaces without destroying the rest — so a DEFAULT VIEW IS A CHOICE RATHER THAN A FACT, and there can be more than one, chosen polymorphically. The object holds its drawings and has NO OPINION about which is used: no canonical face, and the numbers are an index rather than a rank (measured — permuting two drawings gave a byte-identical page). Meaning comes from outside: the decorator names, the container chooses. Settled: a class's drawings are its own. Unsettled: whether anything coordinates across classes, or whether a coordinator object is enough.
10. [Glossary](10-glossary.md) — alphabetical reference of particle-layer terms, both perspective axes included: `$Particle`, `view()`, `$view`, `look()`, `viewLevel`, `perspectives`, `reveal()`, `Perspective`, `$apply$`, `isParticle`, particular, prototypal view.
11. [Styled Particles](11-styled-particles.md) — A class says what it is styled as, and its CSS-named fields ARE the stylesheet — selector = styled.section names the element, frame() stands it as a component compiled once per class, and nothing is added to the tree. WHY IT EXISTS, in Doug's correction of the framing: a CSS string CANNOT BE OVERRIDDEN — 'you can subclass, but changing strings on subclass is very very very hard to do right; you can't just rewrite the string because anything that needs to stay in sync with the parent is a nightmare to maintain. There is no solution to maintaining CSS and supporting polymorphism without a radical new language that is CSS but compiles to TypeScript classes and supports polymorphism.' That sentence IS the specification: a declaration written as a member is a named thing a subclass can replace, promote or leave alone; the same declaration inside a template is text. React never had an answer; chemistry does, because a chemical already inherits. THE THREE SPELLINGS are the reactive law read out loud, so the framework marks nothing — _background bakes, background is reactive, $background is a prop, highest wins nearest class first, and promotion is that rule used by a subclass. A GETTER IS A LIVE VALUE read per render and never baked, which is how a styled particle follows a theme where a bond-constructor assignment takes its value once. NESTED RULES ARE MEMBERS TOO, so &:hover and > *:first-child inherit and read the theme like anything else — two spellings compiling through one path, which is EXPRESSIVENESS rather than a thing said twice: the @select decorator, and the selector written into the name before its last colon. The CSS property is the last _-separated part, so any prefix frees the member name and is needed only when one class says the same property twice. A hand-written styled component may still occupy the selector, but everything inside it is invisible to inheritance, which is the reason not to. Seen in four Lab cases and seventeen promises.
