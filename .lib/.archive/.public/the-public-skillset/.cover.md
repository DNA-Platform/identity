**The verbs this branch can be asked to perform.** A [skillset](../../../../.claude/library/..environmentalism/04-on-skills.md) is a book whose chapters compile to slash commands, and this is the first one that lives in a branch rather than in the team's own library — because these skills are about **this code**, and they would mean nothing anywhere else.

Every chapter here is a **procedure that was first run by hand**, in a session, against a real browser — and then written down because doing it again from memory got it wrong. They carry the numbers the branch had when they were written, so a later run has something to beat, and they carry the traps that cost that session an hour each.

**What makes these branch skills rather than team skills** is that each one names files in `.public/package` and `chemistry/package` and would break if either moved. The team's [Our Skillset](../../../../.claude/library/our-skillset/.cover.md) holds the verbs that work in any repo; this holds the ones that only work here.

## Chapters

1. [public-audit](01-public-audit.md) — run every audit this branch has against a production build in a real browser, parse first and performance second, and report one verdict
2. [public-audit-performance](02-public-audit-performance.md) — measure what a page costs to open and prove a change made it cheaper WITHOUT making it wrong, gated on the rendered text being identical
3. [public-audit-parse](03-public-audit-parse.md) — confirm nothing renders all the way down: parts() is never called below a section, and the composition levels beneath it are never built
4. [public-audit-code-patterns](04-public-audit-code-patterns.md) — read the code against the conventions this branch wrote down and say where it does not cohere: ceremony means a missing framework feature, an ugly member means a feature in the wrong shape
5. [public-code-design](05-public-code-design.md) — A PRINCIPLE UNDER TRIAL, given by Doug 2026-09-08: LATERAL IMPLEMENTATION — lay out every part of a design at once as files of shells, every unbuilt member a not-implemented exception naming what it depends on and whether that was designed for it; build them top-down so each piece is designed for by the one before; mark every file FOUNDATION / CREATED / IN PROGRESS; keep the commit the system stood at so the experiment reverts in one command; take notes as code comments that drain into deletion or documentation — a file with no comments is done. TRIAL NOTES record what it did: consuming the level above found two selectors and a placement fault in minutes; the annealing pass corrected the class hierarchy on its first round; FIVE shells each throwing for a number named ONE missing base reading, and the fifth was then deleted; a shell that could not compile revealed that never-extend-the-kind-above governs the composition levels and not the reference kinds; and the failure — promoting three kinds into the framework for being declared twice INSIDE ONE APPLICATION, when promotion needs two applications and the app root was already the right home.
6. [public-audit-against-the-page](06-public-audit-against-the-page.md) — Compare what we draw against the real document IN NUMBERS rather than impressions, because 'that looks about right' and 'you are VERY far away' are the same sentence said by two people at one screen. CORRECTED 2026-09-10: read the PDF's TEXT LAYER, not its raster, wherever there is one - a raster screenshot is drawn below the viewer's toolbar, so it had been reading 44px low and nothing in the method said so; the text layer gives every glyph's coordinates in the document's own units, needs no calibration, and yields rows and columns from a two-line grouping. The raster still answers one question it cannot: colour. Ten values closed to a tick with it the day it was written.
