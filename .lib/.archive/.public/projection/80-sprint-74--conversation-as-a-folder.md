## <a id="analysis"></a>The analysis — ***what the ruling moved, and what it left standing***

***An exchange rising from section to chapter changes exactly one thing and it is the admission question.***

**At section grade the design needed `$TypeOfExchange` to be ANNOTATIVE** — declared `extends $Type` rather than `extends $TypeOfSection` — because [`$Composition.parts()`](../../package/src/writing/Composition.tsx) keeps a part only if it carries the holder's own level type or the level beneath, *so a level-typed exchange would have held exchanges and nothing else.*

**At chapter grade that problem is gone.** *A chapter holds only annotations and writes its document in `print()` — [`ChapterSpecification.$saysSomething`](../../package/src/library/Chapter.tsx) returns false and `$holdsOnlyAnnotations` says the rest — so a chapter's grade narrows nothing a conversation wants.* **`$TypeOfExchange extends $TypeOfChapter` is therefore the same move [`$Article`](../../package/src/encyclopedia/Article.tsx) already makes, and it is a LEVEL type.**

***The turn does not move: `$TypeOfTurn extends $TypeOfSection`, the same shape `$Aside` and `$Quote` have.***

### <a id="annotative"></a>WHAT ANNOTATIVE MEANS — ***Doug's correction, 2026-09-16, and this sprint had it wrong***

> ***Doug:*** **"They are parts. They don't understand what annotative is. It's a more abstract form of annotation."**

**The 2026-09-13 design called `$TypeOfTurn` ANNOTATIVE and meant only *stands outside the levels ladder*.** ***That is not what the word says, and the session that built from it repeated the error and then went and "measured" it.***

**`$Type extends $Annotation`, so EVERY type is an annotation** — `$TypeOfSection` no less than `$TypeOfFormat`. *What actually distinguishes the four the design listed is that they are types **of annotations**: `$Format`, `$Path`, `$Catalogue` and `$Fold` all extend `$Annotation`.* **And [`parser.tokens`](../../package/src/utilities/Parser.tsx) filters annotations OUT before the parse begins, so an annotation is never a part at all.**

***So a quote in a turn is a PART, and admission and annotation are two questions this sprint had crossed.*** **A turn is a composition; its type stands where the compositions' types stand.**

### <a id="artifact"></a>AND THE ARTIFACT DOUG SUSPECTED IS REAL, AND IT IS NOT THIS SPRINT'S

***Measured 2026-09-16 with existing kinds only, nothing changed:***


**By [`$Composition.parts()`](../../package/src/writing/Composition.tsx) as written, a quote inside an `$Aside` is neither the aside's own kind nor paragraph-grade, so it reaches the fourth clause — `reflection.above(kind, token.kind)` — and [that method is declared TWICE](#heads-three), with the parent walk winning.** *It takes one argument, reads `kind.parent`, and answers something truthy.* ***Every sibling specialisation of a level holds its siblings today for that reason and no other.***

> ***So the earlier entry in this chapter claiming the design's admission argument was false has been WITHDRAWN. It measured the bug.*** **The design was right: under the rule as written, a level-typed holder does not admit a sibling — and what happens to the refused part is worse than dropping. `parse` REDUCES an unaccepted writing into the level beneath, which is a section becoming a paragraph: the `<p><article>` shape [Sprint 73 shipped a fix for](../solutions/84-the-five-pages-that-were-all-one-book.md).**

***The consequence that matters: repairing `above` ALONE would break `$Aside`, `$Quote`, `$Box`, `$Infobox`, `$Navbox` and every other sibling specialisation, on pages that draw correctly today.***

## <a id="decisions"></a>Decisions — ***what was chosen, and over what***

- <a id="d1"></a>**D1 — THE NAME `$Resource` IS ON DISK ALREADY, WEARING THE WRONG ROLE, AND THE PLACEMENT TAKES IT BACK.** [`src/writing/Resource.tsx`](../../package/src/writing/Resource.tsx) holds a `$Resource extends $Code` that draws a file's text under a caption. **That is a VIEWER.** Doug's `<Resource />` is a PLACEMENT — *"a canonical placeholder to put it somewhere on the page or it will get appended as a section to the end."* **Two different things are wearing one name and the placement is the one he named**, so the placement becomes `$Resource` beside [`$Canonical`](../../package/src/library/Canonical.tsx) in `src/library/`, and what stands today moves to `src/resources/` as the viewer for a text file. ***Chosen over keeping the class where it is and naming the placement something else*** — which would spend Doug's word on the thing he did not use it for, permanently.
- <a id="d2"></a>**D2 — A VIEWER IS A KIND, CHOSEN BY THE FILE'S EXTENSION, AND THEY LIVE IN `src/resources/`.** One viewer per extension family, registered by extension. ***Chosen over one viewer switching on the extension***, which is the kind-conditional on a base that Doug has ruled against in the strongest terms: **the base declares the seam and the kinds override.** *A switch also makes a library unable to add a viewer without editing the thing it is adding to.*
- <a id="d3"></a>**D3 — A CHAPTER REACHES ITS RESOURCE THROUGH ITS DOCUMENT, NOT THROUGH THE FILESYSTEM.** `$Chapter` gains `resource` — the file standing beside it, already read. ***Chosen over the chapter reading its own folder***, which a browser cannot do at all and a binder should not be asked to do twice.
- <a id="d4"></a>**D4 — THE BINDER INJECTS THE TEXT AT ASSEMBLY.** Doug, 2026-09-16: ***"I would say direct injection probably makes more sense."*** The assembly already writes a module naming a book's chapters; it writes the raw import beside each one. ***Chosen over routing it through the scratchpad***, which is his own ruling and also one more place for the text to go stale.
- <a id="d5"></a>**D5 — EVERY LIBRARY, EVERY FILE — AND WHAT IS EXEMPT IS NAMED IN `.pubconfig` RATHER THAN GUESSED.** *[His ruling](#r-excluded), which took the strictest of the three offered and then supplied the seam that makes it survivable: a library says which of its own paths stand outside the build.* **A file in a book folder is the book, a chapter, or some chapter's resource — and the binder refuses otherwise.** Doug: ***"Something better break when you compile the app. It should. Please verify that it does and treat such things as build errors."*** **The seam is [`files()`](../../package/.binding/inventory/chapters.ts), which today filters to `.tsx`, keeps the apparatus and the numbered ones, and SILENTLY DROPS EVERYTHING ELSE.** *That silence is why `comments.tsx` and `resource.tsx` have never broken anything, and why `plate.tsx` next door did not either.* ***Chosen over a warning***: a library that is semantic has to compile, and a warning is a thing a build says while succeeding.
- <a id="d6"></a>**D6 — A `.tsx` THAT IS A RESOURCE IS NAMED `.tsx.pub`.** Doug's. *A chapter is a `.tsx` and so is a component; the extension alone cannot separate them, and [D5](#d5) needs it to.*
- <a id="d7"></a>**D7 — A CHAPTER HAS EXACTLY ONE UNNAMED RESOURCE; ANY OTHERS ARE NAMED BY THEIR TYPE.** Doug's. *So `<Resource />` with nothing said means the chapter's own file, which is the common case, and the rarer case pays the cost of saying which.*
- <a id="d8"></a>**D8 — prism-react-renderer, NOT highlight.js.** Doug's. **The tell is in the file we already have: it draws with `dangerouslySetInnerHTML`.** *A library whose whole subject is writing cannot reach its most code-dense page by handing React a string of HTML it did not build. prism-react-renderer returns tokens, and a token is a part.*
- <a id="d9"></a>**D9 — A COMPONENT A BOOK USES LIVES IN THE BOOK.** Doug: ***"Why is this something you can't put in a .book and import from the most logical place."*** *`comments.tsx` and `resource.tsx` fold into [`.book.tsx`](../../../../.me/.claude-and-our-projects/.claudes-importer/.book.tsx), which is the file a book's chapters already import from.* **This is what makes [D5](#d5) affordable rather than punishing** — the rule has an answer for every file it would refuse.
- <a id="d10"></a>**D10 — ONE CONVERSATION, AND NOT ITS DRESS.** Doug: *"we will focus on the importer and importing this one conversation, and we can talk about styling them later."* **[R8](#r8) is withdrawn to a later sprint and nothing in this plan styles a conversation.**
- <a id="d11"></a>**D11 — A RESOURCE IS NOT A PART OF THE LIBRARY, AND IT STILL CARRIES MEANING.** [His definition](#r-resource), given after a question of ours offered him LOCATION or QUOTATION and he refused both. **It accompanies a chapter · it has utility · it has many viewers · it has a location so something can address it.** ***Chosen over every attempt to file it under a kind the library already has*** — *it is not writing, not a chapter, not a mention and not a quotation, and forcing it into one of those is what produced the false choice in the first place.*
- <a id="d12"></a>**D12 — NO LOOK IS REACHED FOR WITHOUT HIS AGREEMENT.** [His ruling](#r-looks), standing and not confined to this sprint. *And the particular reach was worse than premature: `<Resource/>` already says where the thing goes, so a view invented to show it was answering a question he had answered.*
- <a id="d13"></a>**D13 — `..reference` IS A REFERENCE MANUAL, AND THE EIGHT FILES ARE ITS SUBJECT.** [His ruling](#r-manual). **The folder was already NAMED one and held only loose code, which is the whole of what was wrong with it** — *"That reference has to have meaning AS the reference."* ***And the shape did not have to be invented: the eight divide in two on disk already*** — **five are art, one uncoupled cover per book** (the painting and the logo cut from it, the log's nine entries as figures, the theory's domain of referents, the conversation's rubricated transcript, the seven arguments as a switchboard) — **and three are how the library is drawn at all** (the sheet, the apparatus, a chapter's glyph). *That is his "specifying how different books look, and then documenting it based on the code", already sorted.* ***Chosen over folding 1,606 lines into a 69-line `.book.tsx`***, which was the other answer on the table and would have made a dumping ground of the one file every book here extends.
- <a id="d14"></a>**D14 — `makes` BECOMES A UTILITY AND `$Type` LOSES A MEMBER.** [His ruling](#r-makes), taken over the `$TypeOfComposition` base this sprint recommended. ***The measurement that produced the question: `makes` is declared on [`$Type`](../../package/src/writing/Type.tsx) returning nothing, overridden by SIX classes that are all composition levels, and called from ONE line — [`$Composition.reduce()`](../../package/src/writing/Composition.tsx).*** **The six overrides stay where they are; what goes is the base declaration**, and with it the claim that every type in the library makes things. *A utility whose first parameter is the thing it is about is [the third face of polymorphic limiting](../the-coding-style/.cover.md), and it is the one he chose.*
- <a id="d15"></a>**D15 — A LOG IS AUTHORED FORWARD AND READ BACKWARD.** [His ruling](#r-reverse). *Entries are numbered in the order they are written, and drawn newest first; the table follows the same order.* **It belongs to the KIND of chapter rather than to the book**, in his words — *"for those types of chapters"* — which is the seam that keeps an ordinary book unaffected.
- <a id="d16"></a>**D16 — THERE ARE THREE THINGS HERE, NOT TWO, AND [D1](#d1) HAD TWO OF THEM CONFUSED.** [His correction](#r-viewing).
  - ***AND `<Resource>` IS RESOLVED BY THE BINDER, NOT AT DRAW.*** [His ruling](#r-viewer-build): *"Has to explicitly be somewhere, and the binder needs to find and replace it too."* **A pre-transform finds `<Resource>.ts</Resource>` in a chapter’s source and swaps it for the file the binder read.** *Asking for it at draw cost the library a day: the placement reached up for its chapter while that chapter’s own parts were being computed, re-entered the parse it stood inside, and killed `specify` at 291 seconds on a 4GB heap — one book taking all of `.me` with it, while the gate reported green from a cache that had never read the book.*
- <a id="d17"></a>**D17 — A RESOURCE IS IMPORTED BY ITS WHOLE FILENAME, ALWAYS.** *A chapter and its paint share a name by design and resolution prefers `.tsx`, so a short-form import silently reaches the CHAPTER.* **Measured twice.** *Once as `'./3-the-apparatus.tsx'`, which blanked the title, author and subject of every cover in the library at once; once as `'./4-the-chapter-mark'`, which surfaced at bundle time as "glyph is not exported by" — a long way from the mistake.* ***The double extension works imported in FULL and fails imported short, which is not what the first measurement seemed to say.***
- <a id="d18"></a>**D18 — A LIBRARY MAY NOT EXCUSE A FILE INSIDE ITS OWN BOOKS.** [His ruling](#r-gate). *`exclude` is for what a library HOLDS but is not MADE of — a checkout, an install, a folder of notes. A path standing inside a book is code the library ships and nothing documents, and excusing it is how a book stays wrong indefinitely while the gate reports green.* **That is exactly what was done with the seven components for a day**, and the rule now refuses it.
- <a id="d19"></a>**D19 — THE DOCUMENTATION IS THE PRIMARY ARTEFACT AND THE CODE CARRIES NO PROSE.** [His ruling](#r-no-comments). ***558 lines moved out of seven files into the chapters that document them.*** *What does not survive the move is a comment restating the code; what does is every ruling, measurement and caution — and one thing that could not have survived any other way: **a rule holding BETWEEN parts of a file has nowhere to live once the file is split**, which is the plate’s boundary rule and the strongest argument in the book for why a manual exists.*
  - ***`$Resource` is the PLACEMENT***, derived from [`$Canonical`](../../package/src/library/Canonical.tsx) — a mention that names a thing and draws what it says. **So the resource is named as CONTENT and never as a prop**: `<Resource>.tsx</Resource>`, which is his own instinct — *"Maybe `<Resource>.tsx</Resource>` would be more appropriate if we did, but no need to skip right? Why did you? Rethink."* ***[D7](#d7)&rsquo;s `type=` prop is struck by this.***
  - ***`$Source` is the PAGE&rsquo;S OWN SOURCE***, in the sense Wikipedia uses it — a page linking to itself as text. **It is always self-source, so it can never be the viewer for a resource file.** *[R14](#r14) described a link to a resource and was wrong about which word that is.*
  - ***AND THE CODE VIEWER IS A KIND OF [`$Code`](../../package/src/writing/Code.tsx), standing beside `$Source` and using the same tools.*** **It already exists** — [`src/writing/Resource.tsx`](../../package/src/writing/Resource.tsx) is exactly this: a file&rsquo;s text drawn under its own name. ***Only the name was wrong, and it was wearing the placement&rsquo;s.*** *Proxied as `$Listing`, which is the printing trade&rsquo;s own word for a program shown from a file — prior art rather than a coinage — and flagged for him.*

## <a id="risks"></a>Risks

- <a id="k1"></a>**K1 — EVERY `.me` PAGE IS AN 854-BYTE SHELL AND THE BUILD IS GREEN.** `<div id="root"><!--$!--><template></template><!--/$--></div>` is React's errored-suspense marker: **the SSR render throws and the binder reports success.** ***This is the trap that says a green build says nothing about a page, and it invalidates the visible end of nearly every unit below it.*** **Mitigated by making it [U6](#u6) and refusing to measure anything else until it draws.**
