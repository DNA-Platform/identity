---

This is the cataloguing book for the branch library beside the altered-states code, `src/.lib`. It spans
all of `src/`: the pipelines, the analyses built on them, the environment they run in, and the machine
they run on. It records what the team learned building and running that code: why the code is shaped as
it is, the rules it keeps, what broke and what was measured.

It is not the code's documentation. What each folder does is written in that folder's own `.cover.md`,
beside the code, for anyone who clones the project, and it names no teammate. This branch is the team's
own record. The team is named here, and the branch travels with the team's identity, not with the
project ([Library Tree](../../../.claude/library/library-tree/01-branches.md)).

The science the code serves has its own branch, [Altered States](../../../library/.lib/..altered-states/.cover.md),
beside the project's library: the experiment, the data, the literature, and the sprint-by-sprint record
of all the work.

## Books

### [Computation](.cover.md) — Computation

You are reading it. It catalogues itself, because this book is the branch.

### [Projection](../projection/.cover.md)

The branch's sprint book, empty so far. Every sprint up to now, including the ones that built the
pipelines, is in the [Altered States Projection](../../../library/.lib/projection/.cover.md), because
until now the code and the science were planned together.

### [The Pipelines](../the-pipelines/.cover.md)

How the work is computed now: `matched`, `digital_twin`, `mei` and `metamer` in `src/pipelines/`. Each
is one entry point that reads only the finished products of the one before, and they run as one chain on
the lab box. The book covers:
- why the work went back to pipelines on the new machine;
- what each pipeline does;
- the rules every one follows: the manifest as authority, products that know the twin that made them,
  published code on the published frame with no settings, each session in its own units, performance as
  correctness, and labels as claims;
- how their folders are organized, and the tree Doug walks to show the work, with his rulings verbatim.

Authored by Arthur, with Nancy and me.

### [The Build](../the-build/.cover.md)

How the analysis is built and run: a side-by-side Python 3.11 via uv, the pip-tools-locked venv, the
torch plus Sensorium-triple stack and the six failures it fought, the code's organization, the
disk-bound FileTreeDataset loading, the digital-twin and MEI recipes, and reproducibility. Authored by me
from Adam's build; Adam is the domain source.

### [The Lab Box](../the-lab-box/.cover.md)

The lab's Linux GPU machine, `lipshutzlab-01`, and how the team works on it from here:
- what failed on the way in (ProtonVPN's kill switch refusing the tailnet);
- the box as surveyed and brought up, an RTX 5080 with 16 GB and its Python proved package by package
  against this machine's;
- parity between the two machines;
- **working remotely**: the team writes and commits on Doug's machine, the box pulls and runs, and every
  piece of work is a run on its own branch, closed back into `main`.

Authored by me; David is the domain source. The protocols themselves are the `/als-remote` skill.
