## <a id="facts"></a>The mechanics, read 2026-11-06

- **An annotation is a writing.** `$Annotation extends $Writing` in the package's `src/writing/Writing.tsx`: it has its own text and its own annotations, holds what it is told as content, and its `view()` draws `note()`, which is null, so it draws nothing unless a sort says otherwise. A writing's children that are annotations go into its `annotations`, the rest into its `text`.
- **A message is addressable.** The conversation's code stamps every message with a Referent made of its instant and its speaker, `identifier.slug(when + said)`, so `$[[ #<that> ]]` names a message.
- **A reference inside an annotation is read.** The catalogue scans a chapter's prose runs for the notation wherever they stand, `catalogue/annotations.ts`, and the bind refuses a reference that resolves to nothing. A mention, `[[[ X ]]]`, names a writing where it stands, which is how one annotation can be referred to by another.
- **A view reads the model through expressed annotations**, as the register reads a cover's Period and Messages, `annotations.expressed($Messages)?.shown`.
- **The ledger already finds a book by its Origin.** `importRecords` reads every book on disk for the Origin on its cover and keys the line by the conversation's id, Sprint 122; what a rename needs is proven, not built, unless the proof fails.

## <a id="decisions"></a>Decisions

- <a id="d1"></a>**D1. The base moves with its kin, and the rest stays this sprint.** `$Annotation` and `AnnotationSpecification` leave `src/writing/Writing.tsx` for `src/annotations/Annotation.tsx`, and the three annotations defined in that same file today, `$Parenthetical`, `$Narrative` and `$Blank`, go with it, one word a file, since the folder is where annotations live and three left behind in the writing's file would be the wart the move is meant to end. The `Annotations` collection stays in Writing.tsx beside `Text`: it is the writing's, as `Text` is. The annotation words that already have files of their own under writing, Referent, Reference, Append, Date, Format and Theme, stay where they are, on his *"Let's not do too much ahead"*; whether they follow is his to say at the yes, and is flagged there. Chosen over moving only the five sorts, which would leave the base where he said it should not be.
- <a id="d2"></a>**D2. The cycle is declared, not hidden.** An annotation is a writing and a writing is made of annotations, so Writing.tsx and Annotation.tsx import each other; the package already carries three such cycles, Chapter with Title, Chapter with Part, Section with Heading, each named in rollup's `knownCycles` with the reason it cannot be broken, and an undeclared one throws at build. This is the fourth, named with its reason. Because the base extends the writing at load, the subclass's file must be entered first: `src/index.ts` exports the annotations folder before the writing folder, the line saying why, and a promise that builds a writing with each sort from the dist fails loudly at import if the order is ever wrong. Chosen over a marker protocol that would let Writing.tsx recognize an annotation without naming the class, which is a workaround for a cycle the package already knows how to declare.
- <a id="d3"></a>**D3. A sort is Blank-shaped with text.** Each of Note, Comment, Thought, Reaction and Description extends `$Annotation` directly, no base of its own between, marks its class on the writing it annotates, `pa-note` and so on, in `defines` and reverts it in `erase`, and draws nothing, which the base already does. What it holds is its text, read as any writing's, `html.copy(this.text)`. No specification of its own this sprint: the sorts exist semantically, as he said, and an empty note is allowed until a conversation shows that it should not be. Chosen over a shared sort base, which would be an abstraction ahead of its second use.
- <a id="d4"></a>**D4. References inside an annotation are written as references are written in prose.** A reference to a message is a word with `$[[ #<referent> ]]`, the referent the one the conversation's code stamps on every message; a mention `[[[ name ]]]` names an annotation so another refers to it by `$[[ #name ]]`. The catalogue reads a chapter's prose runs wherever they stand, so nothing is built for this; U3 proves it on a real chapter, including the bind's refusal of a bad one.
- <a id="d5"></a>**D5. Annotating happens in the chapter's file, in the room, with the page open.** His workbench serves the library live from its files; a save shows in a quarter of a second, a look reads the page. The bind, under the 10 GB heap and about ten minutes, is the gate at the end of a unit, never the way to look during one.
- <a id="d6"></a>**D6. A cut chapter takes a journal entry's head.** Where a conversation is cut, each chapter is a file `n-<slug>.tsx` holding a `Part` where parts make sense, a `Dated` date of its first message, a `Title` as he likes, and then its messages moved verbatim with their Origins, Speakers and instants; the table lists them under sections headed with the parts' names. The cover is untouched, so the register and the project pages read it as before, and the importer's check reads every numbered chapter of a book, so the pairing against the export still runs over all of them.
- <a id="d7"></a>**D7. The ledger is proven, not changed.** Its promise already keeps one ledger keyed by id and finds the book by its Origin wherever it stands, rename and all; organizing marks a book edited at the next writing run, which is the truth. U7 reads the listing and cites the promise; code is written only if the listing is wrong.

## <a id="risks"></a>Risks

- **The cycle bites at load.** If the bundle's order puts the base before the writing, the package fails at import with a ReferenceError; D2's promise makes that loud and the barrel's order is the mitigation. If the order cannot be held, the fallback is said here and not taken silently: the base stays in writing with the sorts in the folder, and he is told why.
- **The read-back refuses a link into an undrawn annotation.** A mention inside an annotation names a writing the page never draws, so a `$[[ #name ]]` from another annotation may fail the bind's link check. U3's third scenario decides it; if it fails, references between annotations wait for a view that draws them, and the chapter says so.
- **The bind's weight.** About ten minutes under the 10 GB heap per bind, with the browser and the workbench closed first; one bind per organized book, never one per annotation.
- **The chapter's size.** Goldbach through Godel is 2.2 MB in one file; edits are placed by a message's Origin, which is unique, and a cut moves whole Message elements. The editor and the tools can hold it; the workbench's watch may be slow to settle on a save, measured at U5.
- **The marks.** Every organized book reads edited at the next listing, which is right, and a `--write` run without `--reimport` leaves it alone; the promise of Sprint 122 says so and U7 reads it again.
