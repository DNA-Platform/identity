## <a id="facts"></a>The mechanics, read 2026-11-06

- **An annotation is a writing.** `$Annotation extends $Writing` in the package's `src/writing/Writing.tsx`: it has its own text and its own annotations, holds what it is told as content, and its `view()` draws `note()`, which is null, so it draws nothing unless a sort says otherwise. A writing's children that are annotations go into its `annotations`, the rest into its `text`.
- **A message is addressable.** The conversation's code stamps every message with a Referent made of its instant and its speaker, `identifier.slug(when + said)`, so `$[[ #<that> ]]` names a message.
- **A reference inside an annotation is read.** The catalogue scans a chapter's prose runs for the notation wherever they stand, `catalogue/annotations.ts`, and the bind refuses a reference that resolves to nothing. A mention, `[[[ X ]]]`, names a writing where it stands, which is how one annotation can be referred to by another.
- **A view reads the model through expressed annotations**, as the register reads a cover's Period and Messages, `annotations.expressed($Messages)?.shown`.
- **The base is the thing he described, proven 2026-11-06 by a probe against the dist** on his question *"Is an annotation what I am describing now? Will it work for this? … Annotation needs to be able to go anywhere I think"*: a bare Annotation holding words, placed as a child of a paragraph, a word, a section and a chapter, went into that writing's annotations and not its text, kept its words as its own text, answered null to `note()`, and the page drew the writing's words alone; one inside another held its own words and the inner in its annotations; two on one paragraph were both held, newest first, since `add` prepends. Referent and Reference are the reference machinery, annotations to the framework but not commentary; they stay in writing, and if that chunk moves its folder is called reference, his word.
- **The ledger already finds a book by its Origin.** `importRecords` reads every book on disk for the Origin on its cover and keys the line by the conversation's id, Sprint 122; what a rename needs is proven, not built, unless the proof fails.

## <a id="decisions"></a>Decisions

- <a id="d1"></a>**D1. The base moves with its kin, and the rest stays this sprint.** `$Annotation` and `AnnotationSpecification` leave `src/writing/Writing.tsx` for `src/annotations/Annotation.tsx`, and the three annotations defined in that same file today, `$Parenthetical`, `$Narrative` and `$Blank`, go with it, one word a file, since the folder is where annotations live and three left behind in the writing's file would be the wart the move is meant to end. The `Annotations` collection stays in Writing.tsx beside `Text`: it is the writing's, as `Text` is. The annotation words that already have files of their own under writing, Referent, Reference, Append, Date, Format and Theme, stay where they are, on his *"Let's not do too much ahead"*; whether they follow is his to say at the yes, and is flagged there. Chosen over moving only the five sorts, which would leave the base where he said it should not be.
- <a id="d2"></a>**D2. The cycle is declared, not hidden.** An annotation is a writing and a writing is made of annotations, so Writing.tsx and Annotation.tsx import each other; the package already carries three such cycles, Chapter with Title, Chapter with Part, Section with Heading, each named in rollup's `knownCycles` with the reason it cannot be broken, and an undeclared one throws at build. This is the fourth, named with its reason. Because the base extends the writing at load, the subclass's file must be entered first: `src/index.ts` exports the annotations folder before the writing folder, the line saying why, and a promise that builds a writing with each sort from the dist fails loudly at import if the order is ever wrong. Chosen over a marker protocol that would let Writing.tsx recognize an annotation without naming the class, which is a workaround for a cycle the package already knows how to declare.
- <a id="d3"></a>**D3. A sort is Blank-shaped with text.** Each of Note, Comment, Thought, Reaction and Description extends `$Annotation` directly, no base of its own between, marks its class on the writing it annotates, `pa-note` and so on, in `defines` and reverts it in `erase`, and draws nothing, which the base already does. What it holds is its text, read as any writing's, `html.copy(this.text)`. Each sort has a specification of one promise, read as a sentence that says what the sort holds, a note what was noted of its writing, a comment what was said about it, a thought what it prompted, a reaction how it struck the reader, a description what it is, and the one check is that it holds words, so the bind refuses an empty one by name; revised at his yes, *"lets make sure to define annotations thoughtfully"*, from no specification at all. Chosen over a shared sort base, which would be an abstraction ahead of its second use.
- <a id="d4"></a>**D4. References inside an annotation are written as references are written in prose, and they are to mentions.** <a id="u3-finding"></a>Corrected by U3 on 2026-11-06: a message's referent, `2025-10-12t13-49-30-842226-doug`, is stamped by the conversation's code at define and the catalogue reads only names declared in source, books, chapters and mentions, so `$[[ ]]( #<referent> )` is refused as a book called that; and an annotation draws nothing, so a raw address inside one would be checked by nobody, the proof judging only drawn anchors. The language's own route holds: an annotation names itself with a mention, `[[[ His instruction ]]]`, and another refers to it with `$[[ ./His instruction ]]`, the catalogue refusing an unknown name and a name nobody spends; a message is reached through the annotation that names it, which stands in the message's annotations. Whether messages should become names the catalogue holds, a silent naming form in the language the import could write per message, is a pitch for him and not this sprint's.
- <a id="d5"></a>**D5. Annotating happens in the chapter's file, in the room, with the page open.** His workbench serves the library live from its files; a save shows in a quarter of a second, a look reads the page. The bind, under the 10 GB heap and about ten minutes, is the gate at the end of a unit, never the way to look during one.
- <a id="d6"></a>**D6. A cut chapter takes a journal entry's head.** Where a conversation is cut, each chapter is a file `n-<slug>.tsx` holding a `Part` where parts make sense, a `Dated` date of its first message, a `Title` as he likes, and then its messages moved verbatim with their Origins, Speakers and instants; the table lists them under sections headed with the parts' names. The cover is untouched, so the register and the project pages read it as before, and the importer's check reads every numbered chapter of a book, so the pairing against the export still runs over all of them.
- <a id="d7"></a>**D7. The ledger is proven, not changed.** Its promise already keeps one ledger keyed by id and finds the book by its Origin wherever it stands, rename and all; organizing marks a book edited at the next writing run, which is the truth. ## <a id="method"></a>The reading's method — written 2026-11-06 on his question, "What is your goal. How do you know you understand it?"

**The goal.** To understand each conversation well enough to represent in it what he holds important, as marks in the chapter: its narrative, where it turns, what it reaches, what it defines, where he set the course straight, what he treated as mattering, what it left open. Enough that the conversation can be taken apart into chapters titled and summarized as he would title and summarize them, and later filed into the mathematics project by what it reached. He cannot read 154 messages; he can read a page. The reading exists to give him that page, true to the conversation, and the marks are how the page is earned and checked.

**What his importance looks like, and where it is read.** His side of the conversation is the signal and Claude's side is the material. He corrects, *"No you don't have it right at all"*: a Correction, and the thing corrected is important by that fact. He insists or exclaims, *"THERE IT IS"*, *"I really like"*, *"we should feel free to note it for future theorists"*: an Importance, with his words as the why. He returns to a thing, asks it twice, or names it, *"Why not context-free binary!"*: a Formalism where it is named, an Importance where it recurs. He says *"so then we found"*, *"we have shown"*, *"that shows the symmetry"*: a Result. He says *"huh"*, *"That's weird. I wonder why"*: a Question. Claude's *"YES, This Is Brilliant"* is never evidence of importance; Claude's replies are read for the formalism and the results they state, which are the material the marks name. What survived into later work is the strongest sign: a thing of this conversation that recurs in Goldbach through Godel a year later, or in the project's documents, is a Reminder, carried forward.

**How a mark is placed.** On the smallest writing it is about, a paragraph where one paragraph carries it, else the message. A Result or a Formalism names what it marks with a mention, `[[[ G(n) ]]]`, so later marks refer to it, `$[[ ./G(n) ]]`, and the connections are in the model. A Turn says what the subject turns to, and every Turn is a candidate chapter; an Idea beside it proposes the title in his words, since the titles should feel like his. Every stretch between Turns gets a Summary, what it came to. Marks are disposable, as he said: after the cut the Turns and the Ideas that became titles go, the Summaries become the chapters' synopses, and the Results, Formalisms, Corrections, Importances, Questions and Reminders stay as the annotated edition.

**How I know I understand it.** Five checks, in order. One: I can write the conversation's narrative on one page, what was asked, where it turned, what was reached, in order, every sentence anchored to a message by its marks. Two: every Result and Formalism is stated in the conversation's own terms, G(n), context-free binary, Array of Set, and I can say what each is without the conversation open. Three: the Turns I mark fall where he changed course, checked against his own Corrections and Importances, never against Claude's enthusiasm. Four: the audit, a second reading of every mark against its message by me, with the first reader's marks removed or rewritten where they are wrong and the stretch boundaries reconciled where a Turn falls at a worker's edge. Five: his, on the page: the narrative and the proposed titles read to him, and the titles feel like his or they are changed. Only he can make the fifth check, and it is the one the others exist to earn.

**The process.** First, a thorough first pass by workers off to the side, each a teammate reading a stretch whole, both sides of it, writing their marks and a report of the stretch, its narrative, its turns, candidate titles and a summary, into a file of their own in the scratchpad, never the chapter, so no two write one file. Second, the audit: I read every mark against its message and every report against the marks, and write the surviving marks into the chapter at their messages. Third, the narrative on one page from the audited marks, discussed by the team, read by him, his word on the turns and the titles. Fourth, the cut at his turns, the spent marks removed, the kept marks in place, the book specified, bound and seen, the importer's check clean. The Sonnet conversation first, 154 messages in four stretches at the turns the shape showed, 1 to 18, 19 to 54, 55 to 116 and 117 to 154; then the other three of the family by the same method, Goldbach through Godel in more stretches.

## <a id="risks"></a>Risks

- **A reader runs out of room.** A stretch of 60 messages of Claude's long replies is a third of a megabyte; a reader who cannot hold it writes marks on what it skimmed. Mitigation: the brief says read whole and prefer fewer marks; the audit reads every mark against its message and strikes the ones that do not hold; a stretch that defeats its reader is split and sent again.
- **The audit is the whole conversation read by one voice.** 154 messages read against their marks is most of the conversation read by Arthur across turns and compactions. Mitigation: the audit ledger in the scratchpad and this chapter carry its state, mark by mark, so a compaction loses nothing; the 805-message conversation's audit is planned in sittings of two stretches.
- **A mark is placed on the wrong writing.** The placing script keys on the message's `at`, which is unique, and the paragraph's index, which a reader may miscount. Mitigation: the script refuses an `at` it cannot find and a paragraph index past the message's count, saying which; the look after placing reads the message.
- **The specify refuses the placed marks.** A mention named twice, a reference misspelled by a letter, an unspent name: all seen at U3. Mitigation: the audit normalizes names before placing and the specify runs before the look; a refusal is mended, not routed around.
- **The cut breaks a reference.** A mention in one new chapter and its reference in another resolve within the book, `./name`; a reference written to a chapter by name would not survive a rename. Mitigation: U12's scenario runs the specify after the cut.
- **The cycle bites at load.** If the bundle's order puts the base before the writing, the package fails at import; D2's promise makes that loud and the barrel's order is the mitigation. If the order cannot be held, the base stays in writing with the sorts in the folder, and he is told why.
- **The bind's weight.** About ten minutes under the 10 GB heap per bind, with the browser and the workbench closed first; one bind per organized book, never one per mark.
- **The chapter's size.** Goldbach through Godel is 2.2 MB in one file; edits are placed by a message's `at`, which is unique, and a cut moves whole Message elements. The workbench's watch may be slow to settle on a save, measured at U5.
- **The marks in the ledger.** Every organized book reads edited at the next listing, which is right, and a `--write` run without `--reimport` leaves it alone; the promise of Sprint 122 says so and U7 reads it again.
