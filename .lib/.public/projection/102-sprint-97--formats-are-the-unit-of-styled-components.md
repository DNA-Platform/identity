## Where this sprint comes from

**The grade found it.** [Sprint 96](101-sprint-96--the-librarians-grade.md) read Libby's library at the manual's spreads and found one pattern under every fight: a kind of writing has no look of its own and an annotation's look lives in the Theme's sheet, so the sheet grew to a hundred rules by a promise that it comprehend every class, and a library dressed its marks by a hundred more. Doug, on seeing the sheet: *"i was shocked to see the mess of our current theme."* The standard was read in its own words — *"every bit of styling is tied to a specific component"*, a global sheet for *"resets or base stylesheets"* — and a trial that componentized a kind was built and struck within the hour, because it read the standard wrongly.

**His sentences, which are the requirements.** *"We ARE using styled components, so let's use them right."* · *"Can't we have both? Format adds classes and styles, and overriding can happen at either layer?"* · *"The classes don't have to be removed for the styled component to target locally with them."* · *"It shouldn't be so hard to write styled components to override the format of components. Just subclass an annotation and rewrite its style. That's not much harder than writing a styled component to begin with right?"* · *"No you don't need DI!"* · *"Just rewrite the annotation and use yours!"* · *"Style the semantic compositions in the theme, but for the annotations, shouldn't we make them self-contained?"* · *"The right way ISN'T one per page."* · *"Why can't formats be the unit of styled components? And one subclasses a Format and overrides the style to change things? You can subclass many things easily. We document what one might want to subclass? I would think that much of the styling would come from the custom book and theme, and all of the basics can be styled in a sheet. Annotations tend to be formats and carry their own style, and they can easily be subclassed."* · *"It shouldn't be hard to subclass an annotation, export it with the same name and just draw from the one exported in the library, so it's still Table, and just do a sort of by-name replacement. These are what styled components look like just with a format wrapper."* · *"This is an OO framework and one massive string styled component stylesheet might as well literally be CSS. So please come up with a sensible split for what should be in a theme, what should be modular formats, and what overriding the style looks like across the library."*

**The split he asked for** is [in Sprint 96's chapter](101-sprint-96--the-librarians-grade.md#the-split), rule by rule from the sheet as it stands: 26 `pd-` rules, 24 `pa-`, the invariants, the highlighter's four, the twelve generated starts and spans. **His three questions on it, answered there with their state:** it is natural by the three tests and Libby's own existing patterns; the theme and components will be documented as what one subclasses; her library handles it with four Formats in her door and one import line in twenty-five files.

## <a id="libby"></a>What it looks like for Libby to create her library

*In order, the files she writes, each in her own words — the shape of the design seen from the only place it is tested. The code below is what her door would hold, as a sketch for his reading and not the implementation.*

**1. Her door, `manual/.book.tsx` — the one file every other book of hers imports from.** First the eight, as values: `class $LibraryValues extends $Theme { font = …; ink = …; paper = …; link = … }`. Then her typography for the seven levels and their kinds, uniform, extending the base sheet with no cast and no helper — `class $LibraryTheme extends $LibraryValues { override style = selection(this.style)\` .pd-canonical.pd-chapter { counter-increment: chapter; } .pd-chapter .pd-title::before { content: 'Chapter ' counter(chapter); … } .pd-code { … } \` }` — every selector a `pd-` mark, since these are what her writings are. Then her four Formats, each a styled component with a format wrapper, each exported under the framework's name so a chapter's word is hers by import:

```tsx
export class $LibraryCover extends $Cover {
    override style = selection.header`
        .pa-cover:not(.pa-framed) { padding: …; background: color-mix(…); border: …; }
        .pa-cover .pd-title { margin-block: 0 calc(${({ theme }) => theme.space} / 2); }
        .pa-cover .pd-title::before { content: 'Cover'; }
    `;
}
export const Cover = $($LibraryCover);
export class $LibraryTable extends $Table { override style = selection(this.style)` .pa-col { border-block-end: 1px solid …; } `; }
export const Table = $($LibraryTable);
// and TableOfContents, Synopsis the same way; Framed, Literary, Typewritten, Navigable as they are today
```

Then her Book — `class $TheLibrary extends $Book`, its `write()` drawing the running head and the byline, its `$Define` standing `<Navigable />` and `<LibraryTheme />` — and her words, Catchword, RunningHead, Byline, Label, as today.

**2. Each book's `.book.tsx`:** `export default class $APaper extends $TheLibrary { … }` — as today; Libby's stands `<DarkTheme />` in front, `class $DarkTheme extends $LibraryTheme { ink = 'ivory'; … }`; Some Projects stands the framework's `<Theme />` in front and shows the base.

**3. Each chapter:** `import { Chapter, Cover, Table, TableOfContents, Synopsis, Catchword } from '../manual/.book'` for her words and her Formats, and the kinds — Paragraph, Section, Title, Heading, Word — from `@dna-platform/public`, since a kind is never replaced. One import line, twenty-five files.

**What she does not write:** a cast; a fallback for a value the theme provides; a rule for a framework `pa-` mark in her sheet; a registration; a change to any framework file. **And what she grades it by:** her door reads as a theme of values, a sheet of her typography, and a few styled components with format wrappers — which is what a styled-components application looks like.

## <a id="plan"></a>The plan — guardrails, 2026-10-01

### <a id="decisions"></a>Decisions

- <a id="d1"></a>**D1 — A Format's template carries the rules for its own marks, reaching them by descendant and never by child.** The layer is a scope wearing `pd-container`; the marks stay on the writing's own elements, as the trials of Sprint 95 ruled; the template says `.pa-table { display: grid }` under its own class. By descendant because the front-most annotation draws innermost, so a Format added in front of Table draws *inside* Table's layer — his fact of 2026-09-30, *"the next level that you care about is still below and you don't know how many layers below it is."* *Chosen over* a kind's own styled component, the trial built and struck; over an entry per kind on the theme, which subclassing already is; and over gathering rules from annotations into the sheet, a mechanism the by-name replacement makes unnecessary.
- <a id="d2"></a>**D2 — Table and List become Formats lending a scope-layer; the grid stays on the section's own element.** Superseding [Sprint 95's U4](100-sprint-95--pages-formats-and-words.md#u4), *"Table lends no layer"*, on his sentence that annotations tend to be formats and carry their own style — a layer that wraps is not the replacing he struck, and Table still swaps nothing. Synopsis gains a layer for the same reason: its look, italic paragraphs, needs one. *Chosen over* keeping the three as annotations and their looks in the sheet, which is the mess.
- <a id="d3"></a>**D3 — The sheet keeps only what has no class to live in.** The tokens, the frame, the invariants — meaning with `!important` in their own layer, so no library's override reaches them — and the base typography of the levels and kinds. Biography's and Autobiography's title looks leave the base with no look, since they are a library's; Paginated's margins go with it and its hiding stays an invariant; Append's white space goes to Append. The promise splits: the sheet comprehends `pd-`, each Format its own `pa-`. *Chosen over* the base keeping a readable default for annotations' layouts, which he did not ask for.
- <a id="d4"></a>**D4 — Overriding is five moves and no registry.** Values by subclassing the Theme; the basics by extending its `style`, the one selector a library writes for a kind; a Format's look by subclassing it, rewriting `style` and exporting under the same name from the library's door, a chapter's word being the library's by import; a kind in context by a Format's template under its own class; a new look by a Format of the library's own. *Chosen over* chemistry's `$(Host, Kind)(Replacement)`, his *"No you don't need DI!"*
- <a id="d5"></a>**D5 — A subclass rewriting `style` replaces the base's component; one extending it appends.** Both unlayered, so both beat the sheet; a rewrite carries no rule of the base's, which is what a replacement means. The layer order statement stays the Theme's.
- <a id="d6"></a>**D6 — The theme's type is the eight, present.** `DefaultTheme extends Values`; the augmentation stays in Theme.tsx, where a library's declarations are bundled from, since a standalone `styled.d.ts` nothing imports is dropped by the dts bundle — the standard's file is for an application. A promise that draws a writing bare draws it under the framework's Theme, the standard's practice for a test, as the trial taught.
- <a id="d7"></a>**D7 — Libby's library is the measure, and Some Projects the base's context.** Four Formats in her door, her chapters importing them, the cast and `at()` gone; Some Projects standing the framework's `<Theme />` in front, the singular rule taking hers out of expression, so one page shows the base — her decision as the librarian, his library's reader the reason.
- <a id="d8"></a>**D8 — The two marks are the classes' own.** Section marks its opening paragraph at the bond, as Table marks rows; Paragraph marks itself a stanza in its define when every part is a Line; names by the pattern, flagged.
- <a id="d9"></a>**D9 — Measured as Sprint 95 measured:** every page photographed before and after and diffed pixel by pixel; paints counted by `renders.test.tsx`; the sheet's rules counted in the layer before and after; her theme's lines; the suites at their counts; the manual's theme spread on 4242 for his sign-off.
- <a id="d10"></a>**D10 — Performance is a gate, measured by one method before and after** (A7). What the design costs by construction, read before measuring: one generated class per Format *class* per bind and never per instance, as every Format is today, since a styled component is a field; one scope `div` per table, list and synopsis instance, a plain element in `view()`'s reduce and no chemical, so no draw and no paint; rules that move and do not multiply — a subclass that rewrites `style` emits its own rules and not the base's, one that extends emits both, and a page uses one; nothing new in the bond, nothing read per draw. What is measured, on the galley before U1 and the galley after U7, by [Sprint 95's probe method](100-sprint-95--pages-formats-and-words.md#u5) and the regression's bytes: the persona's and the manual's page bytes and sheet bytes; the generated classes counted in each book's sheet file; the DOM's nodes on the persona against 194; draws and paints per change; and the manual's page turn, both galleys in one run, three turns each — the measurement [Sprint 96](101-sprint-96--the-librarians-grade.md#u3) owes, closed here. *Chosen over* believing the construction: the numbers are said.
- <a id="d11"></a>**D11 — Uniform for `pd-`, componentized for `pa-`** (A5). The seven levels and their kinds are dressed by the theme's one sheet, holistically, because a book's typography is one thing and a librarian wants to set it in one place; every annotation is a Format carrying its own look, because what is said of a writing is modular by nature and is what a library swaps. The prefix he gave on 2026-09-22 is the split. *Chosen over* componentizing the kinds, the trial, and over leaving annotations' looks in the sheet, the mess.
