## Where this sprint comes from

**Doug, 2026-09-28, verbatim, questioning the figures:** *"Hmm, questioning our approach to figures. We might want to go back to our template language, and give more flexibility: `{{{ this }}}` … `{{{ whatever.tsx }}}` — And then an implementer can USE Append if they like as a way of inserting it in, but that is not the only way. Now we have to choose the bracketing right. What should mean: request my own representation? We need to demonstrate it's very different and even a whole different id system than the library references. What do you think? Any ideas? Maybe show existing syntax and your recommendation for new syntax."*

**What the room answered, and why braces cannot be it:** since [Sprint 90](95-sprint-90--the-binder-reads-with-the-parser.md) the binder reads the notation through the TypeScript parser, in JSX text and strings; `{{{ this }}}` in JSX is an expression holding an object literal that does not parse. Any character but `{ < > }` is open in JSX text, so the form is a sigil before brackets, as every form is. The room recommended `!`, markdown's own sigil for the one form that inserts rather than links, and `this` for the chapter's own file. **A correction owed him, made in the room:** the referring form today is `$[ X ]`, one bracket; the count of brackets has meant one refers, two titles, three names a place.

**His rulings, verbatim.** On the sigil: *"I Like ! but could it really mean something similar to what we are talking about here? We also want to support cross chapter… We do `$[[ ]]` — do we not? We should stick to two."* On the brackets, asked plainly: **`![[ … ]]` and `$[ ]` becomes `$[[ ]]`.** On the self word: **this.** On a words half: *"Nothing. This inserts a whole file in. No need to be anything else but what it is."* On reaching across chapters: *"Name on disk, but... let's not have it go across chapters. If it goes across chapters, it has no meaning which chapter its associated with. So: `![[ this ]]` And `![[ id.type ]]` And the compiler can now enforce that all resources are used."* On Append and Figure: *"Move Append to writing, as it's related to appendices, and a chapter writing can use Append if they want, or can do other things. Figures can read that if configured, but one might also just `![[ ]]` into the figure, and it should be the kind of thing where `<MyFigure> ![[ this ]] <MyAnnotation /> </MyFigure>` would parse correctly."* On the binder appending: *"No, append is the authors. You remove the flexibility if you have the binder do it. The binder can and should guarantee that every resource file (except this, which is optional) must be specified."*

### Decisions

| | decision | why, and what it was chosen over |
|---|---|---|
| **D1** | **The language's table gains the literal family, and the referring form takes two brackets.** `$[[ X ]]` refers; `![[ this ]]` and `![[ id.type ]]` insert; the bracket run of either is captured as one to three and refused unless it is two, so `$[ X ]` and `![ x ]` are malformed by name and never silent. The annotating forms are untouched. | Doug: *"We should stick to two."* Silence is the one outcome the language forbids; a one-bracket reference left unread would compile to nothing and look like prose. |
| **D2** | **A literal is read in prose only.** The scanner yields a fourth list, the literals, from JSX text runs; a literal in a string literal is refused, since a splice into a quoted string would have to escape for the quote it stands in and the form was made for text between tags. | Doug's parse case is JSX text: *"`<MyFigure> ![[ this ]] <MyAnnotation /> </MyFigure>` would parse correctly."* Over splicing into strings with per-quote escaping, which is a second rule for a case nobody asked for. |
| **D3** | **The structure records each chapter's literals and wellformed holds them to the account.** A literal naming a file the chapter does not have is `UNKNOWN-FILE`; a file beside a chapter that no literal in it names is `UNUSED-FILE`; `this` is never required; a literal with a words half or a `./` name is `MALFORMED-ANNOTATION` with its own sentence. Faults are returned, never raised, in the binder's one form. | Doug: *"the compiler can now enforce that all resources are used"*; *"every resource file (except this, which is optional) must be specified."* The account of a chapter's files is the inventory's already. |
| **D4** | **The transform splices a literal into a string expression.** `![[ this ]]` becomes the file's source as handed, before any edit, as `{"…"}`; `![[ id.type ]]` becomes the text of the file beside the chapter, read from the structure's held source when it has it and from disk otherwise, or a picture's address beside the pages for an image type. Absolute offsets, back to front, as every splice is. | The version written and never the version modified, [Solutions 96](../solutions/96-the-literal-the-transform-modified.md); a string expression is what JSX text with braces and angle brackets in it must become to parse — the probe of Sprint 90 showed the printer cannot do it and the splice can. |
| **D5** | **The assembly appends nothing.** The book module calls each chapter as it did before Sprint 89; the raw imports and `cloneElement` go; the render still copies every image beside the pages; the structure still reads text files beside chapters for the references they spend. | Doug: *"append is the authors. You remove the flexibility if you have the binder do it."* |
| **D6** | **Append moves to `src/writing`,** exported from the writing folder, the figures folder keeping Figure, Code, Image and Svg; a chapter writes one by hand, `<Append identifier="…" type="…">![[ id.type ]]</Append>`, when it wants an appendix among its annotations; Figure reads it by attribute as today and draws the text it is given otherwise. | Doug: *"Move Append to writing, as it's related to appendices… Figures can read that if configured, but one might also just `![[ ]]` into the figure."* `src` moves on his ruling, which is the yes. |
| **D7** | **The test library is rewritten to the language:** every `$[ X ]` to `$[[ X ]]` in every book and in the binder's own fixtures and promises; the manual's Code, Svg and Image figures given `![[ code.tsx ]]`, `![[ .svg ]]`, `![[ .png ]]` and `![[ sketch.html ]]` as their text; every file beside a chapter named, or the bind refuses it. | R1 and R5, observed in the library the binder is proved against. |
| **D8** | **Lezer is the viewer, and the viewer's powers are annotations on Code.** `@lezer/highlight` and `@lezer/javascript` enter the package; a `Highlighted` annotation, said of a Code figure with a `language` attribute, tokenises the letter's text and Code draws its text through the annotation when one is expressed, each token wearing a mark for its tag; a `Numbered` annotation gives each line its number. The default sheet gives the token marks ink from the theme's values, and a library's theme overrides them. Code without either draws as it does today. | Doug ruled Lezer; the annotated version is the form: a keyword wears its mark whatever the theme, and the theme gives it ink. Over highlighting inside Code by a member, which every Code would then carry. Grammars beyond TSX are a library's to add. |
| **D10** | **The manual is read before its code is touched, and a tool's chapter is written before the tool.** U6 rewrites the manual's tools by reading the chapters that document them as their specification; U7 begins with Libby's chapter on the listing — how a file must look to be read: its name above, its lines numbered, its syntax in the library's ink, no line wrapped — and the viewer is built to it; the explorer's chapter, already written, is what its code will be developed from. | Doug, 2026-09-28: *"Are you remembering to actually make the test library a self-documenting codebase, so that you literally read the reference manual to develop the code? It's not a fiction. This is what we are inventing. A library closed under books contains representation of the tools used to build it in its books."* |
| **D9** | **The docs say the language as it is, and the trail is untouched.** The Language, The Binder, As Built, the Figures book with Append's chapter moved to the writing book, The Reference Manual's how-to, How to Be a Librarian's tools table, Books in Annotations; the sprint records and Solutions keep `$[ ]` as history. | Settled accounts are the destination and sprint records are the trail. |

### Risks

| risk | what mitigates it |
|---|---|
| a `$[ ]` left somewhere the pattern did not reach — a string, a promise, a fixture | U6 greps the whole of `.test` and the binder's promises for `$[ ` and ends at zero; the bind refuses one bracket by name |
| a literal's text breaking the string expression — a `</script>`, a `${`, a line separator | `JSON.stringify` escapes all of it; a promise with a hostile fixture |
| the whole file inlined per literal growing a page | already so with the raw import; a file named twice is inlined twice, and the record says so |
| a chapter's file the author never names, refused where before it bound | that is R5; the test library is rewritten in the same unit |
