### Decisions

- **D1 — A mode is an annotation said of the book, set by a press, read by the sheet.** His library's mechanism exactly: a word on the bar sets `book.$is` to the chosen annotation, the annotations define again, the book's element wears the mode's class, and the rules decide what shows. Nothing re-renders on a mode but the book's classes; both faces are drawn and the sheet hides one, which is the one-paint rule. Chosen over a React state on a component, which the framework does not have, and over re-rendering the chapter on a flip, which costs a draw. The modes are the page and the editor, one at a time as his panel's states are; the words-away is a third annotation said beside the editor; light, wrap and lines are three more. *(3.1, 3.3)*
- **D2 — The editor view is a format said of every book, its layer the grid, the file's page drawn by the book.** As the binder's explorer did it: the format's style grids the book's element into the table, the open chapter and the file's page, and the book's base class draws the file's page after its chapters so every book has it, shown only in the editor mode and only when the open chapter has a file. The table of contents is the tree: in the editor mode it stands open beside the open chapter, and a branch format on each of its entries draws the chapter's files beneath the row as presses. Chosen over a separate tree component because the table already catalogues the chapters and the sketch's tree was the table in the page's voice. *(3.1, 4.2)*
- **D3 — The listing is a paragraph wrapping the package's Code figure, dressed by a theme part.** A listing paragraph writes the bar and a numbered Code figure for the file it names, or a tab per file when it names none and the chapter has several; the theme's new part gives the listing his numbers, JetBrains Mono at 12 on 20.4, the night, the four colours, the number column, the light palette under the book's light class. The face comes from Google Fonts by a stylesheet link the listing renders, as the Content renders its style tag. *(2.1, 2.2, 2.3, 2.5)*
- **D4 — An appended HTML has two faces on the bar, the listing and the page run.** A listing whose file is `.html` offers one more word, run, and shows the page in a frame fed the file's text, scripts allowed, in the pane the listing stands in; in the editor mode that pane is the window's height, which is the full screen 2.4 asks for. - **D5 — The appendix is a section of the table wearing an annotation, its chapters in a part of that name.** As his library's appendix: the table's author writes a section headed with the part's name and says Appendix of it; its rows are chapters as any rows are; the theme sets the section at the table's foot in the smaller voice; the branch format hangs each row's files beneath it; a press on a file opens the chapter in the editor turned to that file.
