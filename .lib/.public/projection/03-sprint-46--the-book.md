## The error design — exceptions with views, generalized from check

Doug's direction: *"look for a version that looks as much like catching exceptions as possible… it would be nice for an exception itself to have a view."* Research: React itself throws non-Error values as protocol — Suspense catches a **thrown Promise** and renders around it; error boundaries (still class-only in React 19) render a fallback view for descendant render errors; React 19 adds root-level `onCaughtError`/`onUncaughtError`; `react-error-boundary` popularized the fallback-view-per-boundary idiom. Our lift calls bond constructors and `view()` imperatively, so `$Chemistry` can *guarantee* the catch with plain try/catch — stronger than React's own boundary constraints — and can plant a per-chemical boundary for descendants.

**Built to Doug's calls** (particle-shaped exception; bond scope only; configurable production): `$Exception extends $Particle` takes the caught `Error` as a constructor argument and its `view()` renders the panel — extensible by subclassing, swappable via the `$exceptions` registry (`{ mode, render }` in [dev.ts](../../../chemistry/package/src/implementation/dev.ts)). The bond's one catch site now stores the `Error` object (`$devException$`) beside the message (`$devError$`, byte-compatible — tests unchanged), and the render path renders the registered exception particle instead of calling the hard-coded panel. **`$check`/`evaluate` are untouched** — every bond-constructor error already funnels through the one catch, which is why nothing broke. Production honors `$exceptions.mode`: default `'silent'` (caught, `console.error`-logged, renders nothing — the developer-expectation norm: loud in dev, tucked away in prod, never crash the whole app), `'render'` shows the exception's view, `'throw'` restores the old uncaught behavior. **Flagged change:** production previously threw raw at bind; the new default catches — Doug chose configurable-with-tucked-away. Proven end to end: a rejected book renders the exception's view (51 green, framework 622 green, both tsc at baseline).

## The composition assigns the reference (2026-07-31, Doug's generation laws)

Three laws from Doug, built and proven. **Generation:** references are generated and assigned *with the parts* — the same moment composition assigns the index. This matters below the chapter: paragraphs, sentences, and words are generated fresh by readings with no parent bond, so the lazy fold cannot reach them; assignment at generation is what carries the referential context down (`if (this.ref) p.ref = this.ref.compose(p.index)` in every parts reading and bond constructor). **The holder's authority:** the composable that holds a part *holds the referential context* and may overwrite even the reference written into the block — so the `ref` getter's precedence inverted: derived-from-parent first, `$ref` as the fallback grounding (with a self-parent guard for mounted roots). **References written into the writing:** a `$Reference` at the top or bottom of a block is stripped by the bond constructor — a real splice of the block's `$elements`, so the copy loses it too — and assigned as the writing's own `$ref`, outranked whenever a context-holder speaks. (Doug struck the word *endogenous* from the framework — the book word is *the reference written into the block*.) **`$Highlight`, the kind a highlighter leaves:** not fields on the base — its own kind of reference (Doug), taking its parent through the rendered-inside channel and adding *first and last character relative to the parent's start*; `marks(copy)` returns the marked span. Addresses are never strongly typed below the paragraph — `$for` is a free string, compose keys are loose; the character form is only the *natural* form for the compositional path that generates it. Rendering is a highlighting — underline is the default posture of an in-text reference; following one lights the target and fades it over two seconds (chapter 7 points at its own third paragraph). **Readers follow references** — nobody *goes* in a book: prose links and the ribbon share one `follow(address)`, which builds a real reference rendered inside the book, resolves it through `lookup()`, and only then turns; an unresolved reference does not move the reader. `$Highlight` carries exactly its specification: parent through rendered-inside, first, last.
