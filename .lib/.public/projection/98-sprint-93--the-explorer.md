## Where this sprint comes from

**Doug, 2026-09-28, verbatim:** *"how about you prove that you can elegantly use this system in the reference manual to provide more of a code documentation view. Maybe the book looks almost like its own app, and provides something like a file tree on the left like vscode and then clickable tabs, and the thing on the left is somehow the table of contents? Can you make a clean simple version of something like that, where you build annotations and components that consume them, extending .public as it's supposed to be used, to see if it is ready to provide such an application experience? Remember that plain react and non-writing chemistry can live inside pieces of writing if it needs to."*

**And his questions for the brainstorm, earlier the same day:** *"what is the object model for the app you want, how can subclassing library components, adding annotations, and integrating with outside libraries help you achieve this in a way that provides a beautiful semantic structure if one read the chapters, while also providing a powerful user interface that might even be surprising based on the structure of the text. How can you do things like reinterpret the table of contents into something like a file tree (for the code files)... The art of building a library is keeping the semantic essence of something while exploring new forms and the file tree is the table of contents of the codebase."*

## <a id="found"></a>What building it natively found — the sprint's product, 2026-09-29

**Doug, mid-build:** *"You are testing .public's ability to implement app designs like this natively. Knowing that, how does that change your approach? What does success mean? It might mean discovering why something is hard."* So the explorer is the instrument and this is the reading: what `.public` gave without a fight, what it lacked, and what each lack is. Nothing entered `src` or the compiler; every workaround below is named as one.

**Given.** A class under Paginated says which chapters are pages and which is open, by equality of identifiers, in seven lines. A Format whose layer is a grid over marks the framework already puts on the page lays the app out, and the theme's values reach every rule of it. A paragraph the book draws from its graph, as the masthead is drawn, is the tabs; a word wearing a Reference is a tab; a word wearing a Format whose layer is the control is a tab's close, as a word wearing a Reference is a link — React in a paragraph, proper, its handler augmented by chemistry so its writes batch. A section tucked away by a mark is an appendix, Paginated's own pattern one level down. A Format on each entry of the written table projects the entry as a tree node, finds the chapter the entry means by the equality of a Content's identifier with a chapter's mention, marks the entry when that chapter is open and draws the chapter's appendices beneath it as leaves — the table catalogues chapters and nothing else, and the tree is its projection. A chapter's code is as many files as its tool has parts, each a figure its prose comprehends. The compiler verified every leaf's place and refused what named nothing.

**Hard, each a seam and what it is.**
1. **Expression happens in the bond, before the book binds — and a finding is measured alone before it is believed.** This stood first as the opposite claim, that an annotation is expressed only at its writing's first draw and `is` answers nothing before, and a mark was put on at the bind to work around it. Doug asked whether expression should happen before `$Bound`, and the code answered that it already does: Writing's bond defines its annotations the moment a writing is made, the mirror makes a chemical of an element the moment it is given, and Book's bond calls `$Bound` only after every chapter is in — so `is` answers from construction, and `$Bound` is exactly what he described, every annotation having happened and a writing configuring itself from the result, as Paginated marks its pages and Next finds its neighbour. Tested by reverting the workaround: the leaves draw by `is` alone. The leaves had failed for the second finding alone, and two changes made in one pass hid which one cured them. *What is not decided before the bind is only what depends on the bookmark, set after construction, which is why the open mark moves in `defines` at each draw while the page mark goes on once at `$Bound`.*
2. **A Format's layer that needs its instance is made in the bond.** A `style` field closing over `this` sees the standing instance the class is compiled from, whose parent is itself; the branch drew no leaves and the close closed nothing until both layers were made per instance in the bond, as Table's is. Already the guide's row; the guide was not followed, and the cost was two binds.
3. **The reader's trail is not derivation.** A book knows the reader's place, its bookmark, and nothing knows the places visited; the tabs are marks the explorer puts on arrival and takes back on a close. Derived on every define pass they were restored the moment a close reverted them, since the closing chapter was still the open page when the book redrew; the explorer remembers the last place it marked, in one inert field, and marks on arrival only. *State is a mark, and arrival is remembered.* Whether the trail should be the Book's, bookmarks plural, is a design question for `.public` and not asked of Doug, who does not own this code.
4. **A mention must be spent in writing.** The compiler refuses a mention nobody refers to, and a leaf drawn from the graph refers to nothing the compiler can see; the chapter's prose refers to its appendix, as a paper refers to its figure, and the mention is spent. *A view that spends a mention from the graph is not a reference; the writing must make one.*
5. **The chapter of a place.** A bookmark naming a heading leaves `book.bookmark` undefined, since a chapter is found by its title's reference and a place is a heading's; Paginated then opens the cover on any fragment route. The paging class answers by the same equality over the sections' mentions, one level down. Paginated could answer it itself; recorded, not taken.
6. **Front-most is innermost, and a layer reading the theme stands in front of it.** The explorer's grid, added in the same call as the manual's theme and before it, drew outside the theme's provider and read no value; two adds, the theme first, put it inside. Sprint 88's rule, met again.
7. **A mark is taken back by its author, and a writing authors its own.** A mark authored by the section it stood on was reverted with the section's own class; each transient mark has an author that puts nothing else on that writing — the paging authors the open appendix, the explorer the opened.
8. **An anchor drawn inside a Content's anchor is not kept by the browser.** A Format appended behind the entry's Reference draws outside it; the collection's append is the seam.
9. **A counter cannot count a hidden page**, so the chapter's label lost its number under paging; the tree numbers its entries instead, since the table is always shown.
10. **The theme's element is the page's frame**, its measure and margins, so an app that takes the viewport escapes it with fixed positioning and the manual's theme lifts the measure; a layout at the page's level has no seam of its own.
11. **The DOM was probed before the contract was read**, twice; chemistry's own chapter says a view's handlers are augmented and their writes batched, which was the whole of what the probes found. The reference manual for `.public` coding is read before the browser is asked.
12. **A list that shrinks under a click is keyed by identity.** The tab groups were keyed by index, so when a closed tab left the list React reused its nodes for the tab after it, and the anchor the router read was by then the next tab's close, whose route was the page already open; a fresh page, with nothing after the closed tab, routed. Keys by the chapter's and the appendix's identifiers end it. React's own rule, met where a paragraph the book draws is a list the reader edits.
13. **A tab is a chapter, and the design is followed as drawn.** Doug at the third showing: *"The x and the code extra tab is superfluous, but I also don't understand why you can't see that its a terrible design… please use the design to iterate. And if you aren't matching the book to the html, you aren't using the design…"* A file had a tab of its own beside its chapter's, and every tab a close. [The sixth sketch](98-sprint-93--the-explorer--sketch-6.html) and [its photograph](98-sprint-93--the-explorer--sketch-6.png) drew the tabs as chapters and nothing else, a file opened from its leaf into its chapter's spread; the book was transcribed from it and photographed beside it until the two matched, the last two differences the paper, which lay only behind the head once the book left the theme's frame, and the size of a page's headings. The close went with the ×, so the third and twelfth findings stand as what closing taught, not as what the explorer does.
14. **A served page's first draw is the page as printed.** The spread is opened by a fragment, and a print knows a page's address and never its fragment. The entry built the book with the whole address before hydrating, so its first draw marked the appendix open where the print had not, and React keeps a printed attribute that disagrees rather than patching it: no recoverable error, nothing in the console. Loaded at a file's own address, the address its leaf links and a reader would share, the page showed the chapter's prose and never the file; a click to the same address opened it, since a click moves a book already drawn. The compiler's entry now builds the book at the page's address and moves it to the fragment once the book listens, as the router moves it for any link: one paint more on a fragment's first load, and the only way the print and the first draw agree. The plan's hydration risk fired in a form it did not name, silent where it expected an error. *Drive the address a reader shares, not only the clicks that reach it.*
15. **A field holding a function was not a field.** Code's highlighter, with the highlighting as its default, could not be set: chemistry made an own member whose value was a function into a reagent, a getter, and a prop write threw *"Cannot set property $highlighter … which has only a getter"*. 16. **If one is about the other, show them together.** Doug at the fourth showing: *"Is the chapter about the code? There should not be two clicks to get to the code"*, and then *"If one is about the other, show them together. Just use your other view. And why do you have an empty tab for the library. Or it is maybe just a parenthetical cover?"* A chapter that prints a file is about it, so it opens at its spread, its first file up front, and a leaf puts any other file there; the paging's one new reading says which appendix is open, the one the bookmark names or else the first.
