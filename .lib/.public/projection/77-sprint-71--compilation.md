## <a id="plan"></a>The plan — ***guardrails, 2026-09-15***

### <a id="decisions"></a>Decisions, each with what it was chosen over

- <a id="d1"></a>**D1 — The descent is a rule on `WritingSpecification`.** It applies to any piece of writing that answers `parts()` — a capability, never a kind test — asks for at least one part, calls `specify()` on each, gathers every part's failure with that part's index and kind, and raises once. *Chosen over a member on `$Composition` that walks (the walk would stop being a promise a kind can decline) and over the harness walking (Doug: "The goal here is to have it right in the code").* A kind declines by returning `false` from the rule, the existing convention (`ChapterSpecification.$saysSomething`).
- <a id="d2"></a>**D2 — The toggle lives in the specification and nowhere else.** `Specification.check` runs no rule outside development, reading chemistry's own `dev` from `@dna-platform/chemistry/symbolic` so both packages share one switch; `specify()` and every `specifically` are untouched, so assignments (P13, the bookmark's `persist`) run everywhere. *Chosen over a guard in `valid()` ("DO NOT WRITE ANOTHER SPECIFICATION LAYER") and over a `.pubconfig` define (a second switch beside chemistry's).* The binder's harness children already run under `NODE_ENV=development`; vite's client build is production.
- <a id="d3"></a>**D3 — A failure's place is text.** Each level the failure rises through prefixes `index:Kind › `, and the harness reads the first index as the book's part, which is the chapter's file. *Chosen over a structured error carrying a path (a new type through chemistry's raise) — the message is what `$check` already carries, and the Problems matcher already reads a line.*
- <a id="d4"></a>**D4 — Once per process is module state.** A `WeakSet` beside `printed` in `Writing.tsx` guards `specify()` entire — the first call assigns and checks, every later call answers at once. *Chosen over a field (a bookkeeping field on a chemical is a reactive bond — struck, standing).*
- <a id="d5"></a>**D5 — A chapter's parts are the one writing it prints**, made once and kept in a `WeakMap` beside the memo. A chapter that prints no writing answers no parts and fails D1's rule, which is the truth about it. *Measured Sunday at 84,566 writings from the paper with this exact shape patched from outside.*
- <a id="d6"></a>**D6 — Reflection: what checks moves, what draws stays and is memoized inside reflection.** The one-kind check leaves the `kind` getter for a rule; `numbered`'s gather is kept per holder and kind; `kind` and `classNames` are kept per writing — every memo inside `Reflection`, where Doug ruled reflection is contained. **The bound, bubbled up:** numbers and class names are drawn, in production too, so they cannot leave production; a memo is the only lever there, and the measure is the paper's render profile.
- <a id="d7"></a>**D7 — Scope is a folder.** The specify task and the vitest take one optional folder: a book's folder runs that book, the library root runs all, anything else is an error naming both. The walk down through catalogued books is one function in the harness that answers none — the seam `$$Synopsis` fills next sprint.
- <a id="d8"></a>**D8 — One session, no division.** The output is about six package files, three binding files, three promises rewritten and two accounts marked; smaller than any brief.
