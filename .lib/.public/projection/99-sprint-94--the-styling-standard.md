## Where this sprint comes from

**Doug, 2026-09-29, finding Table with a global style while not a Format:** *"I would think we want format annotations to be standardized. They can do other things."* Then the questions the standard must answer, verbatim in [Where a look lives](../writing/02-theming-and-formatting.md#where-a-look-lives): global styles a mistake? formats local styled components? all globals to the theme? when other themes? what does one get and give up, for dynamism, flexibility and performance? Is Theme in Book a convention or a rule?"* Then, with Cathy's research in hand: *"How are we going to develop themes and use formats etc...? Did we learn what we need to learn? Does it factor in having dynamic properties on the theme that can be consumed in the app?"* And the ruling that made the plan: *"I thought the Theme class itself would have properties set that it passes down to its styled component and others read it… let's give Book a theme property that returns the annotation. We probably want themes to be unique and subclasses can add their own in $Define. Books can type the theme property more specifically. And then let's standardize the design… adding the theme property to $Book, standardizing the Formats to make use of it through their book property if needed or whatever else is needed to formalize and standardize our styled components format-based design, and then really document this with an eye for consistency in the documentation."*

## <a id="d11"></a>Doug's ruling during U3 — the Format that provides, 2026-09-29

The standard's type for a theme, the eight, made Sprint 80's `theme = true` Format, which hands *itself* to a provider with its own fields read by name, untypeable without a cast, and the question went to Doug. His design, verbatim: *"Format doesn't need theme. this.book.theme should get it right? Doesn't the boolean control if it is a theme? Give it a property called themeProvider = true - it is a styled component, so we can reference that, and then you can have `get theme() { return this.book.theme; }` And that can be progressively typed on subclasses. Now every format has a theme, and it has the structure to reach to other themes if need be in subclasses."* And just before: *"Formats can consume theme properties as well as exposing their own, both of which can be passed to their components or maybe to control the classes they put on their writing?"*

**D11** — Format's flag is `themeProvider`; Format gains `theme`, the book's theme typed as the base Theme, throwing where there is no book, narrowed by a cast in a subclass or overridden to reach another theme; a Format that provides hands `this.theme`'s contract, typed as the eight, so no cast stands in `src`; a Format's own properties and the theme's reach its styled component as transient props made once in the bond, as Table's `$columns` do, or decide the marks it puts on its writing; the four promises that had a Format provide its own properties are rewritten to that, inside a book, and one new promise has a subclass reach another theme. Members his: `themeProvider`, `theme`. Owed still: a nested theme's *declarations* on the element that provides it, without which its values reach the subtree only as the fallbacks of its `var()` references.

## <a id="measured"></a>U1 — the three measurements, 2026-09-29, and what they amend

Three probes, made in the package and removed the same turn, against styled-components 6.4.0 and stylis 4.3.6.

- **M1 — stylis wraps a nested `@layer`.** A styled template holding `@layer pd.theme { … & .x { … } }` served as `@layer pd.theme{.jpHPtF{…}.jpHPtF .x{…}}`, the generated class inside the layer, and a declaration outside the block stayed unlayered; a global style's order statement and layered block came out as written. **D8's first shape stands:** the sheet keeps its element and lays its marks' rules in the layer. **And D3 is amended:** the collected head is ordered by the order styled components were *defined*, module by module, not by render — a component defined earlier printed first though it rendered later — so a statement in the sheet is not literally the first rule; the invariants' global styles in `Writing.tsx`, defined before `Theme.tsx` loads, print first, their `@layer pd.invariants {…}` establishing that layer, and the sheet's statement then appends `pd.theme` after it. The resulting order is the one wanted, and it is deterministic by module order. **R6 is re-stated:** the promise reads a bound page's head and holds that `pd.invariants` first appears before `pd.theme` and that no Format's rule is layered; the statement stays the sheet's first rule as the declaration of intent, and the binder still writes nothing.
- **M3 — how `createTheme` behaves.** `createTheme({ ink, space }, { prefix: 'pd', selector: '.t1' })` gives `var(--pd-ink, black)` as the contract's leaf, `--pd-ink` in `vars`, the raw object in `raw`. With raw in the provider and its `GlobalStyle` mounted, the declarations are emitted under the selector and a nested provider under its own — but every interpolation reads the raw value, `color:black`, a class per value, no gain. With the contract in the provider, `GlobalStyle` emits `--pd-ink: var(--pd-ink, black)`, circular. **With the contract in the provider and the declarations written by us from `vars` and the raw fields**, every interpolation is a `var()`, `color:var(--pd-ink, black); padding:calc(var(--pd-space, 1rem) / 2)`, one class per component, and the declarations `.t1{--pd-ink:black;--pd-space:1rem;}`. **D6 is amended:** the provider hands the *contract* to ThemeProvider, made once in the bond so its identity never changes and no consumer re-renders; the theme's own declarations component, reading the eight fields, writes `${vars.x}: ${value}` under the theme's element's selector and re-renders alone when a field is written; `createTheme`'s `GlobalStyle` is not used.
- **M2 — the baseline.** A book with twelve styled elements under Formats, six interpolating `theme.ink` and six not: at mount 6 and 6 rendered; after `theme.ink = 'red'`, **6 and 6 re-rendered — twelve of twelve for one write**, the six that never read the theme included, since a ThemeProvider whose value changes re-renders every styled consumer. **R2's number is 0 of 12** after U3, the provider and the declarations alone redrawn.
