## <a id="requirements"></a>Requirements

- **R1.** One ledger, beside The Importer's chapter as its appendix, for every account; each line names its account, as it does today, and the ids never collide.
- **R2.** The ledger represents reality: a run that writes rewrites it whole at its end, a line for every book the library holds found by the Origin on its cover, each line's digest the book's folder as it then stands; a line whose book is gone is dropped and said.
- **R3.** A hand edit is an explicit mark, not an inference from a stale digest: a run that finds a held book's digest moved since the last run, and does not re-import it, marks the line edited and says so; the mark is kept across runs until the book is re-imported, which clears it and keeps the edited files beside the fresh chapter as today, or until it is settled.
- **R4.** One word settles a change that was the library's own: told to settle, a run clears the mark on the books named or on all, takes each as it stands, and writes no book.

## <a id="decisions"></a>Decisions

- **D1 · One path.** `1-the-importer~ledger.json`, named beside `configurationPath`; `Account` loses its `ledger`, since an import is an account and the ledger is the importer's. Chosen over a ledger per account because Doug ruled it, and because the two never differed in kind.
- **D2 · Replaced whole, from the books on disk.** A writing run collects every held record, those it wrote and those it left, refreshes each digest to the folder as it stands at the end, drops the gone, and writes the file once. Chosen over the present line-by-line write because only a whole rewrite can represent reality, and the present form is how it went stale.
- **D3 · The mark.** A line carries `edited: true` once a run has seen its book moved and not re-imported it; `importState` reads the mark first, then the digest against the line, then growth. Chosen over the present inference because a refreshed digest would bake a hand edit in as the importer's own state and the next grown export would overwrite it.
- **D4 · The word is `--settle`.** It takes the selected books, or all with `--all`, as they stand: clears the mark, refreshes the digest, writes the ledger and no book. Named for what it does to the ledger; `--tend` already means the chapter after struck kept files and stays.
- **D5 · The migration is a script in the scratchpad, run once.** It merges the two ledgers into the one and removes them; the refresh is the importer's own first `--settle --all`. Chosen over migration code inside the importer, which would be cruft after one run.
- **D6 · The chapters follow the code.** The Importer gains the ledger appendix and a paragraph; The Ledger is rewritten for one ledger, the whole rewrite, the mark and the settling; DNA and DNA Legacy lose their ledger sections and appendices.
- **D7 · A gone book's line is dropped, and the book is new to the next run that selects it**, as R16 of Sprint 111 intended: striking a book from the register makes it new.
