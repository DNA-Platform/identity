This is the cataloguing book for the `.public` branch library. `.public` is the subject of *publicity* — the public view onto the whole repository, the library made public so that it can be read, lent, and built upon. It is where the library metaphor takes renderable form: [`@dna-platform/lib`](../../package/), the canonical code library for creating libraries, lives beside this branch in `package/`, and the [public view application](../../app/) that renders the repository to the world lives in `app/`. Publicity is not their API reference — it records the team's applied knowledge of building that public face: why a code library is a pale reflection of what a library means here, why depending on `lib` is what makes a repository a branch, and why in this library publicity means lending — an `npm install` is a book checked out. Publicity catalogues that knowledge as it accumulates.

## Books

### [Publicity](.cover.md) — Publicity

Self-cataloguing. The branch library knowing what it knows about the library's public face — the view onto the repository, the package that lends the means to build a library, and the act of lending that binds a repository into the tree.

### [Projection](../projection/.cover.md)

The sprint-by-sprint record of building the public library — what each sprint aimed to do, what was built, and what was learned. The branch's autobiography, empty at creation and populated as the work proceeds.

### [The Semantics of Books](../the-semantics-of-books/.cover.md)

The derivation of the object model that [`@dna-platform/lib`](../../package/) will realize — `$Composition`, `$Book`, `$Chapter`, `$Title`, `$Author` — worked out from Doug's 2026-07-18 *Semantics of Books* conversation, with every claim cited to where in that conversation it came from. Two levels of closure (composition, then book), built from the bottom. Not the finished spec: the record of how the understanding evolved, kept honest by pointing at its source.

### [Designing Inexplicable Phenomena](../designing-inexplicable-phenomena/.cover.md)

The design record of the repository itself — how `@dna-platform/lib` is used to build ways of viewing the repo's content. Gathers the notes the team already took ([Sprint 43's resource record](../../../chemistry/.lib/projection/42-sprint-43--the-library-hosts-itself.md), the `.archive/` markdown-plus-LaTeX converter and its prototypal classes) and extends them: markdown-with-LaTeX sections on the composition classes, and the Lab's navigation made flexible for full-page, mobile-capable designs. Notes first, designs when settled, each idea cited to where it came from.
