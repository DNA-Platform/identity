***WHAT `.public` IS FOR, in one sentence, so that nothing in this catalogue is read as being about a web framework:*** **library semantics establish the soundness of a knowledge graph — a knowledge graph is an abstraction of a library, and the canonical semantics are chosen because they are suggestive.** *The statement is [The Soundness of a Knowledge Graph](../the-semantics-of-books/18-the-soundness-of-a-knowledge-graph.md), and it is the first thing to read in this branch.*

This is the cataloguing book for the `.public` branch library. `.public` is the subject of *publicity* — the public view onto the whole repository, the library made public so that it can be read, lent, and built upon. It is where the library metaphor takes renderable form: [`@dna-platform/public`](../../package/), the canonical code library for creating libraries, lives beside this branch in `package/`, and the binder that turns a library of books into a published site lives inside it, in [`package/.binding`](../../package/.binding/). Publicity is not their API reference — it records the team's applied knowledge of building that public face: why a code library is a pale reflection of what a library means here, why depending on `public` is what makes a repository a branch, and why in this library publicity means lending — an `npm install` is a book checked out. Publicity catalogues that knowledge as it accumulates, and the branch's own verbs alongside its records.

**Read in this order, since 2026-10-01 — Sprint 95's E3, Doug's word that the documentation be organized for importance.** *The thesis above first. Then, if you are about to write a library on this code, the [Design](../.designing-inexplicable-phenomena/.cover.md) catalogue in the order it gives: [Writing a Book](../writing-a-book/.cover.md), the four books of the classes, the binder as built, the rules, the canon. Then the records, when you need to know how something came to be: [Projection](../projection/.cover.md) by time, its last chapter where things stand; [Solutions](../solutions/.cover.md) by symptom, when something is broken; [The Semantics of Books](../the-semantics-of-books/.cover.md) when the object model's reason is asked. [The Public Skillset](../the-public-skillset/.cover.md) and [Debugging a Page](../debugging-a-page/.cover.md) are procedures, reached for when their verb is wanted. And [The Condition Report](../the-condition-report/.cover.md) is a record of the first draft, read for history and never for the current code's condition.*

### [The Semantics of Books](../the-semantics-of-books/.cover.md)

***The branch's thesis lives here, in [The Soundness of a Knowledge Graph](../the-semantics-of-books/18-the-soundness-of-a-knowledge-graph.md) — read it before anything else in this catalogue.*** **Library semantics establish the soundness of a knowledge graph; a knowledge graph is an abstraction of a library; the canonical semantics are chosen because they are suggestive.** *That chapter is the design purpose of `.public` stated rather than derived, and it is what makes the object model's exactness a requirement instead of a preference — every name in it is a node kind in a graph whose correctness is defined in terms of those names. It also carries the division the architecture rests on: global reference to the catalogue, local well-formedness to the specification, and the compile as the only moment the library exists as one object.*

The rest of the book is the derivation of the object model that [`@dna-platform/public`](../../package/) realizes — `$Composition`, `$Book`, `$Chapter`, `$Title`, `$Author` — worked out from Doug's 2026-07-18 *Semantics of Books* conversation, with every claim cited to where in that conversation it came from. Two levels of closure (composition, then book), built from the bottom. Not the finished spec: the record of how the understanding evolved, kept honest by pointing at its source.

### [The Public Skillset](../the-public-skillset/.cover.md)

A skillset — a book whose chapters compile to slash commands — and the first one that lives in a branch rather than in the team's own [Our Skillset](../../../../.claude/library/our-skillset/.cover.md). Every other book here is a record, each indexing the same work along a different axis: [Projection](../projection/.cover.md) by **time**, [Solutions](../solutions/.cover.md) by **symptom**, [The Condition Report](../the-condition-report/.cover.md) by **kind of fault**. This one is not a record at all — it holds **procedure**, the verbs the branch can be asked to perform. A record remembers what happened; a skill is the instrument for doing it again, correctly. Its chapters — the audits, the code-design trial, the writing driven in Chrome — are routines first run by hand against a real browser and then written down, each carrying the numbers the branch had when it was written so a later run has something to beat, and the traps that cost that session an hour. A branch earns skills of its own when its verbs name files that exist only here: these reach into `.public/package` and `chemistry/package` and would break the moment either moved, which is exactly why they belong to this branch and not to the team's repo-agnostic set.

### [Debugging a Page](../debugging-a-page/.cover.md)

How the look of a page is debugged through the layers that draw it, as fast as it can be — written from the day the Wikipedia look was restored and every address became the compiler's. The loop as it stands with every step measured, the probes and the rule they obey, the browser that should be kept open, prototyping on the compiled output and carrying it back, and the traps that each cost an hour. A tutorial for the team; the name is a proxy.

### [The Condition Report](../the-condition-report/.cover.md)

**A record of the first draft since 2026-10-01.** The standing register, as it was, of every questionable part of the first draft's code, along Doug's own four axes — organization, names, semantics, implementation — each entry carrying the line that shows it, a stable identifier that never moves, and a verdict that can be argued with. Commissioned out of one sentence: *"we have lost the high level design goals and things have gotten muddy."* Its identifiers are still cited by the sprint records and still resolve; its verdicts are history, since the redraft of 2026-09-25 started over rather than cleaning the draft. The current code's condition is read sprint by sprint in [Projection](../projection/.cover.md), and its defects go to [Solutions](../solutions/.cover.md).
