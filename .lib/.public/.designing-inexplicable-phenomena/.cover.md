---

The design record of the Inexplicable Phenomena repository, as a subject: how `@dna-platform/lib` is used to build ways of *viewing* the repo's content, and how the code that does it is written, typed, dressed and consumed. Where [The Semantics of Books](../the-semantics-of-books/.cover.md) derives the object model from its source conversation, this subject holds the **design decisions of the repo itself**, in five books. *Until 2026-09-11 this was one book of twenty-six chapters and 41,018 words; Doug: "Is it time to split it into more books with more covers? Are you sure you can read all those?" — so the book with this name became the catalogue, and its chapters became the books below, each readable in a sitting.*

## Books

### [Designing Inexplicable Phenomena](.cover.md) — Design

You are reading it. Self-cataloguing: the design record knowing its own shape, five books along five questions — how content is viewed, how code is written, what the type system is, how a book is dressed, and what a consumer writes.

### [Ways of Reading](../ways-of-reading/.cover.md)

How the repository's content is VIEWED — the earliest notes: the book as the fundamental website, view patterns, markdown with LaTeX, the Lab's navigation, the live library and the back of every page. Notes first, designs where one settled.

### [The Coding Style](../the-coding-style/.cover.md)

How the code is WRITTEN, as ruled — the unit of code, the order of a class, the style rules in force and the closeness rule beneath them, the spelling of a kind, the shape of TSX, and what natural means. A refactor reads this before it undoes a ruling.

### [The Type System](../the-type-system/.cover.md)

What the framework IS — what carries over between versions, the type and the instance, shells over types, the interface type system, what we believe and what it cost, polymorphic limiting. Why a kind is spelled as the style says.

### [The Motif](../the-motif/.cover.md)

How a book LOOKS — the Wikipedia default, every dress a format, the Wikipedia fit, and why markdown is not a reading yet. Themes and formats as design.

### [Writing a Book](../writing-a-book/.cover.md)

What a CONSUMER writes — using the library plainly, reading the source, the address scheme, and the little framework a book builds for itself in .book, .chapter and .document. The demos' conventions, ruled.

### [Writing](../writing/.cover.md)

The book of the redraft's `src/writing` folder, opening with its front matter in Doug's words: Writing as the base class of the .public document API, split into contents and annotations; annotations as a plugin-like system that keeps things modular, each pointing out a trait the writing has, interacting and overriding one another; Composition structuring the contents of a book while annotations customize them; what developing a class of writing means; and the mechanisms that theming and formatting are two use cases of: an annotation is a note on the page, its own writing wearing pd-annotation and its note at the level of the writing it annotates, built the day it was ruled; Format lending a styled component tried, Theme's rendering the one open thing, uniqueness the feature still to weigh; then Composition and Letter, each to the four parts, and Writing's own three chapters, moved here from the Genesis book the day Letter arrived.

### [Utilities](../utilities/.cover.md)

The book of the redraft's `src/utilities` folder, the first written to [How a Class Is Documented](../the-coding-style/08-how-a-class-is-documented.md): one chapter per class, four parts each — what it is with members cited, how it is extended, its promises, its gate. Collection and Specification, the two things every writing is built with and neither of them a writing.

### [Library](../library/.cover.md)

The book of `.public`'s `src/library` folder, written with Sprint 82: the chapter and the book, and the annotations a chapter carries to say what it is in its book and what its cover says — Cover, Synopsis and TableOfContents, Author, Subject and About, Biography and Autobiography — each to the four parts and shown in use from the compiler's test library. It opens with the two channels: the compiler knows a book by its files and the notation written in them and never by a class, so a library subclasses every one of these freely.

### [Conversation as a Folder](../conversation-as-a-folder/.cover.md)

How a CONVERSATION is a book — Doug's phrase, 2026-09-13: *"I would call it conversation as a folder."* The model, the dress, the inventory of everything Claude can write, and the types each named thing needs. Written in Doug's Library, committed there once and deleted the next day; recovered onto this branch by [Sprint 74](../projection/80-sprint-74--conversation-as-a-folder.md), whose opening ruling supersedes one placement in it — an exchange is a **chapter**, a movement of the conversation, not a section and not a turn.

### [The Catalogue and the Specification](../the-catalogue-and-the-specification/.cover.md)

***A research project, and the record of it*** — the binder works, and working stopped being enough when a one-property change to how a page looks cost forty seconds to see. **Doug, 2026-09-17: *"We have a prototype. It just died. Let's have the next version bring it back to life."*** Written as a project rather than an account: the commission, the method and the questions stand *before* any result, so a reader can judge whether the research was aimed at the right thing and a later session can run it again against a changed world. *The anchor every proposal is judged against first is hot reload* — **"restarting a server is death."** **And the commission was reframed the day it was written, which the book records rather than hides:** *the binder is not being rewritten so that CSS can be edited faster.* **It exists to produce the catalogue, run the specification, provide a realtime development workflow, and validate a knowledge graph as fast as it can be validated** — read [The Soundness of a Knowledge Graph](../the-semantics-of-books/18-the-soundness-of-a-knowledge-graph.md) first, because it is the standard this work is measured against.

### [The Genesis of Writing](../the-genesis-of-writing/.cover.md)

**The record of the redesign of `.public`, which is another draft of it, and the documents it is built from** — Doug's conversation with Claude Desktop in which he gives birth to the library one message at a time, and the three documents Claude Desktop compiled from it: the event stream, the compiled object model, and the implementation notes. *All four verbatim, as resources beside chapters that say only whose they are and how they are replaced,* because he sends newer versions as the work progresses and a resource is overwritten whole while the commentary stands. **Doug, 2026-09-20: *"we have to build the core, get the compiler working, and THEN build the rest of the components onto this foundation."*** The commentary chapter holds his rulings of the day and what the team needs to understand better, sorted by who answers. *The book's name is his conversation's and a proxy as a title.*
