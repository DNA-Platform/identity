# Designing Inexplicable Phenomena

- **subject:** [Publicity](../..publicity/.cover.md)

---

The design record of the Inexplicable Phenomena repository, as a subject: how `@dna-platform/public` is used to build ways of *viewing* the repo's content, and how the code that does it is written, typed, dressed and consumed. Where [The Semantics of Books](../the-semantics-of-books/.cover.md) derives the object model from its source conversation, this subject holds the **design decisions of the repo itself**. *Until 2026-09-11 this was one book of twenty-six chapters and 41,018 words; Doug: "Is it time to split it into more books with more covers? Are you sure you can read all those?" — so the book with this name became the catalogue, and its chapters became books, each readable in a sitting. Ordered for importance on 2026-10-01, Sprint 95's E3, on his word that the documentation be "organized for importance, abstracted and made elegant and minimal for your comprehension."*

**Read in this order if you are about to write a library on this code.** First [Writing a Book](../writing-a-book/.cover.md) — what a library is, how to be a librarian inside it, how it is dressed, the object graph everything sits in front of, and the reference manual. Then, with it open while you dress, [The Styling Surface](../the-styling-surface/.cover.md) — every class the base puts on the page, the clusters a Format owns, and what is on the page that is not a class. Then the four books of the code's own classes, one chapter per class and every chapter to the same four parts — [Writing](../writing/.cover.md), [Library](../library/.cover.md), [Figures](../figures/.cover.md), [Utilities](../utilities/.cover.md). Then [The Catalogue and the Specification](../the-catalogue-and-the-specification/.cover.md), the binder as built, its seventh and ninth chapters before the rest. [The Coding Style](../the-coding-style/.cover.md) before changing a line of `.public`, and [The Genesis of Writing](../the-genesis-of-writing/.cover.md) for the canon the redraft is built from. The earlier layers of the design — Ways of Reading, [The Type System](../the-type-system/.cover.md), [The Motif](../the-motif/.cover.md) — are read with their dates, when the code's reason is asked rather than its use. And two books here are records of the first draft and never the way to write a library: [The First Draft](../the-first-draft/.cover.md) and Conversation as a Folder; the third, [The Condition Report](../the-condition-report/.cover.md), is filed under Publicity.

## Books

### [Designing Inexplicable Phenomena](.cover.md) — Design

### [Writing a Book](../writing-a-book/.cover.md)

What a librarian WRITES on this code — what a library is, said plainly; dressing a library; the object graph of typed writings everything you build sits in front of; the reference manual, a book whose chapters print the tools the library is built with; and how to be a librarian, speaking from inside the closure. The test library beside the binder is the worked example of every chapter. *Its first seven chapters, written against the first draft, are [The First Draft](../the-first-draft/.cover.md) since 2026-10-01.*

### [The Styling Surface](../the-styling-surface/.cover.md)

Everything a styler meets when they dress a library on `.public`, read from the code on the night of Sprint 97's policy, on Doug's task — *"all the classes in the base theme… clusters of classes associated with formats that need to be overridden… this probably deserves its own book."* One side, the base theme's classes: every mark a library's theme dresses, the element that wears it, who puts it there and at which moment, the layers around it, and the one thing a theme usually says of it, in five tables and the rules of writing against them. The other side, the clusters: the classes each replaceable Format owns — Table's nine, List's, Paginated's, Cover's and its header, the table of contents' and its nav, Synopsis', the biographies', the three basics' on their own elements, the theme's outermost layer — what the base's template means by them, what a subclass writes, and how it is put in place. And what is not a class: the attributes, the custom properties, the foreign markup and its stylesheet, the generated hashes a rule never names, and the layers a rule crosses and never counts.

### [Writing](../writing/.cover.md)

The book of the redraft's `src/writing` folder, opening with its front matter in Doug's words: Writing as the base class of the .public document API, split into contents and annotations; annotations as a plugin-like system that keeps things modular, each pointing out a trait the writing has, interacting and overriding one another; Composition structuring the contents of a book while annotations customize them; what developing a class of writing means; and the mechanisms that theming and formatting are two use cases of: an annotation is a note on the page, its own writing wearing pd-annotation and its note at the level of the writing it annotates, built the day it was ruled; Format lending a styled component tried, Theme's rendering the one open thing, uniqueness the feature still to weigh; then Composition and Letter, each to the four parts, and Writing's own three chapters, moved here from the Genesis book the day Letter arrived.

### [Library](../library/.cover.md)

The book of `.public`'s `src/library` folder, written with Sprint 82: the chapter and the book, and the annotations a chapter carries to say what it is in its book and what its cover says — Cover, Synopsis and TableOfContents, Author, Subject and About, Biography and Autobiography — each to the four parts and shown in use from the compiler's test library. It opens with the two channels: the compiler knows a book by its files and the notation written in them and never by a class, so a library subclasses every one of these freely.

### [Figures](../figures/.cover.md)

The book of the redraft's `src/figures` folder, written with Sprint 89: the representation of things that are not quite writing — a file accompanying a chapter, inserted where the author writes a literal, `![[ code.tsx ]]`, or appended by an Append the author writes, and shown in the text by a Figure, the kind of letter that interfaces it; Code, Image and Svg the three that ship, each to the four parts, in a folder that grows as figures are invented.

### [Utilities](../utilities/.cover.md)

The book of the redraft's `src/utilities` folder, the first written to [How a Class Is Documented](../the-coding-style/08-how-a-class-is-documented.md): one chapter per class, four parts each — what it is with members cited, how it is extended, its promises, its gate. Collection and Specification, the two things every writing is built with and neither of them a writing.

### [The Catalogue and the Specification](../the-catalogue-and-the-specification/.cover.md)

***A research project, and the record of it*** — the binder works, and working stopped being enough when a one-property change to how a page looks cost forty seconds to see. **Doug, 2026-09-17: *"We have a prototype. It just died. Let's have the next version bring it back to life."*** Written as a project rather than an account: the commission, the method and the questions stand *before* any result, so a reader can judge whether the research was aimed at the right thing and a later session can run it again against a changed world. *The anchor every proposal is judged against first is hot reload* — **"restarting a server is death."** **And the commission was reframed the day it was written, which the book records rather than hides:** *the binder is not being rewritten so that CSS can be edited faster.* **It exists to produce the catalogue, run the specification, provide a realtime development workflow, and validate a knowledge graph as fast as it can be validated** — read [The Soundness of a Knowledge Graph](../the-semantics-of-books/18-the-soundness-of-a-knowledge-graph.md) first, because it is the standard this work is measured against. *The binder as built is its seventh chapter, and the specification of a library its ninth.*

### [The Coding Style](../the-coding-style/.cover.md)

### [The Genesis of Writing](../the-genesis-of-writing/.cover.md)

**The record of the redesign of `.public`, which is another draft of it, and the documents it is built from** — Doug's conversation with Claude Desktop in which he gives birth to the library one message at a time, and the three documents Claude Desktop compiled from it: the event stream, the compiled object model, and the implementation notes. *All four verbatim, as resources beside chapters that say only whose they are and how they are replaced,* because he sends newer versions as the work progresses and a resource is overwritten whole while the commentary stands. **Doug, 2026-09-20: *"we have to build the core, get the compiler working, and THEN build the rest of the components onto this foundation."*** The commentary chapter holds his rulings of the day and what the team needs to understand better, sorted by who answers. *The book's name is his conversation's and a proxy as a title.*
