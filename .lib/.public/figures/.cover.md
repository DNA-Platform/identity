The representation of things that are not quite writing: a file accompanying a chapter, inserted where the author writes a literal, `![[ code.tsx ]]`, or appended by an Append the author writes, and shown in the text by a Figure, the type of letter that interfaces it. Built 2026-09-28 in [Sprint 89](../projection/94-sprint-89--figures.md) for the code, pictures and prose a library keeps beside the chapters that document them — *"a library whose inside contains its own outside, at least in printed form."* The classes live in [`src/figures`](../../package/src/figures/), a folder that grows as figures are invented.

## Chapters

1. [Figure](02-figure.md) — FIGURE, written 2026-09-28 with Sprint 89: the letter that interfaces an append, named by identifier or by type as attributes, drawing the append's contents after the author's own or standing as its own literal, taking annotations as any letter does, throwing when it names an append its chapter lacks; the general form every figure grows from, and how a library writes a figure of its own.
2. [Code, Image and Svg](03-code-image-and-svg.md) — Code, Image and Svg, the three figures that ship, each to the four parts: Code a letter whose own element is the pre since Sprint 97, replacing its span at the bond as a Date does, holding a code element lit by highlight.js through a highlighter prop, its lines when numbered in spans wearing pd-code-line and carrying their number as data-line for a library's theme to show; Image drawing an img by the address an append holds or the author wrote; Svg drawing an appended file's markup inline; the three marks, and what each refuses.
