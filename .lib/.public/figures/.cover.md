The representation of things that are not quite writing: a file accompanying a chapter, appended to it by the binder as an Append, and shown in the text by a Figure, the kind of letter that interfaces it. Built 2026-09-28 in [Sprint 89](../projection/94-sprint-89--figures.md) for the code, pictures and prose a library keeps beside the chapters that document them — *"a library whose inside contains its own outside, at least in printed form."* The classes live in [`src/figures`](../../package/src/figures/), a folder that grows as figures are invented.

## Chapters

1. [Append](01-append.md) — APPEND, written 2026-09-28 with Sprint 89: the annotation the binder appends to a chapter for each file accompanying it, its text the file's contents uninterpreted, its identifier and type as the file spelled them, hidden as every annotation's writing is; how a file accompanies a chapter — the chapter's name, any one separator with the dot the convention, an identifier and a type, a numbered .tsx a chapter unless it accompanies another, identifiers unique per type, the unaccounted refused, the accounting's refusals four diagnostics in the binder's one form; how the binder appends it in the book's module, text raw and a picture by its address beside the pages.
2. [Figure](02-figure.md) — FIGURE, written 2026-09-28 with Sprint 89: the letter that interfaces an append, named by identifier or by type as attributes, drawing the append's contents after the author's own or standing as its own literal, taking annotations as any letter does, throwing when it names an append its chapter lacks; the general form every figure grows from, and how a library writes a figure of its own.
3. [Code, Image and Svg](03-code-image-and-svg.md) — CODE, IMAGE AND SVG, written 2026-09-28 with Sprint 89: the three figures .public ships, each from an appended file or from what the author wrote — a listing in a code element, a picture by its address, markup inline — with the default sheet's rules for their marks and what Svg trusts.
