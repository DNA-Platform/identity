How a library is written against `.public` as it stands — what a library IS, how it is dressed, the object graph everything you build sits in front of, the reference manual that prints the tools a library is built with, and how to be a librarian inside the closure. Read in order; the first chapter is the metaphor and the last is the voice. The test library beside the binder, [`.binding/.test`](../../package/.binding/.test/galleys.ts), is the worked example of every chapter.

*The book's first seven chapters, written against the first draft of `.public` between 2026-09-06 and 2026-09-15, moved to [The First Draft](../the-first-draft/.cover.md) on 2026-10-01 — Sprint 95's E1, Doug's word that the documentation be reviewed, made consistent and organized for importance. They are kept as records there, and nothing in this book teaches by them. Split out of the single design book on 2026-09-11 at Doug's direction — "26 chapters is way more than you even read in a whole catchup session" — with every chapter's entry carried over byte for byte and renumbered, and renumbered once more at the move.*

## Chapters

1. [What a Library Is](01-what-a-library-is.md) — THE METAPHOR, SAID PLAINLY, written 2026-09-27 on Doug's correction of the test library — 'The metaphor is lost on you and you need to understand it and write it down as part of the developer story, so that you can even build a test library.' A library is books and nothing else; every book is filed under a subject, and a subject is a book, the catalogue of what is filed under it, made a subject by its About, which may catalogue nothing; an author is a person, and a person in a library is their autobiography, the one book by its own subject — About them, filed where they stand: 'her subject is the library as she is its librarian, but her autobiography is about herself - Libby. It is a subject catalogue with zero books'; a biography a subject in turn; the library's own catalogue the top, filed under what it is about, said as a subject with words apart from a name, Libraries. Each word with what its cover says; who may author, in the compiler's own words; the test library as an instance, Libby the librarian's autobiography grounding it, filed under Libraries; what the log got wrong, and what filing her under herself got wrong; and what is not yet nailed down, to be ruled.
2. [Dressing a Library](02-dressing-a-library.md) — THE VISUAL LANGUAGE OF A LIBRARY, written 2026-09-27 with U9 of Sprint 88 on Doug's 'help me know where I am': where a library's look lives in three places — the theme's values, the theme's sheet extended in its $Define with selection(this.style) so a subclass adds rules for the framework's marks and a dark subclass inherits them, and formats in front dressing the library's own marks; the cues a reader gets and the mark each is drawn from — the byline's Author and Filed under, a kind label above every title, the cover a card, the synopsis ruled, the table boxed, chapters counted, the masthead, the catchword; the standard tricks — counters, ::before from a mark, :has() on the semantic wrapper, color-mix from the theme's values — and the two facts that bit, a format in front sitting between the wrapper and the element, and a closed page's wrapper still boxed; why not in a bond of the subclass's own, chemistry's chain rule and Theme passing over Format, pitched; the four shapes of a component with annotations as defaults; and the honest report that both are easy, with the one helper not exported flagged.
3. [The Object Graph](03-the-object-graph.md) — THE OBJECT GRAPH, written 2026-09-27 at the close of Sprint 88 on Doug's word that the way to build with .public be written down compactly: a library is an object graph of typed writings with gettable reactive properties, and everything you build sits in front of it — the five moves, each a few lines, showing a property, drawing a book's layout, giving a kind a default, inserting with an annotation, dressing with the theme and formats; what you rely on, the type hierarchy, the dynamic annotations, the marks and the sheet, the id from the name, the compiler's refusals; and what to know before it bites.

[The Reference Manual](04-the-reference-manual.md) — THE REFERENCE MANUAL, written 2026-09-28 with Sprint 89 by the librarian: a book whose chapters each hold, as the files beside them, a tool the library is built with and use it — the manual's .book.tsx the door every other book imports from, each chapter printing its file through a Code figure and saying how the tool is used; the manual accompanying a subject's reference; how a library grows into subjects when a book outgrows itself, a catalogue, the book and its manual; since Sprint 93, a chapter shown with its file — if one is about the other, show them together, so a chapter that prints a file is read as a spread and the front is the cover with its synopsis; the five steps to write one; and what bit — repeated headings on one page, a picture's dev address, the preload link, a printed file quoting a rule.
5. [How to Be a Librarian](05-how-to-be-a-librarian.md) — HOW TO BE A LIBRARIAN, written 2026-09-28 with Sprint 90 by the librarian, on Doug's correction that speaking of a library from above shows one does not understand what a library is, and that it will affect the code: a library is an identity with closure — closed under books, no outside, every book answering for itself, the regress stopping at a book that returns itself — so whoever speaks of one speaks as a book in it and a voice from above is a non-member the catalogue refuses; WHAT A .PUBLIC LIBRARY IS BESIDE THE TEAM'S, the same metaphor in two materials and not the same thing — no folder says a kind, everything said on a cover in the notation, exactly one autobiography where the team's has ten, links written by the catalogue, refusals compile errors, a look and a manual of its own — with the closure the same on both sides; why that decides the code, the compiler a reader inside the closure, the test library a librarian's library and not a fixture; the five questions in order; the tools mapped to what they say; and how to tend one, toward the integrity of the catalogue, speaking from inside.
