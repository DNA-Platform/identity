Defects diagnosed in this branch, one chapter each, indexed by **what was observed** rather than by what it turned out to be. [Projection](../projection/.cover.md) indexes the same work by time and [The Condition Report](../the-condition-report/.cover.md) indexes the code by **kind of fault**; this book indexes it by **symptom**, and none of the three answers another's question. *Doug drew the line between this book and the report himself: **"it's a bug. And a good one. But it's not a wart in the framework."** A defect gets fixed; a fault of design gets designed away.* Specified in [Solutions](../../../../.claude/library/library-tree/06-solutions.md).

Every entry below opens with the **symptom** — the error text, the wrong value, the visible behaviour — because a reader arrives holding one of those and not a diagnosis. Each chapter carries a keyword line for grep, drawn from the vocabulary below.

## The keyword vocabulary

Grow this list only when a genuinely new class appears, and grow it here so the next writer sees it.

**Surfaces:** `framework` (chemistry itself) · `model` (`@dna-platform/lib`) · `demo` (the app) · `tooling` (compilers, validators, sync) · `library` (books and covers) · `sync` (identity and branches)

**Mechanism classes:** `stale-artifact` (a compiled or derived thing that outlived its source) · `missing-parent` (a chemical built outside chemistry) · `render-loop` (mutation during render) · `wrong-altitude` (a decision made at the wrong level) · `unproven-deletion` (a member removed without proving it dead) · `silent-default` (a guard or flag that did nothing) · `lifted-class` (code reasoning about the class as written, where the object was built from a class the framework made) · `rebind` (prop binding re-running over an already-built instance's held state) · `absent-case` (a gate ran correctly over content or timing that could not exercise the defect) · `narrowed-declaration` (a subclass narrowed what its base widened, and the narrowing travelled the wrong way) · `assumed-environment` (an artifact depending on something the repository does not contain and does not name) · `mechanical-edit` (a change made by matching a pattern where the meaning had to be read) · `guessed-pattern` (a search or query written from an assumption about the shape of what it seeks, whose empty result was read as evidence of absence) · `detached-context` (an instrument whose own footing was destroyed by the thing it was measuring, reporting the subject as missing rather than itself as gone) · `inherited-receiver` (a method inherited from an ancestor, running with the descendant as `this`, so it cannot know which class declared the line that called it) · `construction-write` (a write made while an object is being BUILT, which a system that fans writes out to whoever might have read them treats as a change, so anything building a thing that builds a thing spins) · `construction-throw` (a THROW raised while an object is being built during a render, which the reaction system retries — synchronously, so no timeout can fire and the worker spins until it is killed) · `written-after-bond` (the eval form joins written children to the block AFTER the bond runs, so a bond line deriving a member from its own block silently no-ops in that one construction path) · `smuggled-state` (a per-seat fact written onto a member that persists under a shared key, so one seat's display choice recalls as every seat's truth) · `carried-type` (a rule held by a type that consults a member of that type's own class, so it holds for an instance and fails for the writing that merely CARRIES the type) · `split-discriminator` (one category decided in several places, where re-cutting what the category means updated some of the decisions and not the others, so two rules came to disagree about the same case) · `renamed-binding` (a resolution made through a RUNTIME name — `cls.name`, `fn.name`, `constructor.name` — which a build is free to change under decoration, bundling or minification, so a rename silently switches off the machinery that name was reaching for) · `contested-member` (one field on a shared object that every container processing it writes with its own container-relative fact, so the last walk wins and the first container's fact is silently gone) · `wrapped-value` (a function or class stored on a chemical's reactive field is answered WRAPPED by the membrane, so identity tests — instanceof, ===, registry keys — meet a bound impostor of the thing) · `orphan-root` (a chemical made by the bare eval form is parented to a throwaway host, so a parent walk stops early and answers a legal wrong answer — never an error, because self-at-top is legal) · `render-make` (a view constructed a chemical — parts() parsing, or `$(<element/>)` evaluating — so reaction graphs woke mid-paint and the render looped or detonated) · `birth-dispatch` (a hook firing on assignment fires on every assignment a super-chain makes, running a law against a half-constructed state; the guard is identity — does this type make this very kind) · `surface-blind` (a decision made from a file's LOCAL code quality where only its POSITION could have decided it — the framework and the demo are the same TypeScript in one repository, so nothing in a file says which one it is, and the choice between adding a kind and overriding one always votes for the new class; *proxy name, flagged for Doug*) · `unrun-rule` (a rule that stopped running rather than started passing — indistinguishable from outside, because both are a green number, and a refactor is exactly the act that can remove a measurement; *proxy name, flagged for Doug*)
