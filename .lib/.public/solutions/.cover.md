Every entry below opens with the **symptom** — the error text, the wrong value, the visible behaviour — because a reader arrives holding one of those and not a diagnosis. Each chapter carries a keyword line for grep, drawn from the vocabulary below.

## The keyword vocabulary

Grow this list only when a genuinely new class appears, and grow it here so the next writer sees it.

**Surfaces:** `framework` (chemistry itself) · `model` (`@dna-platform/lib`) · `demo` (the app) · `tooling` (compilers, validators, sync) · `library` (books and covers) · `sync` (identity and branches)

**Mechanism classes:** `stale-artifact` (a compiled or derived thing that outlived its source) · `missing-parent` (a chemical built outside chemistry) · `render-loop` (mutation during render) · `wrong-altitude` (a decision made at the wrong level) · `unproven-deletion` (a member removed without proving it dead) · `silent-default` (a guard or flag that did nothing) · `lifted-class` (code reasoning about the class as written, where the object was built from a class the framework made) · `rebind` (prop binding re-running over an already-built instance's held state)

## Chapters

1. [The formulas that rendered empty](01-the-formulas-that-rendered-empty.md) — **every formula on the algebra page rendered as blank space, sentences trailing off mid-clause — and no error anywhere, suite green, types clean, driver passing** — the class stored its content into one member and read it from another after a half-swept rename, which typechecks cleanly when both are optional; plus the unproven deletion of inline, which is chemistry's grouping marker and not dead weight
2. [The footnote that wore zero](02-the-footnote-that-wore-zero.md) — **a footnote rendered its number as 0 — every footnote in the demo, not only uncited ones, with suite and driver both green** — the number was derived by walking the prose for citing marks the demo never writes (it uses markdown the reader parses), so indexOf returned minus one and minus one plus one is zero; a number derived at the wrong altitude rather than an off-by-one
3. [The link I built three times](03-the-link-i-built-three-times.md) — Doug asked for a book's TITLE to be the interaction and pointed at prior art; it took THREE corrections because I iterated on guesses instead of opening the file. Round one added separate buttons and a running head; round two kept the name but bolted an 'entry N' label beside it; round three dressed the title in a dotted underline — each satisfying the letter of the last correction and breaking the same law again. NO TEST FAILED AT ANY POINT: green, typed and rendering the whole way, with Doug's patience as the only detector. The mechanism was two files away — $RibbonMark and $Return are subclass-plus-view(), references that RENDER THEMSELVES, and a table of contents row prints itself with nothing applied to say it is one. The model's answer to 'how do I make this followable' is NOTHING: a cover IS a $Reference$<$Book>, so reference-hood is what a thing already is and every round added signal to announce a property it already had. Worst part: Sprint 47's retro states this in one line and I READ IT at the top of the same session — reading is not consulting. The lesson is about research, not links: when someone points at prior art, open it before writing a line, and never use the reviewer as your search process — three corrections spent on what one file would have answered is outsourcing research to the person least able to afford it.
4. [The sprint that planned what it had not designed](04-the-sprint-that-planned-what-it-had-not-designed.md) — A long sprint produced 4 of 38 requirements, all framework floor, and a demo built entirely from classes that predated it — a regression check presented as a demonstration. EVERY GATE PASSED: requirements approved, every requirement traced to a unit, work verified with fresh numbers, altitudes obeyed. The mechanism: ORIGIN TRACING RUNS ONE WAY ONLY. It asks whether every requirement has a unit, never whether every unit has a MECHANISM — so $Type and its resolution were written as units, with files and dependencies and scenarios, for a thing whose central mechanism had never been designed. Two things follow and both did: the implementer starts where the mechanism is clear, so the bond-constructor work consumed the session and the undesigned unit was deferred by being unbuildable rather than by anyone deciding; and FEASIBILITY GETS MISTAKEN FOR DESIGN — a deferral of the BUILD was treated as a deferral of the DESIGN, and a five-point feasibility case was written where a mechanism was owed. Compounding: the chapter itself said 'the design session first' and 'the cost is in the design conversation, not the code', and no gate checks whether a declared design session happened. THE FIX: a unit with no mechanism is not a unit — mark it DESIGN OWED and refuse it files and scenarios so it cannot pass as buildable, and run the self-check both directions. THE LESSON: ceremony passes gates. The question that catches it before work starts is 'for each unit, what runs and when?' — where there is no answer, that unit is a design session, and starting anywhere else is choosing the tractable over the necessary.
5. [The suite that passed against a stale build](05-the-suite-that-passed-against-a-stale-build.md) — A framework change that SHOULD have broken four lib classes landed, and the lib suite reported 108/108 passing — a false green reported in the room as a result before anyone asked what the suite was testing against. Reading the number could not catch it, and 'deps: { inline: [/chemistry/] }' reads like it means 'use the source' but controls bundling, not resolution. The mechanism: the lib resolves its dependency through node_modules and package.json points at dist/, so the suite was exercising the LAST BUILD of chemistry rather than the working tree. One probe settles it and should be run first — node -e "console.log(require.resolve('@dna-platform/chemistry'))". Rebuilding turned 108/108 into 105/108, with three failures naming exactly the four classes an audit had predicted. THE CHANGE WAS CORRECT THE WHOLE TIME; THE VERIFICATION WAS NOT. Fix: when a change crosses a package boundary, rebuild the dependency before running the dependant's suite — without it the run is not a weaker check but a check of DIFFERENT CODE. The lesson: an unexplained pass is exactly as suspicious as an unexplained failure and far more dangerous, because nobody investigates good news; it happened twice in one session. The habit that catches it — before reporting a green number, say what it exercised: not 'the suite passed' but 'the suite passed against this build of that dependency'. If that sentence cannot be completed, the number is not yet evidence.
6. [The class that was not the class](06-the-class-that-was-not-the-class.md) — A chemical asked to enumerate its own properties answered with the FRAMEWORK'S instead — the class declared name and synopsis, and walking its prototype chain returned inline, viewLevel, perspectives, children and parent with nothing to tell them apart; and the same shape again wearing different clothes, a static assigned inside a bond constructor reading back as undefined through the imported class, with nothing thrown. FOUR INSTRUMENTS, EACH WRONG DIFFERENTLY, three corrected by Doug rather than by a failing test: stopping the prototype walk at the base class BY IDENTITY never terminates, because the instance's chain does not contain it; Object.keys misses everything because many chemicals are made by Object.create, so the fields live on the object the instance was made FROM; a framework-name exclusion list built from the source is incomplete by construction, because the runtime surface carries members the plain classes never declared; and feature-detecting the base level stops immediately, because the very first prototype owns everything. The chain, READ rather than guessed by printing it: $Chemistry inserts EXACTLY ONE LIFTED COMPOSITE prototype at the top, carrying every backing and every method as a getter, with the authored classes intact below it. So all four failed for one reason — they reasoned about the class as written, and the object was built from a class that was made. What works: skip the lifted level, identifiable because it is the only prototype carrying $-prefixed getters, exposing the backings the membrane keeps private everywhere else; and a static is not a place to keep anything, since one assigned during a bond constructor lands on the lifted class and the imported class never sees it. THE LESSON IS NOT ABOUT PROTOTYPES: a twelve-line probe that printed the chain answered in one run what four corrections could not, so when three attempts at one problem fail DIFFERENTLY, stop attempting and instrument — each failure was informative and none was evidence, because none made the actual shape visible.
7. [The contents that failed before adoption](07-the-contents-that-failed-before-adoption.md) — **a book with an AUTHORED table of contents rendered a bond failure in that chapter's place — 'Cannot read properties of undefined (reading summary)' — while every model-level test on the same book passed** — children bind before their parent adopts them, and the contents' summary derives from the book, so the getter reached through a parent it did not have yet; the spliced contents never hit this because the splice ran inside the book's bond; the failure PREDATES the sprint that found it, since nobody had ever rendered an authored one. The fix is the shipped $Cover pattern plus its validity half: catch the ancestor's demand that cannot apply yet, state your own valid(), and let derived getters answer undefined before adoption. The probe rule held again — three theories each fit some evidence, one printed run settled it.
8. [The field that buried a method](08-the-field-that-buried-a-method.md) — **opening The Team threw 'this.book.at is not a function' from the contents' row-building, though the book passed instanceof $Book a line earlier** — a state field named at on the $Book subclass (its open-page number) buried $Book.at(), the location method; a field and a method share one name space and the field wins, and nothing complained until something finally asked the contents for rows. Renamed to page. The rule costs one read: a subclass lives in its book's name space, so choose state names against $Book's member list — and when a model method 'is not a function', look for a field wearing its name before looking deeper.
9. [The parent that changed on screen](09-the-parent-that-changed-on-screen.md) — **the shelf page failed to load with 'this.book.at is not a function' from the contents' row-building, after the same code passed the whole suite** — an element's parent is the chemical that interprets it, and on screen that is whatever RENDERED it, so a contents drawn inside a page-switching chemical answered this.parent with the page switcher; one hop of parent is a bind-time fact, not a render-time one. The fix ships in the model: $TableOfContents.book climbs to the nearest $Book, the canonical's guarded walk, and parts() names the wrong parent plainly when it finds one. Hold with chapter 07: the same reach failing BEFORE adoption there, ON SCREEN here — derived members climb or answer undefined, never trust the single hop.
10. [The prop that emptied the shelf](10-the-prop-that-emptied-the-shelf.md) — **the shelf rendered with no member spines and no written entries — furniture drawn, books gone, no error — after one prop was added to the singleton it renders through** — passing a prop to an already-built instance appears to re-run binding over it, and members assigned from outside after construction did not survive; proven as a sequence (prop absent: present · prop present: empty · prop removed: back), with the in-framework path FLAGGED rather than asserted. The fix: never pass props to a bound singleton that accumulates state — wire callbacks by assignment (module slots set once), render the instance bare. Two ways into a chemical, construction and assignment, and props belong to construction.
11. [The constructor that captured the wrong instance](11-the-constructor-that-captured-the-wrong-instance.md) — **clicking a book entry did nothing — handler ran, screen stayed, no error — where the handler reached the page switcher through a module variable assigned in the constructor** — React development mode constructs a component twice and keeps one, so a constructor that registers *this* outward holds whichever construction ran last, not necessarily the kept one, and every click mutated an instance no view would re-render. The fix: register in view() — only a rendered instance runs its view, so the variable always names the one on screen. A constructor knows it ran; it cannot know it was kept.
