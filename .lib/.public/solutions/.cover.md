Defects diagnosed in this branch, one chapter each, indexed by **what was observed** rather than by what it turned out to be. [Projection](../projection/.cover.md) indexes the same work by time and [The Condition Report](../the-condition-report/.cover.md) indexes the code by **kind of fault**; this book indexes it by **symptom**, and none of the three answers another's question. *Doug drew the line between this book and the report himself: **"it's a bug. And a good one. But it's not a wart in the framework."** A defect gets fixed; a fault of design gets designed away.* Specified in [Solutions](../../../../.claude/library/library-tree/06-solutions.md).

Every entry below opens with the **symptom** — the error text, the wrong value, the visible behaviour — because a reader arrives holding one of those and not a diagnosis. Each chapter carries a keyword line for grep, drawn from the vocabulary below.

## The keyword vocabulary

Grow this list only when a genuinely new class appears, and grow it here so the next writer sees it.

**Surfaces:** `framework` (chemistry itself) · `model` (`@dna-platform/lib`) · `demo` (the app) · `tooling` (compilers, validators, sync) · `library` (books and covers) · `sync` (identity and branches)

**Mechanism classes:** `stale-artifact` (a compiled or derived thing that outlived its source) · `missing-parent` (a chemical built outside chemistry) · `render-loop` (mutation during render) · `wrong-altitude` (a decision made at the wrong level) · `unproven-deletion` (a member removed without proving it dead) · `silent-default` (a guard or flag that did nothing) · `lifted-class` (code reasoning about the class as written, where the object was built from a class the framework made) · `rebind` (prop binding re-running over an already-built instance's held state) · `absent-case` (a gate ran correctly over content or timing that could not exercise the defect) · `narrowed-declaration` (a subclass narrowed what its base widened, and the narrowing travelled the wrong way) · `assumed-environment` (an artifact depending on something the repository does not contain and does not name) · `mechanical-edit` (a change made by matching a pattern where the meaning had to be read) · `guessed-pattern` (a search or query written from an assumption about the shape of what it seeks, whose empty result was read as evidence of absence) · `detached-context` (an instrument whose own footing was destroyed by the thing it was measuring, reporting the subject as missing rather than itself as gone) · `inherited-receiver` (a method inherited from an ancestor, running with the descendant as `this`, so it cannot know which class declared the line that called it) · `construction-write` (a write made while an object is being BUILT, which a system that fans writes out to whoever might have read them treats as a change, so anything building a thing that builds a thing spins) · `construction-throw` (a THROW raised while an object is being built during a render, which the reaction system retries — synchronously, so no timeout can fire and the worker spins until it is killed) · `carried-type` (a rule held by a type that consults a member of that type's own class, so it holds for an instance and fails for the writing that merely CARRIES the type) · `split-discriminator` (one category decided in several places, where re-cutting what the category means updated some of the decisions and not the others, so two rules came to disagree about the same case) · `renamed-binding` (a resolution made through a RUNTIME name — `cls.name`, `fn.name`, `constructor.name` — which a build is free to change under decoration, bundling or minification, so a rename silently switches off the machinery that name was reaching for)

[The class that was not the class](06-the-class-that-was-not-the-class.md) — A chemical asked to enumerate its own properties answered with the FRAMEWORK'S instead — the class declared name and synopsis, and walking its prototype chain returned inline, viewLevel, perspectives, children and parent with nothing to tell them apart; and the same shape again wearing different clothes, a static assigned inside a bond constructor reading back as undefined through the imported class, with nothing thrown. THE LESSON IS NOT ABOUT PROTOTYPES: a twelve-line probe that printed the chain answered in one run what four corrections could not, so when three attempts at one problem fail DIFFERENTLY, stop attempting and instrument — each failure was informative and none was evidence, because none made the actual shape visible.

[The writing that looped its page](12-the-writing-that-looped-its-page.md) — **a page written with a specialized inline element threw 'Too many re-renders' during render, and the element never appeared — the host rendered 41 times and the child zero, but only when it stood inside another chemical's writing; standing alone it was fine** — the specification carried for two sprints ('a subclass that declares its own props and overrides a method its view() calls will not render') was FALSE, and four filed routes had each failed for a different wrong reason. Five one-variable cases found the true rule — inline, PASSED A PROP, inside a block — and a probe printing identities showed the instance, block and component all stable while the children churned forever. Props are construction and were being recorded as mutation: a chemical written inside another's writing is BUILT during that render and handed its props there, the empty lastProps guard makes every prop a change, the reactive setter records it into the running scope, the scope finalizes dirty, and the host renders again. Fixed in the bond, NOT in the setter — guarding there on 'has not mounted' drops real mutations of a lensed instance and chemistry's own perspectives suite catches it. The lesson: a filed specification is a claim and claims decay, and a theory that reads as true but is irrelevant is a signal to keep instrumenting rather than start fixing.

[The green that exercised nothing](14-the-green-that-exercised-nothing.md) — Five sprints reported 'app tsc 0' and 'driven, zero page errors' while a demo page crashed on open — because TWO GATES WERE NOT CHECKING and neither said so. The typecheck PASSED BY NOT RUNNING: 'cd app && tsc --noEmit' exits 0 having compiled ZERO files where the project form compiles 46 and finds 5, one of them the live crash, named by the compiler the whole time. The driver PASSED BY NOT BEING RUN: it threw at its own step three on a renamed selector, exited non-zero, printed a bare stack trace with no indication of how far it got. Both numbers were TRUE and both scopes were SILENT, and the scope was the whole content of the claim. The fix is that the artifact states its own scope — files typechecked, debt named BY IDENTITY so a fifth error cannot hide among four, unexpected counted, never a bare PASS — and the driver reports checkpoint accounting. The habit that catches it: WATCH THE GATE GO RED BEFORE TRUSTING ITS GREEN. A symptom filed repeatedly is a cause nobody fixed, and the cause is reporting a number without its scope. TWO MORE FROM THE PARSE, and one is a FALSE RED. The relative -p does it too: 'tsc -p tsconfig.json' from inside app/ prints nothing and exits 0 while the same config by ABSOLUTE path finds four real errors — the shortcut was believed and THE GATE CONTRADICTED IT, winning because it states its scope. And inverted: a driver reported four failures that did not exist, because the dev server had outlived three deleted modules and was walking a module graph that was gone; restarted at the same commit, zero. A FALSE RED COSTS WHAT A FALSE GREEN DOES and costs it faster, since it sends you diagnosing correct code — the tell is that when a driver and the unit suite disagree about the same objects, suspect the PROCESS before the code. So the scope rule extends to what a gate RUNS AGAINST: a suite states which build, a typecheck which files, A DRIVER WHICH SERVER. AND A FOURTH APPEARANCE FROM THE BUILD, THE FIRST NOBODY PAID FOR: a glob does not match a file whose name begins with a dot, so a library convention naming a cover .cover.tsx and its account .synopsis.tsx is HALF INVISIBLE to an ordinary include — measured, one of three files seen, with no warning and no count. An explicit import finds them and compiles clean, which is why the convention survives; so the generated module that composes a book is THE ONLY DOOR into its dotted files, and a gate must enter through it rather than walk a pattern. Found by testing the assumption before building on it, which is the only thing about this entry that differs from the three before it. A FIFTH APPEARANCE, AND IT IS THIS CHAPTER'S OWN FIX FAILING TO HOLD: the stale-server rule was already written down here and cost the branch a session anyway. Two dev servers had outlived the modules they were serving and both demo drivers ran against them — 49 checkpoints and 23, restarted at the SAME COMMIT 61 and 25. The tell was not a FAIL this time, it was a SHORT COUNT, legible only because this chapter's own fix made the driver report how far it got — a bare stack trace would have said nothing and 49 looks like a number rather than a stall, so the gate caught its own recurrence. THE INTERESTING PART IS THAT THE FIX DID NOT HOLD: 'restart the server after deleting a module' is a rule A PERSON HAS TO REMEMBER, and it was written by the same team that then did not remember it — a procedural fix does not kill a class. What is procedural today is that the driver ATTACHES TO A SERVER IT DID NOT START and cannot ask whether that server's modules are the ones on disk; two shapes would end it, the driver starting its own server or the served page carrying a build identity the driver asserts against the working copy, and NEITHER IS BUILT. Until one exists the mitigation is a runbook line rather than a rule — the sprint's own How to see it now says start the server yourself before driving it, beside the command, where somebody about to drive will read it. A SIXTH APPEARANCE, AND THE SAME SIGNATURE FROM A DIFFERENT CAUSE: 49 checkpoints and a stall at 1, corrected at the same commit to 61 and 31 — the identical 49/61 pair as the fifth, six days later, with nothing in common between the causes. THE RUNBOOK LINE WAS FOLLOWED: the server was started for this run, on a free port, with --strictPort, and it did not help because the cause was not the server. The mechanism is in The red that exercised nothing — networkidle unreachable while a cold vite compiles 170 modules, and a waitForSelector bound to an execution context that a full page load destroys. What this adds HERE is that 'a procedural fix does not kill a class' is confirmed twice over: the rule was remembered and the class survived anyway, because it addressed one cause of a signature that has at least two. A third structural shape is now built — the wait polls across a navigation and names the landmark that never arrived — and the other two, a driver that starts its own server and a page carrying a build identity, are still not. And one thing this chapter had not said, which cost the most hours: A SHORT COUNT POINTS. Every stall sat at a step that leaves a book and returns to the shelf, a true pattern that indicted the framework work the sprint had just finished — but a stall's location is where the INSTRUMENT gave way, and that coincides with the code only when the instrument is sound.

[The regex that remembered where it stopped](17-the-regex-that-remembered-where-it-stopped.md) — **the page's word count moved 475 to 578 with no change that should add words; a word typed inside an unclosed fence was counted as writing and took the driver red; and the facing-page comparison DISAGREED WITH ITSELF ON SCREEN, 21 words against 30, while the unit suite comparing THE SAME TWO OBJECTS reported them equal** — three theories fit some of the evidence and none of it, and the row that should have redirected the search immediately was the last one, since a test and a screen disagreeing about the same objects is not a disagreement about the objects. 18. [The checkpoint that compared a number to itself](18-the-checkpoint-that-compared-a-number-to-itself.md) — **a driver checkpoint passed on its first run and every run after, and was reported to Doug as evidence — 'the model reads at every altitude and the count cannot move, 260 words as paragraphs, 260 as words' — and there was nothing that could have failed it.** Doug read the sentence and asked what it meant, which is how it was caught. WATCHING THE GATE GO RED WOULD NOT HAVE HELPED, and that is the point: breaking the parse would have moved both numbers together, so no breakage reachable from the code could turn it red. The view rendered ONE GETTER beside four different lists — switching altitude changed the ROWS and never re-derived the COUNT — so the driver compared the result of one expression to the result of the same expression. The claim it appeared to make was real and worth making; the claim it ACTUALLY made was that a getter is stable, and the sentence in the report was accurate about the numbers and false about what they showed. Fixed by having each altitude WALK ITS OWN COUNT four different ways down the model, plus two checkpoints that CAN fail — the rows must differ at every altitude, and the word altitude must print one row per word — driven as 260 words through 4 sections, 11 paragraphs, 17 sentences, 260 words. THE LESSON: a checkpoint that cannot fail is not a checkpoint, and the question the runner cannot ask is WHAT WOULD HAVE TO BREAK FOR THIS TO GO RED. The shape to look for is an identity dressed as an agreement — two things corroborate only when computed by DIFFERENT PATHS, and a corroboration test must be able to name TWO WALKS. AND A SECOND APPEARANCE FROM CUSTOM ELEMENTS, WHERE THIS CHAPTER'S OWN RULE WAS SATISFIED AND THE GREEN STILL WAS NOT EVIDENCE: a promise compared a hand-written parallel text against the same text found in the notation — two genuinely different paths, each the oracle for the other, exactly the shape the rule asks for — and it WENT RED WHEN A DEFECT WAS FIXED, a custom element stopping dissolving and the assertion breaking with nothing about the promise changed. The two sides are deliberately unequal in one place, their titles LABELLING them, so the found side carries one word more by design; and the written side was one word short for an unrelated reason, its Link dissolving into two plain words — two one-word errors with opposite signs, cancelling exactly, so the assertion compared quantities that could never honestly be equal while a defect supplied the compensating error. Fixed by comparing the BODIES and not the whole, dropping the titles because the titles are the one region the sides are SUPPOSED to differ in, with the reason written into the promise so nobody widens it back. TWO WALKS IS NECESSARY AND NOT SUFFICIENT: a comparison spanning a region the sides are designed to differ in carries a built-in error term it never subtracts, so it cannot be green honestly — it is green only while something else is wrong by the same amount, which makes its green a report about a SECOND defect. And the tell is worth more than the rule: A PROMISE THAT GOES RED WHEN YOU FIX SOMETHING WAS MEASURING THE DEFECT — the first question is not what broke, it is what the assertion had been true about.
28. [The specimen that was the component](28-the-specimen-that-was-the-component.md) — A PROP WRITTEN ON ONE ELEMENT CHANGED A DIFFERENT ELEMENT — two tiles drew the same cached specimen, one was written with an extra attribute, and BOTH changed colour, including the one three rows above carrying no such attribute. Thirty-one green promises did not see it: the suite asserted that two specimens of one class differ from each other and never that ONE SITE CANNOT DISTURB ANOTHER, which is a different claim. $lift has two paths and $isTemplate$ chooses between them: a template takes the DERIVATIVE path and every mount gets its own Object.create, while anything else takes DIRECT, where the instance IS the component and state persists across every site. $isTemplate$ asks 'am I the one instance my class registered' — so a SECOND specimen of a class is never a template, which is exactly the case an implementer creates when filing several instances under several names. One shared object per name, and a prop at any site reached all of them.
