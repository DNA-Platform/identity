How a book LOOKS — the Wikipedia default and every dress a format, the Wikipedia fit that made wikimedia-ui-base a real dependency, and why the markdown reading is not yet a reading of a document but a rebuttal of a paper. The themes and formats as design, not as CSS.

*Split out of the single design book on 2026-09-11 at Doug's direction — "26 chapters is way more than you even read in a whole catchup session" — with every chapter's entry carried over byte for byte and renumbered.*

## Chapters

1. [The Default Dress](01-the-default-dress.md) — The Wikipedia default, ripped off intentionally — and SINCE 2026-09-04 EVERY DRESS IS A STYLED CHEMICAL. The mechanism is $Chemistry's own (particle 11); what this chapter owns is how the library uses it, in three rules: a dress is a CLASS declaring selector = styled.h2 with its CSS as fields and a view that writes that element, which is what makes it DI-able where a raw styled component answers null.
2. [The Wikipedia Fit](02-the-wikipedia-fit.md) — Wikipedia as the framework's default style: wikimedia-ui-base taken as a real dependency so $Theme is an applied layer over their palette rather than a copy, $Style renamed $Format with every dress an $XFormat, Codex found to be the integrating document but application chrome rather than article content, the GPL wall around the article CSS, the catalogue card identified as an infobox, and the map of every viewless kind.
3. [Why Markdown Is Not Useful Yet](03-why-markdown-is-not-useful-yet.md) — The markdown reading is not a reading of a document, it is a REBUTTAL of a paper — measured in its own source, where about forty of 138 lines exist only to undo article: four content overrides to remove numbering, left-alignment to undo justification, auto width to undo 8.5 inches. The dependency is still right; what it costs is that a rendered document argues with every decision a paper made, by name. The deeper reason is that a README has no cover, author block, abstract, contents or bibliography and our model supplies all five. What markdown actually wants is a VIEWING CONTEXT — out of the box there is no box, and ours ships one, which is the argument for the desk and the strip living in the base. Ends with the ordered list: $Code throws; build on $Article; move a document's decisions out of a paper's; a citation needs a reading per theme; $Table must be a table.
4. [Themes per Type, Formats per Instance](04-themes-per-type-formats-per-instance.md) — A RULING NOT YET BUILT, 2026-09-11, recorded so the next sprint designs from it: themes are one per type of component, singletons by registration; formats are one per instance; each reads the other's values; the readings' folders should fill with format classes, a particular implementation. Reverses Sprint 57's move of kinds' rules into the sheet, with the encyclopedia's infobox group as the worked example. The base is named Theme and the readings ArticleTheme, MarkdownTheme, EncyclopediaTheme. Placed after LaTeX closes.
