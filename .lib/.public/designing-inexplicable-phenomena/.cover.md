The design record of the Inexplicable Phenomena repository — how `@dna-platform/lib` is used to build ways of *viewing* the repo's content. Where [The Semantics of Books](../the-semantics-of-books/.cover.md) derives the object model from its source conversation, this book tracks the **design decisions of the repo itself**: what gets built on the classes, which prior work is extended rather than reinvented, and what each surface must do. Notes first, designs when settled — a chapter here is allowed to be a working notebook, kept honest by citing where each idea came from.

## Chapters

1. [The Notes We Already Took](01-the-notes-we-already-took.md) — The prior notes this book extends: Sprint 43 resources, the archive markdown-plus-LaTeX converter, the twelve prototypal library classes, the eleven SRT prototypes.
2. [Markdown with LaTeX on the Composition Classes](02-markdown-with-latex.md) — Markdown-with-LaTeX built into the object model — `$Latex` inline, `$Markdown` an authoring adapter that renders composition objects through eval.
3. [Navigation for the Lab](03-navigation-for-the-lab.md) — The Lab navigation: case sections beside full-page designs, mobile-capable — the thing stays, the about-the-thing collapses.
4. [Ways of Reading](04-ways-of-reading.md) — The view catalogue: the book as the fundamental website, view patterns decomposed into three shipped moves — lens, reading, arrangement; a book is an evolvable authored structure, and views multiply claims. THREE LAWS FOR EVERY VIEW now: identity through change, views multiply claims, and — added out of The Parse — A VIEW READS, IT DOES NOT RE-DERIVE. The manifold flattened a chapter into ~55 lines of strings before drawing it, which is a SECOND POPULATION OF THE MODEL wearing a data structure, and it failed three ways in one sprint: it SNIFFED what the model knows (asking a string whether it started with an angle, so every quotation silently became prose the moment the model learned what a $Quoted is), it INVENTED ADDRESSES by arithmetic over array positions while a reference resolved by walking the model, so links followed to nothing when the numbering changed, and it BORROWED A MODEL MEMBER for its own state, storing a ribbon's slot in the writing's number because a number happened to be there. So: ask the model rather than testing its output; an address is a POSITION and not a formula, so the anchor rendered is the string a reference resolves and the two cannot drift; and a view's own state lives on the view. The corroboration that proves a view is really reading is one writing read at four altitudes with each altitude walking its own count — and the failure mode of building that the lazy way is a number compared to itself.
